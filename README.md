# Keepfall

> 게임 이름은 Cat War에서 Keepfall로 바뀌었습니다. 실행 파일(`CatWar.exe`), 설치 프로그램, 서버 서비스, 저장 파일 이름은 기존 설치와 자동 업데이트가 끊기지 않도록 당분간 이전 이름을 그대로 씁니다.

밸런스 자동 대전과 데이터 수집 방법: [반복 가능한 밸런스 실험](docs/BALANCE_BENCHMARK.md).

Godot 4로 만든 1대1 자동 전투 + 전장 개조 게임입니다. 온라인 대전은 별도 전용 서버가 모든 규칙과 전투를 판정하며, 서버 없이 실행되는 오프라인 AI 대전도 제공합니다.

## 프로그램 구성

이 저장소에는 **게임 클라이언트와 전용 서버 코드가 모두 포함**되어 있습니다. 두 프로그램은 서로 다른 코드 복사본이 아니라 같은 Godot 프로젝트와 같은 `BattleModel` 규칙을 공유합니다.

| 실행 방식 | 동작 |
|---|---|
| `CatWar.exe` | 게임 클라이언트와 오프라인 AI 대전 |
| `CatWar.apk` | Android 클라이언트와 오프라인 AI 대전 |
| `CatWar.exe --headless -- --server --port=7777` | 화면 없는 전용 서버 |
| 설치 후 시작 메뉴의 `Cat War Dedicated Server` | UDP 7777 전용 서버 실행 |

전용 서버가 같은 EXE를 서버 모드로 실행하는 구조이므로 클라이언트와 서버의 전투 규칙 버전이 어긋나지 않습니다. 서버 PC에는 `CatWar.exe`와 `StartServer.cmd`만 복사해도 됩니다.

## 주요 기능

게임 규칙의 세부 수치(비용·체력·공격력 등)는 README에 적지 않습니다. 실제 값은 `data/units`, `data/structures`의 `.tres` 리소스가 정하고, 현재 표는 [docs/UNITS.md](docs/UNITS.md)에 자동 생성됩니다. 변경 이력은 게임 내 패치노트와 `CHANGELOG.md`에 있습니다.

**전투**
- 1대1 자동 전투와 전장 개조: 7종 유닛 중 3종, 4종 구조물 중 3종으로 덱을 구성하고 자원으로 병력을 생산하거나 구조물을 설치합니다.
- 서버 권한형 판정: 자원·생산·이동·공격·승패를 전용 서버가 같은 `BattleModel` 규칙으로 계산하고 스냅샷으로 동기화합니다.
- 동시 공격 판정, 지원·광폭화·장판·소환 같은 유닛별 특수 능력, 방벽·늪·포탑·발전기 구조물.
- 기지가 먼저 파괴된 쪽이 패배하며 시간 제한은 없습니다.
- **구조물 설치:** 구조물을 선택한 뒤 전장을 클릭합니다. 터치에서는 전장에서 누른 손가락을 이동해 위치를 미리 보고 놓으면 설치합니다. 전장 밖에서 놓거나 터치가 중단되면 그 설치 동작만 취소되며, 선택한 구조물은 다시 설치할 수 있습니다. **설치 취소** 또는 Esc로 선택을 해제합니다. 팝업·채팅·HUD 버튼과 다른 손가락의 놓기는 설치로 처리하지 않습니다.
- 온라인 설치는 **서버 확인 중** 상태를 표시합니다. 응답을 기다리는 동안 구조물 선택·추가 설치·취소를 잠시 잠그며, 이미 전송한 설치 요청은 취소할 수 없습니다. 병력 생산은 계속 사용할 수 있습니다.
- 구조물 카드 이름 옆에 **현재 설치 개수 / 종류별 한도**를 표시합니다(방벽 2개, 포탑·발전기 각 1개, 늪 3개). 전체 구조물은 진영당 3개까지이며, 제한에 도달한 카드는 **전체 한도** 또는 **종류 한도**를 표시하고 선택을 막습니다. 아군 구조물이 파괴되거나 늪이 만료되면 남은 자리와 자원에 맞춰 다시 활성화됩니다. 카드에 마우스를 올리면 개수·제한 사유·설치 방법을 볼 수 있습니다.
- 구매 카드는 **일시정지 / 연결 복구 중 / 복구 대기 / 관전 / 전투 종료** 사유를 자원·생산 대기보다 우선 표시합니다. 툴팁에서 재개 방법과 추가 자원·생산 대기를 함께 확인할 수 있습니다. 일시정지는 상단의 **계속**으로 해제하며, 연결 복구 후에는 최신 전투 상태에 맞춰 카드가 갱신됩니다. 중단 시 미전송 구조물 선택과 터치 설치 동작을 해제하고, 승패가 확정되면 결과 연출 중에도 클릭·단축키·설치를 차단합니다. 이미 전송한 설치 요청은 서버 확인을 계속 기다립니다.
- 온라인 입장·재접속 후 첫 전투 상태를 기다리는 동안 카드에 **상태 수신 중**, 자원에 **동기화 중**을 표시하고 구매를 잠급니다. 자원·생산 대기·설치 개수를 받은 뒤 같은 상태를 기준으로 카드를 갱신합니다. 새 전투 화면에는 이전 경기의 승패·자원을 이어 쓰지 않습니다.
- 결과 화면의 **전투 요약**에서 양쪽의 생산·처치·피해와 **전세 흐름 그래프**를 확인합니다. 실제 전투 시간에 따라 파랑 위쪽·빨강 아래쪽으로 우세를 표시하고 진영 이름을 함께 보여 줍니다. 같은 경기 재접속에서는 이전 전세·교전 기록을 유지하며, 관전 입장 전이나 상태 수신 공백은 곡선을 이어 그리지 않습니다. 수신 공백을 가로질러 연속 열세를 합산하지 않으며, 일부 구간이 없으면 결과 설명에도 안내합니다. 긴 요약은 터치·휠·키보드로 스크롤하고 **닫기**는 아래에 고정됩니다.
- 전투 요약의 **병력별 기여도**에서 **실제 피해 / 처치**를 전환해 비교합니다. 같은 병력의 파랑·빨강 수치를 나란히 표시하고, 선택한 항목의 양 진영 합계가 큰 순서로 정렬합니다. 막대 길이는 양쪽 공통 눈금이며 `%`는 각 진영 전체에서 해당 병력이 차지하는 비중입니다. 생산 수·포탑 건설 수·해골 소환 수도 함께 표시합니다. 해골의 공격 실적은 네크로맨서에 합산하며, 치유·방어·자원 생산 효과는 공격 집계에 포함되지 않습니다.
- 리플레이에서는 **전투 요약** 버튼 또는 **R** 키로 현재 장면까지의 누적 자원·건설·피해·처치와 병력별 기여도를 비교합니다. 종료 배너에서도 요약을 열 수 있습니다. 클립 시작 전의 전투도 포함하며, 현재 규칙으로 재현한 수치를 표시합니다. 요약을 여는 동안 재생·탐색을 멈추고 **닫기 / Esc**로 이전 재생 상태와 키보드 초점을 복원합니다. 터치·휠·방향키·Page Up/Down·Home/End로 긴 집계를 탐색할 수 있습니다.

**온라인**
- 방 기반 멀티플레이: 대기방·준비·방장 시작·같은 방 재대전·비밀번호·방 채팅·관전. 연결이 끊기면 제한 시간 동안 재접속을 기다리며 전투를 일시정지합니다.
- **빠른 대전**: 로비의 버튼 하나로 대기열에 들어가 먼저 기다린 두 플레이어가 자동으로 방을 만들고 바로 시작합니다. 언제든 취소할 수 있습니다.
- 온라인에서는 양쪽 모두 아군이 왼쪽인 시점으로 표시합니다. 서버 좌표는 바뀌지 않습니다.

**오프라인**
- 서버 없이 즐기는 8단계 AI 캠페인(별 1~3개 평가, 진행·성장 저장)과 자유 연습.
- 첫 AI 전투에서 소환→설치→자원 회복을 실제 행동에 맞춰 안내합니다(건너뛰기 가능).

**일일 도전·업적·덱 시뮬레이터**

- 메인 메뉴의 **일일 도전**은 매일 모두에게 같은 덱·AI 단계·규칙 변형을 주고 점수와 연속 클리어를 기록합니다.
- 기록 화면의 **업적**에서 달성한 배지를 볼 수 있고, 덱 편성의 **덱 시뮬레이션**은 AI와 자동 전투를 돌려 승률과 약점을 알려 줍니다.

**보조 서버와 계산 돕기**

- 별도 설정 없이 도우미를 받습니다(인증 없음, 가벼운 제한만 있음). `CATWAR_ASSIST=off`로 끌 수 있습니다. 자세한 구조는 [보조 서버·계산 돕기 설계](docs/ASSIST_DESIGN.md)를 참고하세요.
- **보조 서버**: 설치 후 시작 메뉴의 `Keepfall Assist Server`(또는 `server/StartAssist.cmd`)를 실행하면 창이 열립니다. 메인 서버 주소와 토큰을 넣고 연결하면, 체크한 종류의 작업만 받아 계산하고 현재 작업과 로그를 보여 줍니다. **종료 (마무리 후)**는 하던 조각을 끝내고 결과를 보낸 뒤 알리며, 남은 일은 메인 서버가 다시 배정합니다. 포트포워딩은 필요 없습니다(모든 연결을 도우미가 먼저 겁니다).
- **계산 돕기**: 게임 설정의 같은 이름 항목에 토큰을 넣고 켜면, 메뉴 화면에서 남는 CPU로 서버의 계산을 돕습니다. 전투 중에는 쉬고, 멀티플레이와는 별도 연결을 씁니다.
- 도우미가 없어도 메인 서버가 같은 작업을 낮은 우선순위로 직접 처리합니다.

**데이터 초기화**

- 저장 파일이 손상되면 기본 진행도로 시작했다는 안내와 원본 보관 위치를 표시합니다. 손상된 파일은 `user://catwar_save.json.recovery/`에 원본 그대로 보관한 뒤에만 새 진행도를 저장합니다. 원본을 읽거나 보관할 수 없거나 더 새로운 저장 형식이면 기존 파일을 덮어쓰지 않습니다.
- **설정 → 데이터 → 진행도 보관·복구**에서 현재 진행도 사본을 보관하고, 사본의 닉네임·별·전적을 확인해 복구할 수 있습니다. 복구 전에 현재 진행도와 디스크 원본도 보관하며, 보관이나 저장에 실패하면 현재 진행도를 유지합니다. 현재 설정·익명 ID·전송 대기 기록은 유지해 과거 결과를 다시 보내지 않습니다. 리플레이와 서버 기록은 복구 대상이 아닙니다.
- 사본 선택·가져오기·복구 확인에는 **현재 → 사본** 상세 비교가 표시됩니다. 변경된 캠페인 단계의 클리어·별·최단 승리 시간·기지 체력·시도/승리 횟수와 성장 보상, 세 덱의 이름·병력·구조물·전투 버튼 순서 및 최근 선택 덱을 확인할 수 있습니다. 다시 잠기는 단계와 줄어드는 클리어·별은 경고로 표시하며, 다른 단계에서 별이 늘어도 감소분을 따로 알려 줍니다. 복구는 높은 기록끼리 합치는 작업이 아니라 진행도 전체를 사본으로 되돌리는 작업입니다.
- **전적 · 항목별 변경**에서 AI 경기·승패, 온라인 완료·승패·무승부·중단, 최고 캠페인, 현재·최고 연승, 일일·주간 누적 성공의 현재/사본 값과 증가·감소량을 확인합니다. 줄어드는 항목은 상단 경고와 상세 행에 표시하며 다른 항목의 증가로 상쇄하지 않습니다. 패배·중단 횟수의 감소도 저장된 기록 감소로 안내합니다. **업적 · 사라짐·추가·달성 시각**은 업적 총수가 같거나 늘어도 미달성으로 바뀌는 업적 이름과 조건을 먼저 보여 줍니다. 추가되는 업적과 달성 시각만 바뀌는 업적은 별도로 표시하며, 시각이 0인 기존 달성 기록은 미달성으로 처리하지 않습니다.
- **시작 목표 · 완료 상태·다음 추천**은 사본 선택·가져오기·복구 확인에서 목표별 완료 변화를 보여 줍니다. 총 완료 수가 같거나 늘어도 다시 미완료로 바뀌는 목표 이름과 안내를 먼저 표시하고 경고합니다. 전적으로 판정하는 첫 승리·일일 도전·온라인 대전과 저장된 완료 기록으로 판정하는 덱 편성·드래프트·리플레이 보기를 실제 메뉴와 같은 기준으로 비교합니다. 다음 추천과 모든 목표 완료에 따른 메뉴 버튼의 표시 변화도 안내합니다. **튜토리얼 · 첫 전투 안내**에서는 완료 상태와 복구 후 캠페인·AI 연습에서 안내가 다시 표시되는지 확인합니다. 안내를 건너뛴 기록도 완료이며 전투 승리 여부와는 별개입니다.
- **도전 · 날짜·버전별 변경**은 일일·주간 기록의 추가·변경·사라짐·동일 개수와 현재/사본의 성공 여부·점수·전투 시간을 보여 줍니다. 이전 버전 기록도 포함하고 같은 날짜라도 버전을 나누며, 버전 미상은 동일 규칙이라고 확정하지 않습니다. 사라지는 기록과 성공→실패·점수 감소·동점의 느린 시간은 따로 경고합니다. 변경된 기록은 날짜(YYYY-MM-DD 또는 YYYYMMDD)·버전·일일/주간 등으로 검색하고 **사라짐·낮아짐 / 추가만 / 변경만**으로 좁힐 수 있습니다. 한 페이지에 8개씩 표시하며 가져오기·복구 확인창에서도 Tab·Esc와 키보드 스크롤을 사용할 수 있습니다. 시간은 해당 최고 점수를 낸 전투의 시간이며, 주간 날짜는 월요일입니다.

- 새 일일·주간 리플레이에는 도전을 시작한 콘텐츠 버전을 선택 메타데이터로 남깁니다. 기존 리플레이는 계속 읽되 버전을 추정하지 않으며, 가져온 전투도 같은 날짜·버전 기준으로 표시합니다. 선택 후 파일이 삭제되거나 내용이 바뀌면 재생을 시작하지 않고 새로고침을 안내합니다. 전투를 다시 볼 때도 현재 규칙으로 재현하므로 업데이트 뒤 결과가 달라질 수 있습니다.
- 도전 전투 선택 창의 **점수 분석**은 선택한 전투의 종료 상태를 재현해 저장된 상태 해시·결과·완료 시간·틱 수가 일치하는지 확인합니다. 남은 내 기지 체력·전체 전투 시간과 **기본 1000점 + 체력×2 − 시간(초)×2**의 계산, 합산 후 반올림과 승리 점수 100~3000점 제한을 표시합니다. 패배·무승부는 0점입니다. 현재 버전으로 확인된 전투는 같은 버전의 보관 최고 기록과 점수·시간 차이를 비교하고, 결과·시간·점수가 모두 같으면 일치 표시를 하되 같은 전투라고 확정하지 않습니다. 이전·미상 버전은 현재 규칙의 참고 점수로 안내하고 최고 기록과 비교하지 않습니다. 재현 결과가 다르면 점수를 표시하지 않습니다. 클립도 전체 전투 기준이며, 분석은 프레임마다 나눠 진행합니다. **분석 취소**, 다른 전투 분석, 새로고침·닫기·재생으로 중단할 수 있고 보관 기록·파일·순위표는 바뀌지 않습니다.
- 도전 시작 안내에도 최고 점수를 낸 전투의 시간을 표시합니다. 기록의 완료 시간은 해당 점수와 짝을 이루며, 모든 도전 중 최단 시간을 뜻하지 않습니다. 실패 기록은 실패한 전투의 시간으로 안내합니다.
- 도전 전투 선택 창에서 **재생 → 나가기**를 누르면 완료된 점수 분석·스크롤과 재생한 카드의 키보드 초점을 유지한 선택 창으로 돌아옵니다. **새로고침**에도 분석과 위치를 유지하며, 재생 중 메모만 저장해도 점수 분석은 그대로 남습니다. 전투 내용이 바뀌거나 삭제되면 이전 분석을 버리고 안내하며, 선택했던 전투가 사라지면 목록으로 초점을 옮깁니다. 새 분석은 직접 시작합니다. 선택 창의 **도전 기록으로** 또는 Esc로 닫으면 원래 날짜·버전·결과 조건과 페이지·스크롤을 유지한 기록 화면으로 돌아갑니다. 분석 결과는 선택 창과 재생기를 오가는 동안에만 기억하고 기록 화면으로 닫으면 해제합니다. 긴 전투 분석에서도 화면에 쓰지 않는 전투 이벤트를 계속 쌓지 않습니다.
- 도전 이력은 실제 달력 날짜(주간은 월요일), 성공 여부에 맞는 점수, 유한한 0초 이상 전투 시간을 확인한 뒤 최근 일일 60일·주간 16주를 남깁니다. 손상된 항목이 정상 기록의 보관 자리를 차지하지 않으며, 주 기록이 손상돼도 유효한 이전 버전 기록은 유지합니다. 시간 제한이 없는 로컬 전투의 긴 시간은 줄이지 않습니다. 로드 시 제외한 기록 수와 원본 보관 위치를 안내하며, 원본 사본 보관에 실패하면 자동 저장으로 원본을 덮어쓰지 않습니다.
- 도전 점수에도 생성 당시 버전을 저장하며, 현재 버전 점수만 전송하고 같은 버전의 저장 확인만 처리합니다. 이전·버전 미상 대기 점수는 제출 기간까지 보관하지만 전송하지 않습니다. 같은 날짜의 새 버전 점수를 얻으면 이전 대기 점수를 교체하며, 이전 최고 기록은 프로필에 남습니다. 기존 서버의 `daily_board.json`은 버전 미상 자료로 보존하고 새 순위표와 합치지 않습니다.

- 도전 안내의 규칙·덱·순위표는 스크롤해서 확인할 수 있습니다. 공유 상태와 도전 시작·돌아가기 버튼은 아래에 고정되어 순위표가 길어져도 사용할 수 있습니다.

**리플레이**
- 서버가 진행한 모든 온라인 전투와 AI 캠페인·(도구를 쓰지 않은) AI 연습 전투는 플레이어 명령만 `user://replays/`에 JSON으로 저장됩니다(읽을 수 있는 최근 50개 유지). 전투가 결정론적이므로 같은 규칙으로 다시 계산하면 결과가 똑같이 재현됩니다.
- 메인 메뉴의 **리플레이**에서 저장된 전투를 목록으로 보고 재생·삭제할 수 있습니다. 재생 화면은 일시정지, 0.5~8배속, 처음부터 다시 보기, 시간 막대로 원하는 지점 이동을 지원합니다.
- 보관함에서 전투 종류·결과·전체 전투/클립을 함께 필터링하고, 날짜·파일명·양쪽 덱의 병력/구조물 이름·메모·클립 제목과 구간을 검색할 수 있습니다. 공백으로 나눈 검색어를 모두 포함한 기록만 표시합니다(예: `일일 20261013`, `방패병`, `00:10`). 결과 개수와 전체 개수를 함께 안내하며 **초기화**로 전체 목록을 다시 봅니다. 온라인·기타 결과는 블루/레드 기준입니다.

- 리플레이는 **코드** 버튼으로 서버에 올려 짧은 코드로 공유하고, **코드로 열기**로 코드를 입력해 봅니다. **최근 온라인 전투**에는 서버가 기록한 온라인 전투가 공개 목록으로 나옵니다(덱과 명령만 담기며 닉네임은 담기지 않습니다). 이 기능들은 필요할 때 자동으로 서버에 접속합니다(접속하지 못하면 이유를 안내합니다).
- **코드로 열기 → 재생 → 나가기**는 입력했던 코드를 유지한 채 코드 창으로 돌아갑니다. 코드가 선택된 상태라 바로 새 코드를 입력하거나 **열기**로 다시 볼 수 있습니다. 복귀할 때는 자동으로 접속·다운로드하지 않으며, 다시 열기는 서버에서 새로 불러옵니다. 재생 전 보관함의 검색 조건과 스크롤도 유지합니다. 코드 창에서 **닫기**나 Esc를 누르면 진행 중인 불러오기를 해제하고 **코드로 열기** 버튼으로 키보드 초점을 돌립니다. 코드 수정 중에는 커서를 맨 뒤로 옮기지 않습니다.
- 최근 온라인 전투 카드에 **서버 보관 시각(UTC)**과 조회 당시의 경과 시간을 표시합니다. 전투 시작·종료 시각과 다를 수 있으며, 경과 시간은 기기 시계로 계산합니다. 이전 파일의 수정 시각은 **보관 시각 추정**, 시각을 제공하지 않는 서버는 **보관 시각 미상**으로 구분합니다. 기기 시계보다 미래이면 시계 확인을 안내하고, **새로고침**으로 경과 시간을 다시 계산합니다.
- 공개 목록은 최신 보관순으로 최대 20개를 표시합니다. 서버 보관은 공유 코드와 공개 전투를 합쳐 최근 200개 기준이며 고정 만료 시간은 없습니다. 새 전투·공유 업로드가 쌓이면 오래된 코드가 정리될 수 있습니다. 목록의 **코드 복사**는 추가 업로드 없이 코드를 복사하며, 계속 보려면 **보기 → 로컬 보관**으로 기기에 저장하세요. 코드 복사만으로 전투가 보존되지는 않습니다.
- 최근 온라인 전투에서 **보관 날짜·코드·병력 검색**, **종류 전체 / 빠른 대전 / 방 대전**, **결과 전체 / 블루 승 / 레드 승 / 무승부**로 조회된 목록을 좁힐 수 있습니다. 공백으로 나눈 검색어는 모두 포함되어야 하며 코드·영문 병력 ID는 대소문자를 구분하지 않습니다. 보관 날짜는 `2026-10-13`이나 `20261013`으로 찾고, 양쪽 병력 이름·전투 시간(`00:30`)·보관 시각 미상도 검색할 수 있습니다. 검색은 최근 공개 목록 안에서만 수행하며 추가 다운로드는 없습니다. 표시 개수와 검색 결과 없음 안내를 제공하고 **초기화**로 전체 목록을 다시 봅니다. 새로고침·창 재진입 때 검색 조건과 스크롤을 유지하며 게임을 종료하면 초기화됩니다.
- 최근 온라인 목록은 양쪽 덱을 각각 줄바꿈하고, 코드 복사·보기와 고정된 새로고침·닫기 버튼에 최소 높이 58을 적용합니다. 목록에 초점을 두고 방향키·Page Up/Down·Home/End로 스크롤하고 Tab으로 버튼을 이동하며 Esc로 닫을 수 있습니다. 새로고침 후 스크롤과 목록에 남은 코드의 버튼 초점을 유지하고, 닫으면 진입 버튼으로 초점을 돌립니다. 조회 실패 시 기존 목록을 유지하며, 서버에서 정리된 코드는 목록 새로고침을 안내합니다.
- 최근 온라인 전투의 **보기** 요청은 검색·목록 새로고침 중에도 유지됩니다. 선택한 코드의 접속·응답 대기 상태를 상단과 카드에 표시하며, 카드가 검색으로 숨겨지거나 최신 목록에서 빠져도 상단 안내가 남습니다. 불러오는 동안 다른 전투의 보기만 잠그고 코드 복사·검색·새로고침·닫기는 사용할 수 있습니다. 실패 이유는 카드에도 표시하고 **재시도**를 제공합니다. 목록 갱신과 보기의 오류 안내는 각각 유지하며, 창을 닫은 뒤 도착한 응답은 전투를 재생하지 않습니다.
- 최근 온라인 전투와 **코드로 열기**에서 접속·응답을 기다리는 동안 **불러오기 취소**를 누르면 창을 유지한 채 다른 전투·코드를 바로 선택할 수 있습니다. 취소한 요청의 응답으로 자동 재생하지 않으며, 이미 서버에 보낸 요청의 전송 자체를 되돌리는 기능은 아닙니다. 서버 연결과 진행 중인 목록 새로고침은 유지합니다. 최근 목록의 취소 안내는 검색으로 카드가 숨겨지거나 새로고침으로 교체되어도 남습니다. 취소·실패 후 목록의 보기 버튼 또는 코드 입력으로 키보드 초점을 돌리고, 코드 창에서도 Tab으로 이동하고 Esc로 닫을 수 있습니다.
- 최근 온라인 전투에서 **보기 → 나가기**는 재생 전 목록으로 바로 돌아갑니다. 검색·종류·결과·스크롤과 선택 카드의 **보기** 버튼 초점을 유지하며, 연결이 끊겨도 목록 복귀는 가능합니다. 복귀한 목록은 **재생 전 조회 목록**으로 표시하고 당시 조회 시각과 경과 시간을 유지합니다. **새로고침**으로 최신 목록을 받으며, 실패하면 이전 목록을 계속 볼 수 있습니다. 이 목록은 게임 실행 중에만 기억하고 전투 자체는 **로컬 보관**으로 저장합니다.
- 같은 리플레이 내용은 기기에 저장·로드하거나 JSON 표현이 달라져도 서버 보관 중인 코드를 재사용합니다. 메모·클립·전투 내용이 다르면 별도 코드로 보관하며, 기존 공유 코드와 원본은 유지합니다.
- 코드 열기·발급·최근 전투 보기는 요청 중 중복 전송을 막고, 연결 실패나 응답 지연 시 재시도를 안내합니다. 닫힌 화면의 늦은 응답은 재생이나 클립보드 변경을 일으키지 않습니다. 코드 발급 응답이 지연되면 같은 전투의 응답을 다시 기다릴 수 있으며, 다른 전투는 기존 발급 응답이 도착하거나 연결이 바뀔 때까지 **복사**로 공유할 수 있습니다. 최근 온라인 전투 목록에는 **새로고침**을 제공합니다.
- 카드에 발급된 코드를 다시 누르면 서버에 재전송하지 않고 클립보드에 복사합니다. 공유 내용이 바뀌면 새 코드를 요청합니다.
- 재생 화면에서 **구간 반복**(시작·끝 지점 지정), 유닛을 눌러 보는 **정보 패널**, 마우스 휠 **확대**와 가운데 버튼 **이동**을 쓸 수 있습니다.
- 비교할 장면에서 **시작 [**을 누르고 뒤의 장면으로 이동해 **끝 ]**을 누른 뒤 **전투 요약 / R**을 열면 **선택 구간**의 자원·건설·병력별 피해·처치·생산·소환을 비교합니다. 반복 재생을 켤 필요는 없습니다. **현재까지 누적**으로 전환하면 요약을 연 장면까지의 집계를 봅니다. 구간 시작 전에 생산된 병력의 구간 내 피해·처치도 포함하며, 비중은 선택 구간의 진영 합계 기준입니다.
- 같은 시작·끝 지점을 정하면 **클립 복사**가 **구간 복사**로 바뀝니다. 화면 위에 표시된 범위와 길이를 확인해 복사하면, 다른 사람이 **클립보드에서 가져오기**로 열 때 그 시작 지점에서 재생하고 정확한 끝 지점에서 멈춥니다. 재생 위치가 구간 밖이어도 지정한 범위를 공유하며 반복을 켤 필요는 없습니다. 시작만 정했을 때는 끝을 정해야 복사할 수 있습니다. **구간 해제**는 지점·반복·비교 범위를 해제하고 주변 장면의 클립 복사로 되돌립니다.
- 공유 클립에는 구간 시작의 전투 상태를 재현하기 위한 전체 전투 기록과 모든 메모가 포함됩니다. 클립 끝에서 **재생**을 누르면 나머지 전투를 이어서 볼 수 있고, 구간 안으로 다시 탐색하면 끝에서 다시 멈춥니다. **처음부터**는 클립 시작으로 돌아갑니다. 복사만으로 원본 리플레이나 로컬 보관 파일이 바뀌지는 않습니다.
- 재생 화면에서 장면마다 **메모**를 남길 수 있고, 메모는 리플레이와 함께 저장·공유됩니다.
- 코드나 최근 온라인 전투로 연 리플레이도 **로컬 보관**할 수 있습니다. 첫 메모를 남기면 자동으로 이 기기에 보관하고, 이후 메모는 같은 파일에 저장합니다. 메모 저장 실패 시에는 재시도 버튼을 표시합니다.
- 전투 종료 후 리플레이 저장에 실패하면 화면 상단의 **저장 재시도**로 복구할 수 있습니다. 화면을 이동하거나 다음 전투를 시작해도 실패한 기록을 유지하며, 저장 전에는 자동 업데이트를 보류합니다. 게임을 종료하기 전에 저장을 완료하세요.
- 리플레이는 최대 216,000틱(30Hz 기준 2시간)과 플레이어 명령 20,000개를 기록합니다. 상한을 넘은 전투는 불완전한 리플레이를 저장하지 않고 이유를 안내합니다. 전투 진행과 전적 집계는 계속됩니다.
- 리플레이는 **복사** 버튼으로 한 줄 텍스트가 되어 클립보드에 복사되고, 다른 사람이 **클립보드에서 가져오기**로 목록에 추가할 수 있습니다(손상·조작된 텍스트는 거부).
- 구간을 지정하지 않은 뷰어의 **클립 복사**는 가까운 명장면(없으면 현재 위치) 앞뒤 10초를 텍스트로 복사합니다. 리플레이의 기록 주파수에 맞춰 시간을 계산합니다. **되감기 실험**은 원하는 순간부터 직접 이어서 플레이합니다. 목록의 **고스트 대전**은 리플레이 속 상대의 행동을 재현한 상대와 겨루고, **덱 분석**은 저장된 리플레이로 덱 성적을 모아 보여 줍니다.
- 규칙이 바뀐 뒤에도 결과가 같은지 검증하거나 밸런스·버그 재현에 쓸 수도 있습니다. [리플레이 사용법](#리플레이-사용법)을 참고하세요.

**기타**
- 한국어 전용, 오디오(BGM·효과음)·화면·전투 연출·키 설정. 버튼·전투 카드·결과 화면의 UI 효과음은 실행 중 합성하므로 별도 음원 파일이 없습니다.
- 터치 기기에서는 모든 버튼과 슬라이더가 손가락 크기(최소 높이 58)로 커집니다. 제목과 큰 숫자에는 번들 글꼴 Black Han Sans(OFL)를 씁니다.
- 개인 전적과 덱 프리셋 저장, 투명 PNG 캐릭터와 픽셀아트 렌더링.
- Windows 설치·제거 프로그램, Android ARMv7·ARM64 서명 APK와 설치 화면 없이 갱신되는 콘텐츠 팩.

## 설치 프로그램 사용

`dist/CatWarSetup.exe`를 더블 클릭하면 일반 Windows 응용프로그램처럼 설치됩니다.

설치되는 항목:

- `%LOCALAPPDATA%\Programs\Cat War\CatWar.exe`
- 시작 메뉴의 `Cat War`
- 시작 메뉴의 `Cat War Dedicated Server`
- 선택 가능한 바탕 화면 바로가기
- Windows 설정의 앱 제거 항목

현재 설치 파일은 코드 서명 인증서로 서명하지 않았으므로 다른 PC에서는 Windows SmartScreen 경고가 표시될 수 있습니다.

Android에서는 Release의 `CatWar.apk`를 내려받아 최초 한 번 설치합니다. 이후 일반적인 게임 코드·장면·이미지·음원 업데이트는 실행 시 `CatWarContent.pck`를 자동으로 내려받아 적용하므로 APK 설치 화면이 나타나지 않습니다. Godot 엔진, Android 권한 또는 네이티브 설정이 변경된 때만 새 APK 설치가 필요합니다. 매 릴리스 최신 콘텐츠를 포함한 APK를 같은 전용 키로 새로 빌드하며, 콘텐츠만 바뀐 경우 네이티브 버전을 유지해 기존 설치자에게 불필요한 APK 업데이트를 강제하지 않습니다.

## 강제 자동 업데이트

`main` 브랜치에 코드가 푸시될 때마다 `.github/workflows/build-and-deploy.yml`이 다음 작업을 수행합니다.

1. 테스트 묶음(unit · network · ui · security · balance · release)을 병렬 job으로 실행
2. `release.json`에 지정된 출시 버전과 대상 커밋으로 새 빌드 생성
3. Windows 게임/서버 EXE·설치 프로그램, Android APK와 콘텐츠 팩 생성
4. 설치 프로그램·APK·콘텐츠 팩의 SHA-256 및 APK 서명 검증
5. 새 버전일 때만 버전 태그와 GitHub Release 생성(기존 태그는 덮어쓰지 않음)
6. GitHub Pages에 `update.json`, `CatWarSetup.exe`, `CatWar.apk`, `CatWarContent.pck` 배포

게임은 `https://gamparda.github.io/codingcircle/update.json`을 시작 시점과 비전투 상태에서 60초마다 확인합니다. 최신 버전이 발견되면 업데이트를 건너뛸 수 없으며, 설치 파일을 다운로드하고 SHA-256을 검증한 다음 게임을 종료해 무인 설치하고 자동 재실행합니다.

Android 부트스트랩은 실행 직후 같은 메타데이터를 확인합니다. APK 자체 교체가 필요하면 **APK 업데이트가 필요합니다.** 안내와 다운로드 버튼을 표시합니다. 콘텐츠 팩만 더 최신이면 앱 전용 저장소로 자동 다운로드하고 SHA-256을 검증한 뒤 원자적으로 교체합니다. 새 팩은 메인 장면이 5초 이상 안정적으로 실행된 뒤에만 부팅 성공으로 확정하며, 그 전에 종료되면 다음 실행에서 보관한 이전 팩 또는 APK 내장 버전으로 복구합니다. 네트워크가 끊겼을 때는 **현재 버전으로 시작**할 수 있으며 다음 실행에서 다시 자동 확인합니다.

- 메뉴·매칭 대기·결과 화면: 즉시 강제 업데이트
- 진행 중인 경기: 새 버전만 감지하고 다운로드·설치는 경기 종료까지 대기
- 전용 서버: 활성 매치가 없을 때만 설치 및 재시작
- 업데이트 서버 접속 실패: 현재 실행은 유지하고 나중에 자동 재시도

테스트를 통과한 최신 `main` 빌드가 곧 자동 업데이트 채널(GitHub Pages)이 됩니다. GitHub Release는 **새 버전 번호일 때만** 만들어집니다.

### 버전 관리

버전은 **`release.json` 한 곳에서만** 고칩니다.

```json
{ "content_version": "0.18.0", "windows_version": "0.16.0", "android_binary_version": "0.4.18", "update_url": "..." }
```

```powershell
python tools/release_meta.py sync    # release.json → build_info.json, project.godot, export_presets.cfg
python tools/release_meta.py check   # 생성 파일이 release.json과 어긋나면 실패(CI가 실행)
```

Android 네이티브 바이너리 버전은 콘텐츠·Windows 버전과 독립적으로 유지합니다. 빌드 스크립트는 `build_info.json`의 커밋 값을 실제 대상 SHA로 교체하고, Pages용 `update.json`은 workflow가 SHA-256과 배포 시각을 포함해 생성합니다.

### 정식 릴리스와 개발 빌드

- `release.json`의 `content_version`이 **새 값**이면 `v<버전>` 태그와 GitHub Release가 만들어집니다.
- 이미 존재하는 태그는 **덮어쓰지 않습니다.** 같은 버전으로 다시 푸시하면 업데이트 채널(Pages)만 갱신되고 산출물은 `dev-build-*` workflow 아티팩트(14일 보관)로만 남습니다. 정식 릴리스를 새로 내려면 `release.json`의 버전을 올리세요.
- GitHub Pages 배포가 처음이라면 저장소의 **Settings → Pages → Source**가 `GitHub Actions`로 설정되어 있어야 합니다.

각 Release에는 다음 파일이 포함됩니다.

- `CatWarSetup.exe`
- `CatWar.apk`
- `CatWarContent.pck`
- `update.json`
- `SHA256SUMS.txt`
- GitHub가 자동 생성하는 소스 ZIP과 TAR.GZ
- 이전 버전 이후의 자동 변경 내역

버전별 수동 다운로드는 [GitHub Releases](https://github.com/gamparda/codingcircle/releases)에서 할 수 있습니다.

## 한 번에 전체 빌드

저장소 루트에서 다음 한 줄을 실행합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build_release.ps1
```

스크립트가 순서대로 수행하는 작업:

1. 게임 규칙·v0.4 기능·UI 흐름 테스트 실행
2. Windows용 게임/서버 겸용 `CatWar.exe` 생성
3. 생성된 EXE의 오프라인 AI 모드 실행 검증
4. Inno Setup으로 설치 프로그램 생성

결과물:

```text
builds/CatWar.exe

dist/CatWarSetup.exe
```

Godot 또는 Inno Setup을 사용자 지정 위치에 설치했다면 다음처럼 경로를 넘길 수 있습니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build_release.ps1 -GodotPath "C:\경로\godot_console.exe" -IsccPath "C:\경로\ISCC.exe"
```

대상 커밋을 지정하거나 테스트를 건너뛸 수 있습니다. 버전 번호는 인자로 바꾸지 않고 `release.json`을 고칩니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build_release.ps1 -Version "0.4.2" -Commit "테스트커밋SHA"
```

## 실행 방법

### 게임 클라이언트

```powershell
.\builds\CatWar.exe
```

온라인 대전은 주소 입력 없이 공식 서버 `ruellyya.kr:7777`에 연결됩니다. 일반 클라이언트에서는 다른 서버 주소로 변경할 수 없습니다.

### 전용 서버

```powershell
.\builds\CatWar.exe --headless -- --server --port=7777
```

또는 다음 런처를 사용합니다.

```powershell
.\server\StartServer.cmd 7777
```

서버는 **UDP**를 사용합니다. 서버 PC의 Windows 방화벽, 공유기 포트 포워딩 또는 클라우드 보안 그룹에서 선택한 UDP 포트를 허용해야 합니다.

### 오프라인 AI 대전

Windows 또는 Android 클라이언트를 실행하고 **AI 캠페인** 또는 **AI 연습**을 선택합니다. 서버나 인터넷 연결이 필요하지 않습니다.

## 데이터와 밸런스

- 유닛·구조물 수치는 `data/units/*.tres`, `data/structures/*.tres`에서 **한 번만** 정의합니다. 새 파일을 추가하면 `scripts/data/GameData.gd`의 목록에도 등록해야 하며 `tests/unit_data_test.gd`가 누락을 잡습니다.
- 수치를 바꾼 뒤 `python tools/gen_unit_docs.py`로 [docs/UNITS.md](docs/UNITS.md)를 갱신합니다(테스트가 최신 여부를 확인).
- 대규모 자동 대전 실험은 [docs/BALANCE_BENCHMARK.md](docs/BALANCE_BENCHMARK.md), 지난 조정 결과는 [docs/BALANCE_RESULTS.md](docs/BALANCE_RESULTS.md)를 참고하세요.

## 테스트

`tests/suites.json`이 모든 테스트를 묶음으로 나눕니다. 새 테스트 파일은 반드시 한 묶음에 등록해야 하며 `suites_cover_all_tests_test.py`가 확인합니다.

| 묶음 | 내용 |
|---|---|
| `unit` | 전투 규칙, 데이터, AI, 저장, 리플레이 |
| `network` | 프로토콜, 방·재접속·빠른 대전(실제 2~4 클라이언트 RPC 포함) |
| `ui` | 메뉴·덱·전투 HUD·대기방·.tscn 화면·리플레이 뷰어·터치 크기 검사 |
| `security` | 업데이트 스크립트와 설치 프로그램 보안 |
| `balance` | 벤치마크 구매 정책, 밸런스 데이터 무결성, 수치 문서 최신 여부 |
| `release` | 버전 정책, 번역 카탈로그, 묶음 누락 검사 |
| `render` · `production` | `all`에 포함되지 않음. 실제 화면(xvfb/GPU)이나 운영 서버가 필요한 수동 점검 |

```powershell
python tools/run_suite.py all
```

## 리플레이 사용법

```powershell
# 저장된 모든 리플레이를 다시 계산해 기록된 결과와 같은지 검증 (규칙이 바뀌면 실패)
```

파일에는 초기 덱·자원·기지 체력, 틱 번호가 붙은 생산/설치 명령, AI 단계(있는 경우), 결과 해시만 들어 있어 보통 수 KB입니다. 서버 매치는 30Hz 고정 간격, 캠페인 전투도 30Hz 고정 간격으로 진행되어 결과가 정확히 재현됩니다.

## 온라인 배포 체크리스트

1. 서버와 클라이언트를 같은 커밋에서 빌드합니다.
2. 중앙 Linux 전용 서버의 updater가 최신 `main`을 설치하도록 합니다. 플레이어 호스트/LAN 대전은 지원하지 않습니다.
3. 외부 UDP 7777을 전용 서버로 전달하고 방화벽에서 허용합니다.
4. `catwar-server.service`와 `catwar-update.timer`가 활성 상태인지 확인합니다.
5. 두 클라이언트가 공식 서버에 접속해 서로 다른 진영과 같은 매치 스냅샷을 받는지 확인합니다.
6. 같은 LAN에서는 NAT loopback 우회를 위해 `192.168.0.4:7777`, 외부에서는 `ruellyya.kr:7777`과 공인 IP fallback을 사용합니다. 모두 동일한 중앙 서버 경로입니다.

## 방 기반 멀티플레이

멀티플레이 → 닉네임·덱 선택 → 방 생성/참가 → 준비 → 방장 시작 → 결과 → 같은 방에서 재대전. 비밀번호는 선택이며 관전 입장에도 적용됩니다. 대기실과 전투에서 방 채팅을 사용할 수 있고, 진행 중인 경기에도 관전할 수 있습니다. 관전자에게 전투 조작 권한이나 개인 승패 기록은 부여하지 않습니다. 방장 이탈 시 남은 플레이어에게 소유권을 넘기고, 마지막 플레이어가 나가면 방을 정리합니다. 방 비밀번호는 게임 입장용이며 ENet 게임·채팅 전체의 TLS/종단간 암호화를 의미하지 않습니다.
