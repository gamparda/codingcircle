# 프로젝트 개선 기록

## 2026-10-13 — 진행도 복구 전 닉네임·새 기능 확인 상태 비교

- 이번 주제: 진행도 사본 선택·가져오기·복구 확인에서 닉네임과 새 기능별 확인 상태 변화를 미리 안내한다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 해시와 HEAD·인덱스 루트 트리를 비교했다. 미커밋 변경과 미추적 파일은 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고 아직 남아 있던 복구 시 프로필·새 기능 상태 비교를 선택했다. 소스 수정 전에 주제를 로그에 기록했다.
- 확인한 문제: 복구는 닉네임과 seen_features도 사본 값으로 되돌리지만 기존 상세 비교에는 이 변화가 없었다.
- 프로필 항목에 현재 → 사본 닉네임을 표시하고 이름이 달라지는 경우 상단에서 경고한다. 같은 이름은 변경 없음으로 안내한다.
- 복구 후 멀티플레이의 닉네임 입력에 사본 이름이 표시되고 다시 수정할 수 있음을 설명한다. 서버에 보관된 기록은 복구 대상이 아님을 안내한다.
- 현재 새 기능 안내 목록의 각 기능을 확인함·미확인으로 비교한다. 다시 미확인이 되는 기능 이름을 먼저 표시하고 경고한다.
- 총 미확인 수가 같거나 줄어도 기존 확인 기록의 변화를 따로 표시한다. 다른 기능의 확인 증가로 상쇄하지 않는다.
- 확인함으로 바뀌는 기능과 상태 유지 개수도 표시하며, 변화가 없는 사본은 변경 없음으로 안내한다.
- 실제 메뉴의 NewFeatures.FEATURES·is_seen·unseen·features_for를 재사용한다. 기능 제목·목록·확인 판정은 별도로 복제하지 않는다.
- 미확인 개수 변화와 모든 기능 확인 여부에 따라 새 기능 버튼이 다시 표시되거나 숨겨지는 동작을 설명한다.
- 메뉴별 NEW 변화는 같은 메뉴로 연결된 모든 기능을 함께 판정한다. 리플레이 기능 하나가 미확인이면 해당 메뉴의 NEW를 유지하는 기준을 따른다.
- 과거 기능 ID와 확인 배열의 순서는 현재 안내 개수·NEW 판정에서 제외한다. 과거 ID는 사본 내용대로 복구됨을 설명한다.
- 확인 상태는 기능의 잠금이나 전투 진행도와 별개임을 안내해 미확인으로 복구되는 의미를 분명히 한다.
- 공통 비교에 연결해 사본 선택·클립보드 가져오기·최종 복구 확인에서 같은 내용을 보여 준다. 복구 범위 안내에도 닉네임·새 기능 상태를 명시한다.
- 기존 줄바꿈·세로 스크롤과 경고색을 사용한다. 새 버튼·초점 정지점은 추가하지 않아 기존 Tab·Esc·스크롤 조작을 유지한다.
- 실제 복구와 같은 정규화된 데이터를 읽기만 한다. 원본 보관·지문 확인·저장 실패 처리와 현재 설정·익명 ID·전송 대기 기록 유지 정책은 바꾸지 않는다.
- README를 갱신하고 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 비교 데이터·메뉴 판정·세 화면 연결을 소스로 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 실제 로드·표시·조작 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식을 유지한다. 버전 번호·release.json·CHANGELOG·PatchNotes는 수정하지 않았고 Git 명령은 실행하지 않았다.
- 다음 후보: 도전 보관 전투에서 내 덱·상대 덱을 나눠 검색하는 흐름, 공유 코드를 서버에서 찾지 못했을 때 보관 정책과 로컬 보관 경로 안내, 복구 사본의 덱별 변경을 한눈에 고르는 흐름.

## 2026-10-13 — 공유 코드 붙여넣기와 잘린 입력 방지

- 이번 주제: 코드 입력 창에 검증된 클립보드 붙여넣기를 추가하고, 긴 입력이 6자리로 잘려 다른 전투를 여는 문제를 막는다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 해시와 HEAD·인덱스 루트 트리를 비교했다. 미커밋 추적 변경과 미추적 소스·문서는 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고 공유 코드 붙여넣기를 선택했다. 소스 수정 전에 이번 주제를 로그에 기록했다.
- 확인한 문제: 입력의 6자 제한이 긴 코드·문장을 앞의 6자로 잘라 유효한 다른 코드를 요청할 수 있었다. 터치 화면에는 전용 붙여넣기 조작도 없었다.
- 입력 길이 제한을 제거해 직접 입력·기본 붙여넣기의 전체 내용을 검증한다. 긴 내용을 잘라 요청하지 않는다.
- 코드 전체의 앞뒤 공백을 제거하고 대문자로 정리한 뒤 기존 NetworkProtocol 검증기를 사용한다. 코드 길이·허용 문자는 바꾸지 않는다.
- 코드 입력 옆에 붙여넣기 버튼을 추가하고 터치 최소 높이 58을 적용했다. 별도 행을 늘리지 않고 기존 창 크기를 유지한다.
- 클립보드는 버튼을 누를 때만 읽는다. 창 열기·재생 후 복귀 때 기존 입력을 자동으로 덮어쓰지 않는다.
- 유효한 코드는 입력·전체 선택하고 열기 안내를 표시한다. 붙여넣기 자체로 서버 접속·다운로드를 시작하지 않는다.
- 빈 클립보드와 잘못된 코드는 각각 안내하고 기존 입력을 유지한다. 임의의 문장·리플레이 텍스트에서 6자 부분을 추출하지 않는다.
- 직접 열기의 오류 안내에도 허용되지 않는 I·O·0·1과 중간 공백을 명시한다. 유효한 입력은 실제 요청 코드로 정리해 표시한다.
- 다운로드 중에는 붙여넣기도 잠그고 취소·실패 후 즉시 복원한다. 기존 요청 소유권·중복 요청 방지·늦은 응답 보호를 유지한다.
- Tab 순환에 붙여넣기를 포함하며 잠긴 조작은 건너뛴다. Esc 닫기·입력 커서 보존·재생 후 코드 복귀·진입 버튼 초점 복원을 유지한다.
- 입력 안내를 줄바꿈해 버튼 추가 후에도 창 폭 안에 표시한다. 오류 안내는 클립보드 원문을 표시하지 않는다.
- README에 붙여넣기·검증·요청 잠금 동작을 안내하고 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 검증기·입력·취소·실패·초점 경로를 소스로 검토했으며 실제 로드·조작 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식을 유지한다. 버전 번호·release.json·CHANGELOG·PatchNotes는 수정하지 않았고 Git 명령은 실행하지 않았다.
- 다음 후보: 진행도 복구 전 닉네임·새 기능 확인 상태의 변화 안내, 도전 보관 전투에서 내 덱·상대 덱을 나눠 검색하는 흐름, 공유 코드를 서버에서 찾지 못했을 때 보관 정책과 로컬 보관 경로를 안내하는 흐름.

## 2026-10-13 — 새 기능 바로가기 복구와 안내 창 조작 개선

- 이번 주제: 열리지 않던 라이브 전투·리플레이 뷰어 바로가기를 복구하고, 새 기능 안내의 스크롤·초점·확인 상태 표시를 개선한다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 해시와 HEAD·인덱스 루트 트리를 비교했다. 미커밋 변경과 미추적 파일은 없었다.
- 최근 3회차·아카이브와 다음 후보를 읽었다. 후보 밖의 새 기능 진입 경로를 조사해 실제 작동하지 않는 버튼을 발견했고 소스 수정 전에 주제를 기록했다.
- 확인한 문제: 라이브 전투 목록·리플레이 뷰어 강화는 열기에서 처리되지 않아 창만 닫힌 뒤 확인 완료로 저장됐다.
- 기능별 ID 대신 기존 메뉴 버튼의 목적지로 연결한다. 현재 6개 기능을 주간 도전·드래프트·리플레이·덱 편성·멀티플레이의 기존 진입점으로 보낸다.
- 라이브 전투는 기존 방 목록과 공식 서버 접속 경로를 사용한다. 리플레이 뷰어 강화는 보관함에서 재생할 전투를 고르는 기존 흐름으로 연결한다.
- 없는 ID나 지원하지 않는 목적지는 창을 닫거나 확인 상태를 저장하지 않는다. 이동 경로가 있는 기능만 기존 방식으로 확인 처리한다.
- 같은 리플레이 메뉴로 이어지는 공유·뷰어 기능은 함께 확인 처리하는 기존 규칙을 유지한다. 기능 목록·ID·저장 판정은 바꾸지 않는다.
- 메뉴를 유지하는 주간 도전 안내에서도 NEW 태그와 새 기능 개수를 즉시 갱신한다. 모든 기능을 확인하면 칩을 숨긴다.
- 기존 메뉴 버튼으로 들어갈 때도 같은 갱신을 적용한다. 프로필 저장 실패 경고·재시도는 기존 Main._save_profile 경로를 유지한다.
- 안내 창에 미확인/전체 개수와 NEW·확인함 표시를 추가한다. 창을 열어 보거나 닫는 것만으로는 확인 처리하지 않는다.
- 6개 카드가 고정 창 높이를 넘지 않도록 세로 스크롤에 넣고 제목·설명을 줄바꿈한다. 닫기 버튼은 스크롤 밖에 유지한다.
- 열기·닫기에는 터치 최소 높이 58, 목록에는 터치 스크롤 데드존을 적용한다. 기존 카드와 버튼 이름을 유지한다.
- 첫 미확인 기능에 초점을 두고 배치 후 보이도록 스크롤한다. 이미 모두 확인했다면 첫 기능에 초점을 두며 배치 대기 중 이동한 초점을 빼앗지 않는다.
- Tab·Shift+Tab과 방향키의 이동을 창 안으로 묶는다. Page Up/Down·Home/End는 목록을 스크롤하고 목록 초점의 위·아래는 조금씩 스크롤한다.
- 닫기와 Esc는 같은 경로로 돌아가 원래 메뉴 컨트롤의 초점을 복원한다. 대상이 사라지면 새 기능 칩·멀티플레이 버튼을 사용한다.
- 화면·팝업 수명을 확인해 이전 창의 클릭·배치 후 스크롤·초점 복원이 새 화면이나 새 팝업에 적용되지 않도록 한다.
- README에 바로가기·공동 확인·스크롤·키보드 조작을 안내했다. 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 목적지 함수·콜백·확인 상태·화면 수명을 소스로 검토했으며 실제 로드·조작 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식을 유지한다. 버전 번호·release.json·CHANGELOG·PatchNotes는 수정하지 않았고 Git 명령은 실행하지 않았다.
