# 프로젝트 개선 기록

## 2026-10-13 — 도전 보관 전투의 점수 분석과 최고 기록 비교

- 이번 주제: 도전 리플레이를 선택 창에서 분석해 기지 체력·완료 시간의 점수 근거와 최고 기록 차이를 확인한다.
- 이어서 마무리: 분석 중 전투 이벤트 누적을 막고, 새로고침에도 분석 결과·선택 위치를 유지하며 중단된 기록을 완성한다.
- 시작 상태: Git 명령 없이 추적 파일·인덱스 해시와 HEAD·인덱스 루트 트리를 읽어 미커밋 변경이 없음을 확인했다. 이번 주제만 적힌 중단 기록과 이미 반영된 관련 코드를 먼저 검토했다.
- 최근 3회차와 아카이브의 다음 후보를 읽었다. 새 주제를 중복 구현하지 않고 도전 점수 분석 회차를 마무리했다.
- 보관 전투 카드의 점수 분석에서 내 기지 체력·전체 전투 시간과 기본 점수·체력 가점·시간 감점·반올림·최솟값/최댓값 적용을 표시한다.
- 종료 상태 해시·승패·틱 수·완료 시간이 저장 결과와 일치할 때만 점수를 표시한다. 패배·무승부는 0점이다.
- 현재 버전 전투만 같은 버전의 보관 기록과 점수·시간 차이를 비교한다. 이전·미상 버전은 현재 규칙의 참고 점수로 구분한다.
- 결과·시간·점수가 모두 같아도 같은 전투라고 확정하지 않는다. 클립 분석은 전체 전투의 종료 점수임을 안내한다.
- 선택한 전투만 프레임마다 최대 120틱·약 5ms씩 분석하며 취소·다른 전투 분석·새로고침·닫기·재생으로 중단한다.
- 마무리 중 발견한 문제: 분석용 모델에서 쓰지 않는 전투 이벤트가 누적됐고 새로고침 시 완료된 분석과 스크롤이 사라졌다.
- 분석 모델의 이벤트 배열을 매 틱 비워 긴 전투의 임시 이벤트 누적을 막는다. 모델 상태·전투 집계·점수 계산은 유지한다.
- 선택 창이 열린 동안 완료된 분석 요약만 보관하고 새로고침 후 파일 지문이 같은 카드에 즉시 복원한다. 모든 전투를 자동 재분석하지 않는다.
- 삭제·변경된 파일의 요약은 폐기한다. 원본 재확인·내용 지문 비교를 유지하며 리플레이·모델·화면 노드는 분석 요약에 넣지 않는다.
- 새로고침 전 스크롤과 초점의 파일 경로·버튼 종류를 기억해 배치 후 복원한다. 대상이 사라지면 목록으로 초점을 돌린다.
- 화면과 부모의 삭제 예약까지 확인해 중단된 분석과 지연 복원이 새 화면에 결과를 쓰지 않게 한다. 고정 하단 버튼·Tab·Esc·키보드 스크롤을 유지한다.
- 도전 시작 안내의 최고 점수를 낸 전투 시간·실패 전투 시간 표시를 확인했다. 분석으로 기록·파일·순위표를 변경하거나 서버로 전송하지 않는다.
- README를 갱신하고 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 소스 차이·콜백 연결·취소 수명·파일 지문·캐시 정리·초점 복원을 읽어 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 실제 로드·표시·조작 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식을 유지한다. 버전 번호·release.json·CHANGELOG·PatchNotes는 수정하지 않았고 Git 명령은 실행하지 않았다.
- 다음 후보: 사본 복구 전후 도전 기록의 날짜·버전별 상세 비교, 최근 온라인 전투 목록 새로고침 중 개별 보기 요청 상태 안내, 도전 보관 전투 재생 후 분석 카드로 바로 복귀하는 흐름.


## 2026-10-13 — 최근 온라인 전투 재생 후 목록·선택 카드 복귀

- 이번 주제: 최근 온라인 전투를 본 뒤 검색 조건·스크롤·선택 카드 초점을 유지한 목록으로 바로 돌아온다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 해시와 HEAD·인덱스 루트 트리를 비교했다. 미커밋 소스·문서 변경은 없었고 기존 Python 캐시만 있었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고, 남아 있던 최근 온라인 전투 재생 후 목록 복귀를 선택했다.
- 확인한 문제: 최근 공개 전투를 재생한 뒤 나가면 로컬 보관함으로 이동해 목록을 다시 열고 서버 응답을 기다려야 했다.
- 최근 온라인 전투의 보기 → 나가기를 원래 공개 목록으로 연결했다. 재생 전에 조회한 카드 순서를 그대로 복원한다.
- 검색어·종류·결과·스크롤을 유지하고 재생한 코드의 보기 버튼으로 키보드 초점을 돌린다.
- 성공적으로 받은 목록과 조회 시각만 Main의 세션 상태에 보관한다. 빈 목록도 정상 응답이면 반영한다.
- 보관 데이터는 응답 요약의 깊은 복사이며 화면 노드·다운로드한 리플레이·재생기를 저장하지 않는다.

- 명시적인 새로고침은 기존 요청 수명·중복 전송 보호를 사용하고 성공 응답으로 세션 목록을 교체한다.
- 새로고침 실패 시 기존 카드·검색 조건을 유지한다. 정리된 코드의 보기 실패 안내와 재시도도 유지한다.
- 선택 카드가 보이지 않으면 목록으로 초점을 돌린다. 화면 수명·복원 순번을 확인해 늦은 위치 복원이 새 화면을 건드리지 않게 한다.
- 복귀한 목록을 닫으면 새 로컬 보관함의 최근 온라인 전투 진입 버튼으로 초점을 돌린다.

- 로컬 보관·메모 자동 저장·미저장 메모 확인·여기서 해보기는 기존 재생기 흐름을 사용한다.

## 2026-10-13 — 최근 온라인 전투 검색·결과 필터

- 이번 주제: 최근 온라인 전투를 보관 날짜·공유 코드·병력 이름과 결과로 빠르게 찾고 새로고침 때 탐색 상태를 유지한다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 해시와 HEAD·인덱스 루트 트리를 비교해 미커밋 변경이 없음을 확인했다. 최근 3회차와 아카이브의 다음 후보에서 날짜·덱·결과 탐색을 선택했다.
- 확인한 문제: 최신 공개 전투를 카드마다 읽어야 했고 특정 날짜·병력·승리 진영의 전투를 좁힐 수 없었다.
- 검색 입력과 빠른 대전/방 대전 종류 필터, 블루 승/레드 승/무승부 결과 필터를 추가했다.
- 공유 코드·양쪽 병력의 게임 내 이름과 영문 ID·전투 종류·결과·전투 시간을 검색한다.
- UTC 보관 날짜는 YYYY-MM-DD와 YYYYMMDD를 모두 지원한다. 추정 시각도 포함하고 미상은 미상으로 검색하며 코드나 전투 길이로 날짜를 추정하지 않는다.
- 공백으로 나눈 검색어가 모두 포함된 카드만 표시한다. 코드·영문 ID는 대소문자를 구분하지 않는다.
- 검색 대상이 조회된 최근 공개 목록임을 안내한다. 더 오래된 보관 전투까지 검색한다고 오인하지 않도록 개수 툴팁과 빈 결과 안내를 제공한다.
- 표시 개수/조회 개수를 표시하고, 서버의 빈 목록과 검색 조건의 빈 결과를 구분한다. 초기화로 전체 목록을 다시 볼 수 있다.
- 조회 시 검색 문자열을 한 번 만들고 입력마다 카드 표시 여부만 바꾼다. 검색 때문에 추가 요청·다운로드·카드 재생성을 하지 않는다.
- 검색·종류·결과·스크롤은 Main의 세션 메모리에만 저장한다. 새로고침·창 재진입 때 유지하고 게임 종료 시 초기화한다.
- 첫 응답을 기다리는 빈 화면이 저장된 스크롤을 0으로 덮지 않도록 수신 완료 이후에만 위치를 갱신한다.
