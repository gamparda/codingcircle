# 프로젝트 개선 기록

## 2026-10-13 — 진행도 사본 내보내기와 가져오기

- 이번 주제: 진행도 사본을 클립보드로 내보내고, 외부 JSON 사본을 미리 확인해 보관·복구하는 흐름을 추가한다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 내용 해시와 압축된 HEAD 객체의 트리를 읽었다. 작업 시작 전 미완료 변경·새 소스·문서는 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고, 남아 있던 진행도 사본의 내보내기·가져오기 흐름을 선택했다.
- 확인한 문제: 사본을 다른 기기에 옮기거나 재설치 전에 보관하려면 저장 폴더를 직접 찾아 복사해야 했고, 외부 사본을 앱에서 확인해 가져오는 기능이 없었다.
- 진행도 보관·복구 화면에 현재 진행도 내보내기와 선택한 사본 내보내기를 추가했다. 기존 진행도 JSON을 클립보드에 복사한다.
- 내보내기는 익명 설치 ID·결과 순번·전송 대기 기록을 비워 다른 기기로 전송 대기열을 옮기지 않는다. 원래 진행도와 로컬 사본은 수정하지 않는다.
- 선택한 사본은 내용을 다시 읽고 목록의 지문과 비교한다. 읽기 실패·내용 변경 시 내보내기를 중단하고 새로고침을 안내한다.
- 복사 후 클립보드 내용을 확인하고, 게임 밖의 .json 파일로 별도 저장해야 함을 안내한다. 클립보드 미지원·복사 실패도 표시한다.
- 클립보드 사본 가져오기는 닉네임·별·전적·도전 기록 수를 현재 진행도와 비교한 뒤 사본만 보관한다. 실제 진행도 복구는 기존 별도 확인을 거친다.
- 미리 확인한 입력 문자열을 보관하므로 확인 중 클립보드가 바뀌어도 다른 사본을 가져오지 않는다. 취소·검증 실패는 파일을 쓰지 않는다.
- 빈 내용·잘린 JSON·비프로필 자료·새로운 저장 형식·UTF-8 기준 2 MiB 초과 입력을 거절한다. UTF-8 BOM이 있는 사본도 원본 바이트를 유지하며 읽는다.
- 잘못된 도전 기록의 제외 수를 가져오기 미리보기·사본 선택·복구 확인에 표시한다. 가져온 JSON 원본은 정규화하지 않고 기존 복구 폴더에 보관한다.
- 같은 원본은 기존 내용 지문 보관 정책으로 재사용한다. 보관 실패 시 확인 화면에 재시도 안내를 남기고 현재 진행도를 유지한다.
- 보관·가져오기 완료 시 해당 사본을 선택한다. 새로고침도 선택을 유지해 기존 사본 재사용이나 목록 정렬로 다른 사본을 복구하지 않도록 했다.
- 데스크톱에 보관 폴더 열기를 추가했다. 기존 사본·손상 원본을 직접 다른 위치에 복사할 수 있고 폴더 접근 실패를 안내한다.
- 가져오기·복구 확인 창의 본문 스크롤, Esc 취소, 닫은 뒤 초점 복원, 내부 키보드 초점 순환과 터치 최소 버튼 높이를 적용했다.
- README에 게임 밖 보관·가져오기 절차와 리플레이 별도 이동을 설명했다. 이전 1회차는 아카이브로 옮겨 최근 3회차만 남겼다.
- 검토: 기존 원본 보관·원자적 저장·복구의 기기 설정/ID/대기열 유지 정책과 새 조회·입력·화면 연결을 소스로 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 수행하지 않았다. 클립보드·터치·실행 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. 기존 세이브 필드·형식 번호·RPC 시그니처·서버 파일 형식을 유지한다. 버전·release.json·CHANGELOG·PatchNotes는 수정하지 않았고 Git 명령은 실행하지 않았다.
- 다음 후보: 리플레이 병력 기여도의 선택 구간 비교, 도전 기록의 성공/실패 필터, 많은 진행도 사본의 검색·정리 흐름.

## 2026-10-13 — 도전 기록 복원의 날짜·완료 시간 검증

- 이번 주제: 손상된 날짜·완료 시간이 정상 도전 기록을 밀어내거나 0초 최고 기록으로 복원되지 않도록 검증하고, 유효한 이전 버전 기록을 보존한다.
- 시작 상태: Git 명령 없이 인덱스와 추적 파일의 내용 해시, HEAD와 인덱스의 루트 트리를 비교했다. 미완료 소스·문서 변경은 없었고 무시 대상 Python 캐시만 있었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고, 남아 있던 도전 기록의 날짜·완료 시간 로드 검증을 선택했다.
- 확인한 문제: 날짜를 정렬·제한한 뒤 검사해 손상된 날짜가 정상 기록을 밀어낼 수 있었다. 없는 달·날짜와 월요일이 아닌 주간 키도 허용했다.
- 일일 기록은 실제 달력 날짜, 주간 기록은 실제 월요일인지 기존 서버 날짜 검증으로 확인한다. 문자열이 아닌 키도 정렬 전에 제외한다.
- 유효한 날짜와 기록을 먼저 모은 뒤 최근 일일 60일·주간 16주만 남긴다. 손상된 항목은 보관 한도를 소비하지 않는다.
- 성공 여부·점수·완료 시간의 자료형을 검사한다. 성공은 기존 점수 범위 100~3000점, 실패는 기존 규칙대로 0점만 허용한다.
- 누락·음수·무한대·숫자가 아닌 완료 시간을 0초로 바꾸거나 상한값으로 보정하지 않고 해당 버전 기록을 제외한다.
- 실제 0초는 허용하고, 시간 제한이 없는 로컬 전투의 유한한 긴 완료 시간은 자르지 않는다. 서버 제출 시간 한도는 그대로다.
- 주 기록이 손상되어도 유효한 이전 버전 기록을 독립적으로 검증해 살린다. 결정적인 버전 순서로 대표 기록을 골라 기존 저장 구조를 유지한다.
- 이전 기록의 버전은 해당 history 키를 사용하며, 과거 점수를 현재 버전의 최고 기록으로 바꾸지 않는다. 유효한 대표 기록은 같은 버전의 중복보다 우선한다.
- 로드 시 제외한 항목 수를 기존 저장 경고 화면에 안내한다. 전적·덱·설정 등 정상 진행도와 유효한 성공 이력은 유지한다.
- 제외가 있으면 디스크 원본 바이트를 기존 복구 폴더에 보관한다. 보관 실패 시 원본 보호 플래그와 저장 재시도 흐름으로 자동 덮어쓰기를 막는다.
- 도전 시작 안내에 최고 점수를 낸 전투의 시간을 추가했다. 실패 기록은 실패한 전투의 시간으로 별도 안내한다.
- 개인 기록 본문과 시간 툴팁에 최고 점수와 완료 시간의 관계, 동점이면 빠른 성공 기록을 남기는 규칙을 설명한다.
- README를 갱신하고 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다.
- 검토: 생성되는 정상 기록, 버전별 조회·연속 성공·재도전, 원본 보관 실패·저장 재시도·경고 표시 연결을 소스로 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 수행하지 않았다. 기존 손상 시간을 0초로 정규화하는 테스트 기대는 새 제외 정책과 다르므로 외부 검증에서 검토해야 한다.
- 호환성 변경: 없음. 기존 세이브 필드·형식 번호·RPC 시그니처·서버 파일 형식을 유지한다. 손상된 도전 항목의 로드 정책만 강화했다. 버전·release.json·CHANGELOG·PatchNotes는 수정하지 않았고 Git 명령은 실행하지 않았다.
- 다음 후보: 진행도 사본의 내보내기·관리 흐름, 리플레이 병력 기여도의 선택 구간 비교, 도전 기록에서 실패 이력·성공 이력을 빠르게 필터링하는 흐름.

## 2026-10-13 — 리플레이 시점별 전투 요약과 병력 기여도 비교

- 이번 주제: 리플레이의 원하는 시점과 종료 화면에서 누적 전투 집계·병력별 기여도를 확인하고, 요약을 닫으면 이전 재생 상태로 복귀한다.
- 시작 상태: Git 명령 없이 인덱스와 추적 파일 내용 해시, 압축된 HEAD 객체와 인덱스 루트 트리를 읽어 비교했다. 미완료 변경이나 새 소스·문서 파일은 없었다.

- 확인한 문제: 리플레이는 승패 배너만 표시하며, 결과 화면에서 제공하는 병력별 기여도를 다시 확인할 수 없었다.
