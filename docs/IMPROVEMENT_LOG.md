# 프로젝트 개선 기록

## 2026-10-13 — 공유 코드 조회 실패 복구 안내와 로컬 보관 경로

- 이번 주제: 공유 코드 조회 실패 원인을 구분하고 서버 보관 정책·로컬 경로·보관함 탐색을 연결하는 도움말을 구현한다.
- 시작 상태: Git 명령 없이 인덱스와 추적 파일의 해시를 비교했다. 작업 트리의 미완료 변경과 미추적 소스·문서는 없었다. 팩 객체를 직접 읽어 HEAD·인덱스 루트 트리도 일치함을 확인했다.
- 최근 3회차·아카이브의 다음 후보를 읽고 남아 있던 코드 실패 복구 안내를 선택했다. 소스 수정 전에 주제를 로그에 먼저 기록했다.
- 확인한 문제: 코드 조회 실패는 찾을 수 없다는 안내뿐이어서 서버 보관 한계·다른 서버 접속·로컬 사본을 확인할 방법을 알기 어려웠다.
- 빈 응답과 읽을 수 없는 응답을 구분하는 공통 안내를 만들고 코드 입력·최근 온라인 전투의 두 조회 경로에 적용했다.
- 빈 응답을 만료·삭제로 단정하지 않는다. 코드·발급 서버 확인과 이미 저장한 전투 찾기를 안내한다.
- 코드 창에 보관·복구 도움말을, 로컬 리플레이 보관함의 검색 행에 보관 안내를 추가했다.
- 서버의 공유 코드·공개 전투 합산 최근 200개와 공개 목록 최대 20개, 고정 만료 시간 없음, 조회가 보관 순서를 갱신하지 않음을 설명한다.
- 코드로 재생만 한 전투와 로컬 보관·메모 저장에 성공한 전투를 구분해 이 기기에 남는 조건을 안내한다.
- BattleReplay.save_dir의 실제 기기 경로를 표시하고 읽기 전용 선택·경로 복사를 제공한다. 클립보드 미지원 환경에서는 복사 버튼을 잠근다.
- 도움말 진입으로 폴더를 만들거나 서버 요청·저장·자동 정리를 실행하지 않는다. 저장 전 폴더 부재와 모바일 앱 폴더 접근 제한을 안내한다.
- 보관함에서 찾기는 명시적으로 모든 검색·필터·스크롤을 초기화하고 전체 목록의 검색칸으로 초점을 옮긴다. 서버 접속은 하지 않는다.
- 로컬도 최근 50개를 유지하므로 중요한 전투의 텍스트·JSON 사본 보관을 안내한다. 경로 복사가 파일 백업을 뜻하지 않음을 설명한다.
- 사본이 없는 경우 보낸 사람에게 리플레이 텍스트를 받아 기존 클립보드 가져오기로 저장하는 경로를 안내한다.
- 도움말에서 돌아오면 코드 입력·오류 안내와 기존 진입 버튼의 약한 참조를 복원한다. 보관함에서 연 도움말은 검색 조건·스크롤을 유지한다.
- 요청 중에는 도움말을 잠그며 취소·실패 후 복원한다. 기존 중복 요청 방지·늦은 응답 보호·취소·재생 복귀 동작을 유지한다.
- 도움말에 줄바꿈·세로 스크롤·Tab 순환·Esc 복귀·방향키와 Page Up/Down·Home/End·터치 높이 58을 적용했다. 코드 창을 넓혀 실패 안내 공간을 확보했다.
- README를 갱신하고 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 소스로 응답 분기·콜백 인자·화면 수명·초점·쓰기 범위를 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 실제 로드·표시·조작 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식을 유지한다. 버전 번호·release.json·CHANGELOG·PatchNotes는 수정하지 않았고 Git 명령은 실행하지 않았다.
- 다음 후보: 리플레이 보관함의 삭제 확인과 실수 방지, 복구 사본의 덱별 변경을 한눈에 고르는 흐름, 도전 보관 전투에서 덱 구성 클릭으로 검색 조건을 지정하는 흐름.

## 2026-10-13 — 도전 보관 전투의 내 덱·상대 덱 개별 검색

- 이번 주제: 도전 보관 전투에서 내 덱과 상대 덱의 병력·구조물 조건을 각각 검색하고, 재생 후 복귀·새로고침에도 조건을 유지한다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 해시와 HEAD·인덱스 루트 트리를 비교했다. 미커밋 변경과 미추적 소스·문서는 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고 남아 있던 덱별 검색을 선택했다. 소스 수정 전에 이번 주제를 로그에 기록했다.
- 확인한 문제: 기존 검색은 양쪽 덱을 합쳐 검사해 내 덱의 병력과 상대 덱의 병력을 구분한 대결 구성을 찾을 수 없었다.
- 내 덱 (블루)·상대 덱 (레드)의 검색칸을 추가했다. 각 진영의 저장된 출전 병력·구조물 한글 이름과 영문 ID만 검색한다.
- 예를 들어 내 덱의 탱커·포탑과 상대 덱의 궁수·방벽을 동시에 지정해 원하는 대결 구성을 찾을 수 있다.
- 각 칸은 대소문자를 구분하지 않고 공백으로 나눈 검색어를 모두 포함해야 한다. 빈 검색칸은 제한하지 않는다.
- 덱별 검색에 파일명·클립 제목·버전·상대 진영의 병력을 섞지 않는다. 현재 덱이나 오늘의 도전으로 저장 덱을 대체하지 않는다.
- 기존 양쪽 덱·파일·클립 검색을 전체 검색으로 안내하고 유지한다. 전체 검색·두 덱 조건·결과·클립 필터를 함께 적용한다.
- 진영별 검색 텍스트를 진입·새로고침 때 한 번 만들고 전체 검색에도 재사용한다. 입력마다 파일 조회·리소스 로드·전투 분석을 하지 않는다.
- 세 검색칸을 재생 후 복귀·새로고침의 기존 상태 사전에 보존한다. 완료된 분석·스크롤·선택 카드 초점 복원도 유지한다.
- 초기화는 세 검색칸과 결과·클립 필터를 모두 해제한다. 덱별 검색만 사용해도 초기화 버튼을 활성화한다.
- 결과 없음 안내에 진영 기준과 조건 해제 방법을 명시한다. 전체·그룹별 표시 개수와 최신 보관순은 기존 동작을 유지한다.
- 새 검색칸을 기존 Tab 순환·Esc 닫기·초점 복원에 포함한다. 숨겨진 카드의 진행 중인 분석 취소와 완료된 분석 재사용을 유지한다.
- 검색칸에 진영 이름·색상·입력 예시·지우기 조작과 터치 최소 높이 58을 적용했다. 기존 필터 행에 넣어 목록의 세로 공간을 유지한다.
- 재생·분석 직전 파일 재확인·지문 비교와 날짜·버전의 후보 제한은 유지한다. 기록·파일·순위표에는 쓰지 않는다.
- README에 실제 검색 방법과 조건 결합·복원·초기화를 안내했다. 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 소스의 검색 범위·상태·초점·화면 수명을 검토했으며 실제 로드·표시·조작 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식을 유지한다. 버전 번호·release.json·CHANGELOG·PatchNotes는 수정하지 않았고 Git 명령은 실행하지 않았다.
- 다음 후보: 공유 코드를 서버에서 찾지 못했을 때 보관 정책과 로컬 보관 경로 안내, 복구 사본의 덱별 변경을 한눈에 고르는 흐름, 도전 보관 전투에서 덱 구성 클릭으로 검색 조건을 지정하는 흐름.

## 2026-10-13 — 진행도 복구 전 닉네임·새 기능 확인 상태 비교

- 이번 주제: 진행도 사본 선택·가져오기·복구 확인에서 닉네임과 새 기능별 확인 상태 변화를 미리 안내한다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 해시와 HEAD·인덱스 루트 트리를 비교했다. 미커밋 변경과 미추적 파일은 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고 아직 남아 있던 복구 시 프로필·새 기능 상태 비교를 선택했다. 소스 수정 전에 주제를 로그에 기록했다.
- 확인한 문제: 복구는 닉네임과 seen_features도 사본 값으로 되돌리지만 기존 상세 비교에는 이 변화가 없었다.
- 프로필 항목에 현재 → 사본 닉네임을 표시하고 이름이 달라지는 경우 상단에서 경고한다. 같은 이름은 변경 없음으로 안내한다.
- 복구 후 멀티플레이의 닉네임 입력에 사본 이름이 표시되고 다시 수정할 수 있음을 설명한다. 서버에 보관된 기록은 복구 대상이 아님을 안내한다.
- 현재 새 기능 안내 목록의 각 기능을 확인함·미확인으로 비교한다. 다시 미확인이 되는 기능 이름을 먼저 표시하고 경고한다.
- 총 미확인 수가 같거나 줄어도 기존 확인 기록의 변화를 따로 표시한다. 다른 기능의 확인 증가로 상쇄하지 않는다.
- 확인함으로 바뀌는 기능과 상태 유지 개수도 표시하며, 변화가 없는 사본은 변경 없음으로 안내한다.

- 미확인 개수 변화와 모든 기능 확인 여부에 따라 새 기능 버튼이 다시 표시되거나 숨겨지는 동작을 설명한다.
- 메뉴별 NEW 변화는 같은 메뉴로 연결된 모든 기능을 함께 판정한다. 리플레이 기능 하나가 미확인이면 해당 메뉴의 NEW를 유지하는 기준을 따른다.
- 과거 기능 ID와 확인 배열의 순서는 현재 안내 개수·NEW 판정에서 제외한다. 과거 ID는 사본 내용대로 복구됨을 설명한다.
- 확인 상태는 기능의 잠금이나 전투 진행도와 별개임을 안내해 미확인으로 복구되는 의미를 분명히 한다.
- 공통 비교에 연결해 사본 선택·클립보드 가져오기·최종 복구 확인에서 같은 내용을 보여 준다. 복구 범위 안내에도 닉네임·새 기능 상태를 명시한다.
- 기존 줄바꿈·세로 스크롤과 경고색을 사용한다. 새 버튼·초점 정지점은 추가하지 않아 기존 Tab·Esc·스크롤 조작을 유지한다.
