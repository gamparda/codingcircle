# 프로젝트 개선 기록

## 2026-10-14 — 리플레이 진입 전세 분석 분산과 중단

- 이번 주제: 재생 화면을 먼저 열고 전세 그래프·하이라이트 분석을 프레임마다 나누어 긴 리플레이의 진입 지연과 화면 이탈 후 불필요한 계산을 줄인다.
- 시작 상태: Git 명령 없이 인덱스·작업 파일의 원본/LF 해시, 인덱스에서 재구성한 트리와 HEAD 트리를 대조했다. 미커밋·스테이징 변경·충돌·미추적 소스가 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 주제·다음 후보를 읽고 남아 있던 재생 진입 전세 분석을 선택했다. 소스 수정 전에 이번 주제를 UTF-8 패치로 먼저 기록했다.
- 확인한 불편: ReplayViewer.open이 전체 전투를 동기 재계산한 뒤 화면을 만들어 긴 리플레이는 재생·일시정지·나가기조차 분석 완료까지 기다려야 했다.
- 화면·초기 장면·시간 막대를 먼저 만들고 독립된 무음 분석 작업을 화면의 처리 프레임에서 진행하도록 바꿨다. 별도 스레드·대기 콜백은 만들지 않는다.
- 분석은 프레임당 최대 512틱 또는 약 4ms 예산으로 나눈다. 검증·플레이어 초기화는 별도 프레임에 처리하며 단일 틱·초기화·마지막 정렬 비용은 4ms를 넘을 수 있다.
- 기존 동기 ReplayAnalysis.analyze의 인자·반환 형식은 유지하고 같은 분산 작업을 끝까지 실행한다. 전세 계산 가중치·샘플 간격·교전 판정·기지 이정표·주요 순간 제한은 유지한다.
- 분석 전용 전투 모델과 재생 모델을 분리한다. 부분 곡선·하이라이트는 공개하지 않고 마지막 정렬·간격 정리를 마친 뒤 한 번에 그래프와 탐색 목록에 반영한다.
- 분석용 이벤트는 매 틱 읽고 즉시 비우며 사용하지 않을 전체 이벤트 깊은 복사를 없앴다. 실제 재생의 효과음·애니메이션 이벤트 처리는 유지한다.
- 진행 패널에 분석한 시각·기록 시각·진행률과 분석 중지 버튼을 표시한다. 진행률은 기록 틱 수를 기준으로 하며 완료 전에는 최대 99%로 표시한다.
- 분석 중지·다시 분석은 계산 작업만 버리거나 처음부터 준비한다. 현재 장면·재생/정지·배속·메모·선택 구간·로컬 보관 상태는 바꾸지 않는다.
- 시간 막대·그래프·방향키·클립 시작·구간 반복의 시점 탐색을 우선한다. 탐색 중에는 전세 분석을 진행하지 않으며 탐색 완료·취소 이후 남은 분석을 이어 간다.
- 분석 전의 빈 그래프도 기록된 전체 길이를 사용하여 올바른 시점으로 이동한다. 메모 표시·선택 구간·재생 위치는 분석 결과를 적용할 때 그대로 유지한다.
- 이전/다음 순간 버튼은 분석 완료까지 잠그고 N/P·직접 함수 호출에도 안내를 넣는다. 시간 막대·방향키 이동과 처음부터는 계속 사용할 수 있다.
- 분석 전 주변 클립 복사는 현재 장면을 기준으로 하고 안내에도 명시한다. 완료 후에는 기존 가까운 주요 순간을 사용하며 지정한 시작·끝 구간 복사는 그대로 유지한다.
- 완료 시 진행 패널을 숨기고 주요 순간 조작을 연다. 숨긴 분석 버튼에 초점이 있었다면 시간 막대로 옮기며 지난 하이라이트를 뒤늦게 알리지 않는다.
- 실제 나가기·메모 폐기 확인 후 나가기·직접 플레이 진입·트리 이탈·삭제 대기에서 남은 분석 참조를 버린다. 메모 폐기 확인을 취소하면 같은 화면의 작업을 유지한다.
- README 사용법을 반영하고 가장 오래된 회차를 아카이브로 옮겨 최근 3회차만 남겼다. 소스로 초기화·계산 경계·탐색 우선순위·취소·메모·구간·초점·화면 수명 경로를 검토했다.
- 테스트 추가·수정·실행과 게임 실행·렌더링은 하지 않았다. 실제 로드·긴 전투·동기/분산 결과 일치·중지/재시작·클립·키보드·화면 이탈 검증은 외부 스크립트에 맡긴다. 즉시 하이라이트를 기대하는 기존 검증은 완료 대기가 필요하다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식과 버전 번호·release.json·CHANGELOG·PatchNotes를 유지했다. Git 명령은 실행하지 않았다.
- 다음 후보: 도전 보관 전투의 페이지별 카드 제한, 복구 비교에서 특정 감소 경고의 상세로 바로 이동하는 흐름, 긴 리플레이 그래프의 화면 폭에 맞춘 그리기 비용 제한.

## 2026-10-14 — 긴 리플레이 시점 탐색 분산과 취소

- 이번 주제: 리플레이 시점 탐색을 프레임마다 나누고 진행 표시·취소·새 탐색으로 교체하여 긴 전투에서도 입력을 유지한다.
- 시작 상태: Git 명령 없이 인덱스와 작업 파일의 원본/LF 해시, 인덱스에서 재구성한 트리와 HEAD 트리 해시를 대조했다. 미커밋·스테이징 변경·충돌·미추적 소스가 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 주제·다음 후보를 읽고 긴 리플레이 탐색을 선택했다. 소스 수정 전에 이번 주제를 UTF-8로 먼저 기록했다.
- 확인한 불편: 시간 막대·전세 그래프·하이라이트 이동·구간 반복은 목표 시점까지 전투를 한 번에 다시 계산하여 긴 전투에서 입력과 화면 처리를 막았다.
- 화면 조작은 탐색 요청으로 전환하고 재시뮬레이션을 프레임당 최대 512틱·약 4ms 예산으로 나눴다. 한 틱과 초기화·최종 스냅샷 비용은 예산을 넘을 수 있어 4ms를 보장 시간으로 취급하지 않는다.
- 계산 전용 플레이어와 마지막 완성 장면의 플레이어를 분리한다. 목표 도달 또는 실제 전투 종료 때 한 번만 교체하며 부분 계산 상태를 메모·요약·직접 플레이에 전달하지 않는다.
- 탐색 중 목표 시각·계산 시각·진행률과 이전 장면 표시를 안내한다. 장면 애니메이션과 효과음을 멈추고 시간 막대·그래프에는 선택한 목표를 표시한다.
- 탐색 취소 버튼과 Esc는 계산 중인 플레이어만 버리고 이전 장면·시간 막대·그래프를 복원해 일시정지한다. 되돌리기 위해 다시 시뮬레이션하지 않는다.
- 연속 드래그는 다음 프레임의 최신 목표 하나로 합친다. 새 목표가 계산 시점보다 뒤라면 진행한 계산을 이어 쓰고, 앞이라면 다음 프레임에 다시 시작한다.
- 연속 방향키·이전/다음 순간은 계산 중인 목표를 기준으로 이동한다. 방향키 5초와 하이라이트 1초 전 도착은 저장된 주파수를 사용해 30Hz 외의 리플레이도 맞춘다.
- 탐색 중 메모 추가·삭제, 시작·끝 지정, 반복 전환, 클립 복사, 요약, 여기서 해보기를 버튼과 함수 양쪽에서 잠근다. 입력 중 메모 문구와 기존 구간 집계는 유지한다.
- 재생·일시정지 선택, 배속, 로컬 보관, 구간 해제, 처음부터, 나가기는 계속 사용할 수 있다. 완료 후 선택한 재생 상태를 유지하고 취소 버튼의 초점은 시간 막대로 옮긴다.
- 클립 시작 이동·처음부터의 클립 복귀·자동 구간 반복도 같은 분산 경로를 사용한다. 클립 끝 정지와 누적·선택 구간 요약, 생존 병력 비교의 기존 규칙은 유지한다.
- 탐색 중 연출 이벤트는 매 틱 바로 비워 전체 이동 구간을 누적하거나 버릴 이벤트를 깊은 복사하지 않는다. 실제 전투·일반 재생의 이벤트 처리와 전투 규칙은 바꾸지 않는다.
- 화면 이탈·삭제 대기·나가기는 남은 계산을 버린다. 별도 스레드·지연 콜백 없이 화면의 처리 프레임에서만 계산하여 이전 화면의 결과가 나중에 반영되지 않는다.
- 기존 동기 seek와 인자 없는 재시작·하이라이트 함수 호출은 유지하고 실제 버튼·키보드·그래프 경로만 분산 처리한다. 재생 진입 시 전세 분석은 기존 동기 방식으로 남아 다음 개선 후보로 기록한다.
- README에 사용법을 반영하고 가장 오래된 회차를 아카이브로 옮겨 최근 3회차만 남겼다. 로그 정리 중 PowerShell 파이프가 손상시킨 이번 회차 문구는 UTF-8 패치로 복구했다. 소스로 탐색·취소·정지·클립·반복·메모·요약·화면 수명 경로를 검토했다.
- 테스트 추가·수정·실행과 게임 실행·렌더링은 하지 않았다. 실제 로드·긴 전투·진행률·키보드·터치·취소·클립·구간 반복 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식과 버전 번호·release.json·CHANGELOG·PatchNotes를 유지했다. Git 명령은 실행하지 않았다.

## 2026-10-14 — 리플레이 시점별 생존 병력과 역할 구성 비교

- 이번 주제: 리플레이 전투 요약에서 현재 시점의 양쪽 생존 병력·역할 구성과 선택 구간 시작 대비 증감을 확인한다.
- 시작 상태: Git 명령 없이 인덱스·작업 파일의 원본/LF 해시와 인덱스 트리·HEAD 트리를 대조했다. 미커밋·스테이징 변경·충돌·미추적 소스가 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 주제·다음 후보를 읽고 리플레이 시점별 역할 구성 비교를 선택했다. 소스 수정 전에 이번 주제를 UTF-8로 먼저 기록했다.
- 확인한 불편: 리플레이 요약은 누적 생산·피해·처치를 보여 주지만 장면에 살아 있는 병력과 구간 전후 구성을 직접 비교할 수 없었다.
- 전투 요약에 피해·처치 / 생존 병력 보기를 추가했다. 기존 피해·처치 보기를 기본으로 유지하며 같은 리플레이에서는 마지막 보기 선택을 기억한다.
- 현재 시점은 요약을 연 장면의 블루·레드 생존 수·소환 수·역할 구성·종류별 수를 나란히 표시한다.
- 역할은 실시간 병력 현황과 같은 근접 전열·원거리 공격·공속 지원·소환 지휘를 사용한다. 분류 정의를 공통 객체로 옮겨 두 화면의 기준을 맞췄다.
- 해골은 근접 전열에 포함하고 종류별 수에서는 따로 표시한다. 네크로맨서와 중복 집계하지 않으며 사망 후 정리 대기 병력·구조물은 제외한다.
- 역할별 비율과 막대는 자기 진영 전체 생존 인원이 분모다. 생존 수가 0이면 비율 —·빈 막대로 표시하며 0으로 나누지 않는다.
- 시작 [ · 끝 ] 지정을 할 때 작은 생존 수 집계를 함께 보관한다. 실제 유닛 참조·전체 스냅샷을 저장하거나 구간 조회를 위해 다시 시뮬레이션하지 않는다.
- 선택 구간에서는 끝 장면의 생존 구성과 총원·소환·역할·종류별 시작→끝 (순증감)을 표시한다. 재생 위치를 옮겨도 지정한 두 시점을 비교한다.
- 순증감은 생산·소환·사망이 합쳐진 값이며 처치 수·전투력·승률이 아님을 안내한다. 역할별 비율은 구간 끝의 생존 구성 기준이다.
- 시작점을 끝 이후로 옮기면 끝의 비교 집계도 지우고, 구간 해제·새 리플레이 열기에서는 시작·끝 집계를 초기화한다.
- 요약을 열 때 현재·시작·끝 집계를 고정한다. 보기·범위 전환이 이후 재생 상태를 참조하지 않으며 범위별 제목·안내도 함께 바꾼다.
