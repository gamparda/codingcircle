# 프로젝트 개선 기록

## 2026-10-11 — 공유 리플레이 코드의 내용 기준 재사용과 도전 기록 조회

### 이전 작업 확인

- 앞선 11회차의 저장 보호·전송 확인·버전 분리·리플레이 보관 순서·서버 용량 진단을 확인했다. 작업 시작 시 Git 작업 트리는 깨끗했다.
- 남은 후보인 공유 코드 동일성을 조사했다. 서버가 압축된 공유 문자열을 해시하므로 같은 리플레이도 JSON 저장·로드 후 정수/실수 표현이 바뀌거나 JSON 들여쓰기·키 순서가 달라지면 새 코드를 발급했다. 기존 테스트에 두 재현 검사를 넣어 수정 전에 두 실패를 확인했다.
- 보존한 이전 버전 도전 최고 기록은 사용자 화면에서 조회할 수 없었다. 기존 버전 분리·기록 보관을 다시 구현하지 않고 공유 식별과 전적 조회 기능을 보완했다.

### 구현한 개선

1. **내용이 같은 공유 리플레이의 코드 재사용**
   - 공유 텍스트를 검증·파싱한 뒤 정렬된 JSON 키와 숫자의 전체 정밀도를 사용해 내용 해시를 계산한다. 기기 저장·로드, JSON 표현·키 순서·압축 표현의 차이로 보관함에 중복 항목을 추가하지 않는다.
   - 메모·클립·전투 수치·메타데이터는 내용의 일부로 유지한다. 다른 메모나 클립을 공유하면 별도 코드를 받으며 기존 공유 내용을 바꾸지 않는다. 로컬 보관 순번은 기존 파서의 제외 정책을 유지한다.
   - 서버 재시작 때도 같은 내용 해시를 재구성한다. 기존의 여러 코드가 같은 내용을 가리키면 모든 코드·원본 파일·공개 여부를 유지하고 새 요청은 가장 오래된 보관 코드를 재사용한다. 그 항목이 정상 보관 정책으로 삭제되면 남은 동일 내용 코드로 인덱스를 연결한다.
   - 디스크 저장 완료 후 발급·공개 전환, 삭제 실패 재시도와 200개 보관 정책은 유지했다. 기존 파일을 일괄 다시 쓰거나 코드 자체를 변경하지 않는다. 코드가 보관함에서 모두 제거된 뒤의 재업로드에는 기존처럼 새 코드가 생길 수 있다.

2. **개인 전적에서 일일·주간 도전의 버전별 최고 기록 조회**
   - 기존 캠페인 표 옆에 일일·주간 도전 탭을 추가했다. UTC 날짜, 콘텐츠 버전, 성공 여부, 최고 점수와 완료 시간을 보여 준다. 주간 날짜는 저장된 주 시작일이며 서버 순위표와 구분되는 기기 최고 기록임을 안내한다.
   - 날짜는 최신순, 같은 날짜에서는 현재 버전을 먼저 표시한다. 현재 기록이 `previous`에 보관되어 있어도 조회하며, 이전·미상 버전과 실패·0초 기록도 별도로 표시한다. 서로 다른 버전의 점수를 합치거나 비교하지 않는다.
   - 전체·현재·이전/미상 버전 필터와 빈 결과 안내를 추가했다. 조회용 사본을 사용해 화면 조작이 진행도나 전송 대기열을 변경하지 않는다.
   - 목록에 스크롤을 추가하고 업적·메인 화면 버튼을 하단 한 줄에 고정했다. 실제 렌더링에서 기존 캠페인 8개 행을 모두 볼 수 있고, 긴 도전 이력을 스크롤해도 버튼이 화면 안에 남는 것을 확인했다.
   - 긴 버전명은 줄임표와 전체 문자열 툴팁을 사용한다. 현재·이전·미상 표시는 버전명 앞에 배치해 긴 문자열에서도 구분이 보인다. 터치용 탭·필터·하단 버튼은 기존 최소 크기를 따른다.
   - README와 서버 문서에 도전 기록 조회와 공유 코드 재사용·기존 코드 보존 정책을 기록했다.

### 검증

- 새 테스트 파일·묶음은 추가하지 않았다. 기존 `replay_shelf_test.gd`에 실패 재현, 실제 파일 저장·로드, 재시작 후 재사용, 메모·클립·미세 수치 차이 구분을 보완했다. 기존 중복 코드·공개 목록·파일 바이트 보존과 자동 정리 후 남은 코드 재사용도 확인했다. 기존 저장·공개 전환 실패와 삭제 실패 재시도 검사도 통과했다.
- 기존 `scene_screens_test.gd`에서 날짜 정렬, 보관된 현재 버전 조회, 이전·미상 기록·실패·0초 표시, 일일/주간 전환, 세 버전 필터, 빈 선택 안내와 프로필 무변경을 검사했다.
- Godot 4.7.2 헤드리스에서 관련 GDScript 테스트 **5개 통과**: `replay_shelf_test.gd`, `scene_screens_test.gd`, `achievements_test.gd`, `touch_layout_test.gd`, `replay_code_ui_test.gd`. `docs_policy_test.py`의 4개 검사와 `git diff --check`도 통과했다.
- Windows OpenGL 렌더러에서 논리 화면 1280×720의 캠페인·일일·주간·스크롤 끝·터치 크기 화면을 캡처하고 확인했다. 60개 날짜의 180개 버전 기록과 긴 버전명을 사용해 하단 버튼 경계와 오래된 기록 접근을 확인했다. 실제 기기 터치 검증은 하지 않았다.
- 첫 렌더링에서 캠페인 마지막 행이 잘려 하단 버튼을 한 줄로 조정했고 관련 화면·업적·터치 검사만 다시 실행했다. 긴 버전명이 상태 표시를 가리는 문제도 상태를 앞에 배치해 해결했다. 터치 캡처는 이전 화면의 지연 삭제 전에 탭을 찾던 검증 스크립트 문제를 한 프레임 대기로 수정했다. 마지막 실제 파일 왕복 검사 추가 뒤에는 리플레이 보관함·공유 UI·문서 검사만 실행했다.
- 실행별 `APPDATA`를 `.godot/validation-user/iteration12/` 아래로 분리했다. 일회성 검증·렌더 스크립트, 로그·캡처는 무시되는 `.godot` 아래에만 있다. 사용자 데이터와 운영 서버를 대상으로 검증하지 않았고 추적 에셋 자동 생성 변경은 없다.
- 기존 환경의 인증서 저장소 오류, 보관함 테스트의 없는 폴더 정리 진단과 일부 종료 시 객체 누수 경고는 검증을 막지 않았다. 출시 버전·전투 규칙·저장 형식 번호·RPC·새 의존성은 변경하지 않았다.

### 다음 개선 후보

1. **프로필 복구의 사용자 흐름**: 원본·현재 진행도를 함께 보관한 뒤 복구 사본을 읽는 기능을 검토한다. 익명 ID·결과 순번이 되돌아가 새 결과가 이미 처리된 것으로 판정되지 않도록 복구 정책이 필요하다.
2. **도전 기록 날짜와 시간의 로드 검증**: 도전 전송 대기열과 달리 로컬 최고 기록은 8자리 정수 문자열을 날짜로 받아들이고 잘못된 완료 시간을 0초로 보정한다. 유효하지 않은 달력 날짜·시간의 재현과 정상 진행도 보존을 함께 검토한다.
3. **설치 확인 기록 상한의 장기 운영 정책**: 기존 중복 방지 자료를 버리지 않으면서 같은 규칙 버전을 장기간 운영할 수 있는 확장·이관 방식은 운영 수요를 확인한 뒤 검토한다.
4. **많은 도전 기록의 탐색 편의**: 이번 회차는 조회와 버전 필터를 제공했다. 사용자가 원하는 날짜로 빠르게 이동할 필요가 확인되면 날짜 선택·구간 이동과 키보드 스크롤 접근성을 검토한다.

Git 커밋·푸시는 수행하지 않았다.

## 2026-10-11 — 프로필 사본 보관과 안전한 진행도 복구

- 이번 주제: 설정에서 현재 진행도 사본을 보관하고, 복구 사본을 확인한 뒤 현재 진행도와 원본을 보존하며 복원한다.
- 시작 상태: 인덱스의 루트 트리와 HEAD, 추적 파일 내용과 인덱스를 Git 명령 없이 읽어 비교했다. 미완료 변경이나 새 파일은 없었다.
- 최근 기록과 다음 후보를 읽고, 아직 구현되지 않은 프로필 복구 흐름을 선택했다. 기존 저장 보호·리플레이·도전 기록 조회는 유지했다.

### 구현한 개선

- 설정 → 데이터에 **진행도 보관·복구**를 추가했다. 현재 메모리의 진행도를 기존 복구 폴더에 사본으로 보관한다.
- 같은 내용의 사본은 재사용한다. 사본·손상 원본은 자동 삭제하지 않으며 전체 초기화 대상임을 안내한다.
- 읽을 수 있는 사본의 파일 보관 시간·닉네임·별·전적·도전 기록 수를 표시하고 복구 전 확인 화면을 제공한다.
- 손상·새 형식·프로필 구조 누락 파일은 목록에서 제외하고 개수와 보관 위치를 안내한다. 목록은 새로고침할 수 있다.
- 복구 전에 현재 메모리 진행도와 디스크 원본의 정확한 바이트를 모두 보관한다. 보관·읽기·원자적 저장 실패 시 현재 진행도를 유지한다.
- 확인한 사본의 내용 지문을 다시 비교한다. 확인 도중 바뀐 파일은 다시 선택하도록 안내한다.
- 전적·진행도·덱·닉네임을 복구하되 현재 설정·익명 ID·전송 대기열을 유지한다. 과거 사본의 대기 결과는 되살리지 않는다.
- 같은 익명 ID의 결과 순번은 현재 메모리·디스크·복구 사본 중 가장 큰 값을 유지해 새 결과가 이미 처리된 것으로 판정되는 일을 막는다.
- 목록과 확인 설명은 스크롤되며 복구·취소 버튼은 고정한다. 실패 안내가 생기면 해당 위치로 스크롤한다.
- README에 사본 보관·복구·수동 수리 사본의 사용법과, 정상 사본이 없으면 손상 전 진행도를 자동 복원할 수 없다는 한계를 설명했다.

### 검토와 다음 후보

- 테스트를 추가·수정·실행하지 않았다. 소스의 저장 실패 분기·기존 원본 보호·화면 전환·전송 대기열 연결을 읽어 검토했으며 실행 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. 기존 저장 스키마·형식 번호·RPC·서버 파일 형식을 유지하며 버전·release.json·CHANGELOG·PatchNotes는 수정하지 않았다. Git 명령은 실행하지 않았다.
- 다음 후보: 도전 기록의 실제 달력 날짜·완료 시간 로드 검증, 많은 도전 기록의 날짜 탐색 편의, 진행도 사본의 내보내기·관리 흐름.

## 2026-10-11 — 도전 기록 날짜 검색과 페이지 탐색

- 이번 주제: 개인 전적의 일일·주간 도전 기록에 날짜 검색과 페이지 이동을 추가하고, 조회 상태를 유지해 오래된 기록을 빠르게 찾는다.
- 시작 상태: Git 명령 없이 인덱스의 트리 해시와 HEAD, 작업 파일의 내용 해시를 읽어 비교했다. 미완료 변경·새 파일은 없었다.
- 최근 3회차와 다음 후보를 확인했다. 이미 구현된 기록 조회·버전 분리를 유지하고 남아 있던 날짜 탐색 불편을 개선했다.
- 확인한 문제: 최대 60일의 여러 버전 기록을 모두 펼쳐 보이며 원하는 날짜는 스크롤로만 찾을 수 있었다. 필터 변경도 두 도전 목록 전체를 다시 만들었다.

### 구현한 개선

- 날짜 검색을 추가했다. `2026`, `2026-10`, `20261011`처럼 UTC 날짜의 앞부분을 입력하고 버전 필터와 함께 사용할 수 있다.
- 주간 기록은 월요일인 주 시작일로 검색한다. 잘못된 입력과 검색 결과가 없는 경우에 원인·입력 방법을 안내한다.
- 날짜 10개 단위로 최신·더 최근·더 이전·마지막 페이지를 이동한다. 같은 날짜의 버전별 기록은 한 페이지에 묶는다.
- 현재 범위·조건에 맞는 날짜 수·전체 기록 수를 표시하고 첫·마지막 페이지에서 불가능한 이동을 비활성화한다.
- 일일·주간 탭마다 검색어·버전 필터·페이지·스크롤 위치를 따로 기억한다. 초기화하면 해당 탭의 전체 기록 첫 페이지로 돌아간다.
- 화면에 열린 도전 탭의 현재 페이지에만 표 셀을 만든다. AI·온라인 요약은 캠페인 탭에 표시해 도전 탐색 공간을 확보했다.
- 목록에 키보드 초점을 두면 방향키·Page Up/Down·Home/End로 스크롤한다. 탐색·업적·메인 화면 버튼은 목록 밖에 유지한다.
