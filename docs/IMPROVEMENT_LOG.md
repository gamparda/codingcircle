# 프로젝트 개선 기록

## 2026-10-13 — 진행도 사본 검색·정렬과 선택 삭제

- 이번 주제: 많은 진행도 사본을 검색·정렬하고, 내용 확인 후 선택한 사본만 안전하게 정리한다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 내용 해시와 HEAD·인덱스 루트 트리를 비교했다. 미완료 변경·새 소스·문서는 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고, 남아 있던 많은 진행도 사본의 검색·정리 흐름을 선택했다.
- 확인한 문제: 긴 드롭다운을 훑어 사본을 찾았고 불필요한 사본은 저장 폴더에서 수동으로 삭제해야 했다.
- 닉네임·UTC 보관 날짜·파일명·진행도 요약 검색을 추가했다. 공백으로 나눈 검색어가 모두 포함된 사본만 표시한다.
- 최근 보관순·오래된 보관순·별 많은 순·캠페인 진행순을 제공한다. 동률은 보관 시간과 파일 경로로 일정하게 정렬한다.
- 표시 수와 읽을 수 있는 전체 사본 수를 안내한다. 검색 결과 없음과 복구 가능한 사본 없음은 구분한다.
- 초기화는 검색과 정렬을 되돌린다. 검색·정렬 변경과 새로고침에도 선택한 파일 경로를 유지한다.
- 선택한 사본이 검색 결과에서 사라지거나 외부에서 삭제되면 다른 사본을 자동 선택하지 않고 복구·내보내기·삭제를 비활성화한다.
- 현재 진행도 보관·가져오기 성공 시 검색을 비우고 해당 사본을 선택한다. 실패는 기존 조건·선택을 유지한다.
- 미리보기에 보관 시간·진행도·파일명을 함께 표시해 같은 닉네임이나 비슷한 진행도의 사본을 구분한다.
- 삭제 확인 창에서 요약·전체 경로·영구 삭제 설명을 제공한다. 취소 버튼에 먼저 초점을 두고 Esc 취소를 지원한다.
- 삭제는 복구 폴더의 읽을 수 있는 일반 JSON 사본 하나로 제한한다. 경로 이탈·링크·내용 변경·읽기 실패는 거절한다.
- 삭제 시 전체 사본을 다시 읽어 마지막으로 읽을 수 있는 사본을 보호한다. 손상·미지원 원본은 대체 사본으로 세지 않는다.
- 삭제 직전에도 선택 파일의 지문을 확인한다. 삭제 실패는 확인 창에 남겨 재시도를 안내한다.
- 삭제 완료 후 조건은 유지하고 다른 파일은 직접 선택하도록 한다. 현재 진행도·다른 사본·리플레이·서버 기록은 수정하지 않는다.
- 검색·정렬은 화면 진입 때 읽은 목록을 사용하며 입력마다 디스크 조회·저장·서버 요청을 수행하지 않는다. 조건은 세이브에 추가하지 않는다.
- 기존 고정 하단 버튼, 확인 본문 스크롤·초점 순환·닫기 후 초점 복원·터치 최소 높이를 유지한다.
- README를 갱신하고 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 사본 조회·지문·삭제 범위·선택 및 화면 연결을 소스로 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 수행하지 않았다. 실제 표시·조작·파일 처리 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식·버전 번호·release.json·CHANGELOG·PatchNotes는 변경하지 않았다. Git 명령은 실행하지 않았다.
- 다음 후보: 리플레이 선택 구간 자체의 클립 공유, 도전 기록에서 보관한 전투 리플레이로 이동하는 흐름, 사본 복구 전후 캠페인·덱 변경의 상세 비교.

## 2026-10-13 — 도전 기록의 성공·실패 필터와 결과 안내

- 이번 주제: 날짜·버전 검색에 성공·실패 필터와 결과별 기록 수를 더해 원하는 도전 기록을 빠르게 찾는다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 내용 해시와 압축된 HEAD 객체·인덱스 루트 트리를 비교했다. 미완료 소스·문서 변경은 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고, 아직 구현되지 않은 도전 기록의 성공·실패 필터를 선택했다.
- 확인한 문제: 날짜와 버전만 고를 수 있어 성공 기록과 미성공 기록을 따로 찾으려면 전체 목록을 훑어야 했다.
- 일일·주간 도전 기록에 결과 전체 / 성공만 / 실패만 선택을 추가했다. 기존 버전 필터·날짜 앞부분 검색과 함께 적용한다.
- 같은 날짜의 현재·이전·미상 버전을 각 기록의 성공 여부로 따로 판별한다. 한 버전의 성공으로 다른 버전의 실패를 숨기지 않는다.
- 결과를 걸러낸 뒤 날짜 단위로 페이지를 나눈다. 조건에 맞는 날짜만 페이지 수·범위에 포함하고 같은 날짜의 해당 버전 기록은 함께 표시한다.
- 날짜·버전 조건에 맞는 성공·실패 수와 결과 필터 적용 후 표시할 기록 수를 목록 위에 표시한다.
- 결과별 수는 모든 페이지 기준으로 계산하고, 결과 선택을 바꿔도 날짜·버전 조건의 성공·실패 수는 유지한다.
- 최고 기록 수는 전체 도전 횟수나 승률이 아님을 툴팁에 설명한다. 성공이 보관된 날짜·버전의 실패 시도는 별도로 표시하지 않음을 안내한다.
- 선택한 결과만 없으면 반대 결과의 기록 수와 결과 전체 선택 방법을 안내한다. 저장 기록 없음·잘못된 날짜 입력·날짜/버전 불일치는 기존 별도 안내를 유지한다.
- 결과 조건 변경 시 첫 페이지·스크롤 시작으로 돌아가 이전 페이지 번호 때문에 기록이 비어 보이지 않도록 한다.
- 일일·주간 탭은 결과 선택을 각자 기억한다. 초기화는 날짜·버전·결과 조건과 페이지를 함께 해제한다.
- 결과 조건만 선택했을 때도 초기화 버튼을 활성화한다. 페이지 안내 툴팁에 결과 조건도 반영했다.

- README에 결과 필터·집계 범위·보관 최고 기록의 의미를 설명하고 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다.

## 2026-10-13 — 리플레이 선택 구간의 병력 기여도 비교

- 이번 주제: 시작·끝 지점 사이의 생산·건설·피해·처치를 누적 집계와 전환해 비교한다.
- 시작 상태: Git 명령 없이 인덱스·작업 파일 해시를 비교하고 압축된 HEAD 객체의 트리와 인덱스 트리를 비교했다. 미완료 변경·새 소스·문서는 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고, 남아 있던 리플레이 선택 구간 비교를 선택했다.
- 확인한 문제: 누적 집계만 보여 특정 교전에서 각 병력이 낸 피해·처치나 그 구간의 투입 자원을 구분하기 어려웠다.
- 기존 시작 [ · 끝 ] 지정 때 각 시점의 집계 사본을 보관한다. 반복 재생을 켜지 않아도 구간을 비교할 수 있다.
- 전투 요약에 선택 구간 / 현재까지 누적 전환을 추가했다. 유효한 구간이 있으면 구간 집계를 먼저 표시하고, 없으면 지정 방법과 비활성 버튼을 표시한다.
- 누적 집계는 요약을 연 장면, 구간 집계는 지정한 두 장면에 고정한다. 재생 위치가 구간 밖이어도 선택 구간의 범위를 제목에 명확히 표시한다.
- 제목·지점 지정 알림·요약 버튼 툴팁에 리플레이 주파수 기준의 분·초·소수 시간을 표시해 짧은 교전도 구분한다.
- 구간 사용 자원·건설과 병력별 피해·처치·생산·해골 소환을 두 집계의 차이로 계산한다. 원본 집계는 수정하지 않는다.
- 시작 이전에 생산된 병력의 구간 내 피해·처치도 포함하며, 비중은 선택 구간의 진영 합계 기준임을 안내한다.
- 기존 피해/처치 전환·공통 눈금·양 진영 합계 정렬·지원 병력·빈 집계·소량 피해 표시를 구간에도 재사용한다.
- 병력별 차이를 합산해 피해·처치 총계의 일관성을 유지한다. 잘못된 집계나 감소한 누적 값은 구간 계산에서 거절한다.
- 시작이 끝 이후로 이동하면 끝 지점과 집계 사본을 함께 해제한다. 새로운 리플레이를 열 때 이전 구간과 사본도 초기화한다.
