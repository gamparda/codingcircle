## 2026-10-14 — 진행도 복구 비교의 항목별 접기·펼치기

- 시작 상태: Git 명령 없이 인덱스와 추적 파일의 원본/LF 해시 및 HEAD 루트 트리를 직접 비교했다. 미커밋 변경·충돌·미추적 소스·문서가 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고 아직 남아 있던 긴 진행도 복구 비교의 접기·펼치기를 선택했다.
- 기록 순서: 소스 수정 전에 주제 기록을 시도했으나 PowerShell 인코딩으로 반영되지 않았다. 문서 확인 중 발견해 즉시 보정했다.
- 확인한 불편: 닉네임부터 도전 기록까지 상세 내용과 설명이 한꺼번에 표시되어, 아래쪽 캠페인·덱·도전 변경을 확인하려면 긴 스크롤이 필요했다.
- 비교를 닉네임·새 기능·전적·업적·시작 목표·튜토리얼·캠페인·덱·도전의 9개 항목으로 나누고 처음에는 요약부터 표시한다.
- 각 항목에 상세 펼치기/접기 버튼을 추가했다. 항목별 요약은 상세 영역 밖에 두어 접은 상태에서도 변경 규모와 현재/사본 상태를 확인한다.
- 캠페인에는 변경된 기록의 단계 수·개방 단계·총 별 요약을 추가했다. 기존 단계별 비교와 성장 보상 계산은 유지한다.
- 모두 펼치기/모두 접기를 추가했다. 일괄 조작은 해당 비교 화면만 바꾸며 복구·가져오기·삭제 동작을 실행하지 않는다.

- 접기·펼치기는 기존 컨트롤의 표시만 바꾼다. 재계산·파일 읽기·서버 요청을 추가하지 않고 선택한 덱 슬롯과 도전 검색·필터·페이지를 유지한다.
- 항목별 접기 상태는 기존 화면 상태에만 보관한다. 사본 변경·새로고침·보관·가져오기·복구 후 재생성과 확인창을 열 때 이어 쓴다.

- 새로고침 후 기억한 초점이 접힌 상세 안에 있으면 해당 항목의 펼치기 버튼으로 복원한다. 파일 소실·필터 제외 시 기존 사본 목록/검색칸 복귀와 화면 수명 보호는 유지한다.
- README를 갱신하고 오래된 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 소스 변경을 원본과 비교하며 상태 전달·빈 변경·컨트롤 수명·기존 복구 경로를 검토했다.

## 2026-10-14 — 리플레이 보관함의 진영별 덱 검색

- 이번 주제: 보관함에서 내 덱·상대 덱(온라인은 블루·레드)을 따로 검색하고 저장된 출전 구성을 재생 전에 확인한다.
- 시작 상태: Git 명령 없이 인덱스와 추적 파일의 원본/LF 해시, HEAD 루트 트리를 직접 비교했다. 미커밋 변경·충돌·미추적 소스·문서가 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고 남아 있던 보관함의 진영별 덱 검색을 선택했다. 소스 수정 전에 이번 주제를 한 줄 먼저 기록했다.
- 확인한 불편: 전체 검색에서는 병력·구조물이 어느 덱에 있는지 구분하지 못하고, 카드의 초상화만으로는 구조물 구성을 확인할 수 없었다.
- 전체 검색과 별도로 블루·레드 덱 검색칸을 추가했다. 캠페인·연습·일일/주간 도전·드래프트는 내 덱/상대 덱으로 안내한다.
- 온라인·기타는 현재 플레이어의 진영을 추정하지 않고 블루·레드 기준을 검색칸 제목과 카드·도움말에 표시한다.
- 각 진영에 저장된 병력·구조물의 한글 이름과 영문 ID만 검색한다. 날짜·파일명·메모나 반대편 덱의 이름으로 해당 진영 조건이 충족되지 않는다.
- 각 칸에서 공백·탭·줄바꿈으로 나눈 검색어를 모두 포함해야 한다. 대소문자를 구분하지 않고 빈칸은 조건을 제한하지 않는다.
- 전체 검색·양쪽 덱 검색·종류·결과·클립·보존 조건을 함께 적용한다. 기존 최근/오래된/용량 큰 순 정렬과 표시 개수·용량 집계는 유지한다.
- 클립도 저장된 전체 전투의 덱을 사용한다. 오늘의 도전이나 현재 편성 덱으로 출전 구성을 대체하지 않는다.

## 2026-10-14 — 리플레이 보관 용량 안내와 큰 파일 탐색

- 이번 주제: 보관함의 전체·일반·정리 제외·읽기 실패 파일 용량과 개수를 안내하고, 큰 파일부터 정렬해 보존한 전투를 관리한다.
- 시작 상태: Git 명령 없이 인덱스와 추적 파일의 원본/LF 해시를 비교했다. 변경·미추적 소스·문서가 없었고, 압축 HEAD 객체를 읽어 인덱스 루트 트리와 일치함을 확인해 중단 작업이 없음을 확인했다.
- 최근 3회차와 아카이브의 다음 후보를 읽고 남아 있던 보관 용량·개수 안내를 선택했다. 소스 수정 전에 이번 주제를 한 줄 먼저 기록했다.
- 확인한 불편: 정리 제외한 전투는 계속 누적되지만 차지하는 용량과 큰 파일을 구분할 안내·정렬이 없었다.
- 보관함 상단에 전체 파일 개수와 용량, 일반·정리 제외·읽기 실패의 개수와 용량을 항상 표시한다. 검색 조건과 관계없는 전체 현황이다.

- 파일 소실·접근 실패·링크 등으로 크기를 확인하지 못하면 0으로 계산하지 않고 용량 미상으로 표시한다. 일부 미상 합계는 확인한 최소 용량과 미상 개수를 안내한다.

- 정리 제외만 필터와 큰 순 정렬로 용량이 큰 보존 전투를 살펴볼 수 있다. 보존 해제·삭제는 기존 카드의 확인창을 거친다.
