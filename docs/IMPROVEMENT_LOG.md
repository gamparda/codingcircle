# 프로젝트 개선 기록

## 2026-10-14 — 전투 스탯의 분류별 읽던 설명 복원

- 이번 주제: 병력·구조물·전투 규칙을 오갈 때 각 분류의 읽던 설명을 복원하고, 창 재열기·빠른 전환·화면 폭 변경에서도 탐색 위치를 유지한다.
- 시작 상태: Git 명령 없이 추적 파일의 원본/LF 해시·인덱스와 느슨한 객체·팩 객체의 HEAD 트리를 대조했다. 미커밋 변경·충돌·미추적 소스·문서가 없어 중단 작업은 없었다.
- 최근 3회차·다음 후보와 아카이브 주제를 읽고 남아 있던 전투 스탯의 분류별 위치 복원을 선택했다. 소스 수정 전에 이번 주제를 한 줄 먼저 기록했다.
- 확인한 불편: 병력 설명을 읽다가 구조물·전투 규칙을 확인하면 원래 분류도 맨 위로 돌아가 읽던 설명을 반복해서 찾아야 했다.
- 병력·구조물·전투 규칙의 위치를 각각 현재 전투의 메모리에 보관한다. 분류를 다시 선택하면 해당 분류에서 읽던 설명으로 돌아간다.
- 현재 선택된 분류를 다시 눌러도 위치를 유지하고 선택 표시가 꺼지지 않게 했다. 방문하지 않은 분류는 처음부터 표시한다.
- 맨 위에 걸친 카드의 고유 ID와 카드 안의 위치를 함께 기억한다. 같은 제목의 여러 전투 규칙 카드도 서로 다른 ID로 구분한다.
- 창 재열기와 분류 복귀에서도 카드 기준 복원을 사용한다. 한 열·두 열 배치가 바뀌면 같은 설명으로 복원하며 카드 높이와 스크롤 범위에 맞춰 위치를 제한한다.
- 빠른 분류 전환은 이전 지연 복원을 무효화한다. 배치 대기 중 다시 전환해도 아직 복원되지 않은 픽셀 위치로 기존 기록을 덮어쓰지 않는다.
- 배치 대기 중 즉시 창을 닫으면 도착할 분류의 위치를 보관한다. 다시 열 때 이전 분류의 스크롤을 잘못 적용하지 않는다.
- 분류 전환과 열 수 변경은 키보드 초점을 강제로 옮기지 않는다. 기존 창 재열기의 초점·검색 커서 복원과 자동 정지·확인창의 초점 우선순위를 유지한다.
- 직접 스크롤·터치·스크롤바·Tab·Ctrl+F·페이지 이동이 들어오면 복원보다 사용자 조작을 우선한다. 삭제·교체된 창의 지연 콜백도 기존 수명 검사로 중단한다.
- 검색어·진영·출전 필터를 바꾸면 분류별 위치를 지우고 새 결과의 처음부터 표시한다. 이전 결과의 위치를 새 검색 결과에 적용하지 않는다.
- 조건 초기화는 분류별 위치까지 지우고 병력 분류의 처음으로 돌아간다. 검색 조건이 기본이어도 현재 또는 다른 분류에 읽던 위치가 있으면 초기화 버튼을 사용할 수 있다.
- 분류당 위치 하나만 보관하고 노드 참조나 파일 저장을 추가하지 않는다. 기존 같은 경기 재접속의 상태 유지와 새 전투·재도전·재대전의 상태 초기화 경로를 재사용한다.
- 분류 버튼·초기화 툴팁과 README에 사용법을 반영했다. 가장 오래된 1회차를 아카이브로 옮겨 최근 3회차만 남겼다.
- 소스로 초기 구성·분류 전환·필터 변경·복원 취소·초점·창 닫기·열 수 변경·전투 초기화 경로를 검토했다. 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 실제 로드·배치·터치·빠른 전환·재접속 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·스냅샷·세이브·서버 파일 형식과 전투 규칙·밸런스·버전 번호·release.json·CHANGELOG·PatchNotes를 유지했다. Git 명령은 실행하지 않았다.
- 다음 후보: 전장 병력 종류별 생존 수를 터치로 확인하는 상세 안내, 도전 보관 전투 선택 창의 개별 검색 조건 해제, 복구 비교에서 특정 감소 경고의 상세로 바로 이동하는 흐름.

- 확인한 문제: 모델은 양쪽 병력·소환수 합계 256명에서 생산을 거절하지만 카드는 자원·생산 대기만 확인했다. 한도에 도달하면 활성 카드를 눌러도 생산되지 않았고 원인도 표시되지 않았다.
- 양쪽 기지 패널의 기존 제목 옆에 살아 있는 병력 수를 표시했다. 소환수가 있으면 전체 병력 중 소환수 수를 함께 표시해 전력 규모를 바로 확인할 수 있다.
- 각 진영의 툴팁에 병력 종류별 생존 수와 소환 병력을 표시했다. 관전의 툴팁은 블루·레드 기준을 사용하며 내 진영이 오른쪽 서버 진영이어도 실제 진영에 맞춰 집계한다.

- 생존 병력 수는 체력이 남은 병력만 집계한다. 생산 한도 판정은 모델과 동일하게 배열 전체 크기를 사용해 사망 후 정리 대기 중인 병력도 포함한다.
- 정리 대기 중인 병력이 있으면 전체 한도 툴팁에 그 수를 별도로 안내한다. 구조물·포탑·발전기는 병력 수에 포함하지 않는다.

## 2026-10-14 — 전투 자원 회복과 구매 예상 대기 안내

- 이번 주제: 전투 HUD에 자원 회복 속도·한도 도달 상태와 카드별 구매 예상 대기를 표시해 생산·건설 시점을 쉽게 판단한다.
- 시작 상태: Git 명령 없이 추적 파일의 원본/LF 해시와 인덱스를 비교하고, 느슨한 객체·팩 객체의 HEAD 트리도 인덱스와 대조했다. 미커밋 변경·충돌·미추적 소스·문서가 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 주제·다음 후보를 읽었다. 보관함·복구·스탯 탐색과 중복되지 않는 실제 전투의 구매 시점 안내를 선택하고 소스 수정 전에 주제를 먼저 기록했다.
- 확인한 불편: 구매 카드는 부족한 자원만 표시하고 회복 속도는 보이지 않아 생산·건설까지 얼마나 기다려야 하는지 계산해야 했다. 자원이 가득 차 회복이 멈춘 상태도 숫자만으로 판단해야 했다.
- 자원 패널 아래에 회복 +N/초를 표시했다. 툴팁에는 전투 시간 기준 회복량·살아 있는 아군 발전기 개수·보유 한도를 함께 안내한다.

- 기존 설치 개수 집계에서 체력이 남은 아군 발전기만 포함해 추가 수입을 계산한다. 적 발전기와 파괴 후 정리 대기 중인 발전기는 포함하지 않는다.
