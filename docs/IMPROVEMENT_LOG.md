# 프로젝트 개선 기록

## 2026-10-14 — 누르고 유지하는 병력 반복 생산

- 이번 주제: 병력 카드·구매 단축키를 누르고 있는 동안 기존 생산 조건에 맞춰 반복 구매하고, 입력 해제·화면 중단 시 즉시 취소한다.
- 시작 상태: Git 명령 없이 인덱스와 작업 파일의 원본/LF 해시를 대조하고, 인덱스에서 재구성한 트리와 HEAD 트리를 비교했다. 변경·스테이징 변경·미추적 소스가 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 주제·다음 후보를 읽고 남아 있던 병력 반복 생산을 선택했다. 구현 전에 이번 주제를 로그에 먼저 적었다.
- 확인한 불편: 병력을 계속 생산하려면 카드나 단축키를 매번 다시 눌러야 했으며, 생산 대기·자원 부족 중 누른 입력을 계속 유지할 방법이 없었다.
- UnitPurchaseHold에 입력 소유권과 유지 상태를 모았다. Main은 입력 전달·프레임 진행·화면 정리만 연결하고 구조물 선택·설치 경로는 유지한다.
- 카드의 짧은 클릭·터치는 놓을 때 한 번 구매한다. 약 0.35초 유지하면 반복으로 전환하며 반복 후 손을 뗄 때 추가 구매하지 않는다.
- 병력 구매 단축키는 누르는 순간 기존 구매를 실행하고 유지하면 반복한다. 사용자 지정 키를 그대로 사용하며 운영체제 키 자동 반복 속도에는 의존하지 않는다.
- 자원 부족·생산 대기·전장 한도로 비활성화된 카드에서도 유지를 시작할 수 있다. 최신 카드 상태가 구매 가능으로 바뀔 때만 구매하며 자원을 미리 예약하지 않는다.
- 구매는 기존 pressed 신호를 통해 실행해 로컬 모델·서버 판정·클라이언트 구매 간격·튜토리얼 진행·리플레이 기록을 유지한다. 연습 배속에서도 기존 생산 조건을 따른다.
- 반복 시도 사이에 최소 기존 구매 간격을 두며 느린 프레임 뒤 누적 구매를 몰아서 보내지 않는다. 구조물은 반복 구매 대상에서 제외한다.
- 가장 최근에 시작한 병력 한 종류만 유지한다. 다른 키·클릭·터치는 이전 유지를 취소하고, 나중에 손을 떼도 이전 종류를 자동으로 재개하지 않는다.
- 카드에 유지하면 반복 / 반복 생산 중 표시를 추가했다. 기존 비용·단축키·자원 부족·생산 대기·병력 한도 표시는 유지하고 툴팁과 README에 조작을 설명했다.
- 누름을 시작한 카드 밖으로 이동·드래그하거나 해당 키·마우스·터치를 놓거나 운영체제가 취소하면 중단한다. 좌표 판정은 카드의 캔버스 변환을 반영한다.
- 입력 해제는 GUI보다 먼저 처리해 구매 중 카드가 비활성화돼도 놓는 입력을 받는다. 취소된 키의 반복·해제와 포인터 해제를 소비해 아래 버튼에 전달하지 않는다.
- 터치와 마우스의 에뮬레이션 이벤트는 새 유지를 시작하지 않아 같은 동작의 중복 구매를 막는다. 창 아래 카드 위치라는 이유로 모달의 에뮬레이션 클릭을 막지 않는다.
- 스탯·병력/구조물 현황·전투 요약·채팅·확인창·일시정지·연결 복구·최신 상태 대기·관전·전투 종료에서는 유지를 취소한다. 앱 이탈·화면 정리·노드 종료는 입력 기록도 비운다.
- 새로운 병력 유지 시작 시 진행 중이던 구조물 터치만 정리한다. 구조물 선택과 키보드 미리보기·설치 확정·서버 확인 흐름은 유지한다. 유지 상태는 메모리에만 둔다.
- 소스로 구매·입력 라우팅·해제·취소·상태 갱신·화면 수명을 검토하고 [Godot 에뮬레이션 입력](https://docs.godotengine.org/en/stable/classes/class_inputevent.html)과 [터치 취소](https://docs.godotengine.org/en/stable/classes/class_inputeventscreentouch.html) 속성을 확인했다.
- 테스트 추가·수정·실행과 게임 실행·로드 검사·렌더링은 하지 않았다. 실제 로드·짧은 탭·장기 유지·자원/한도 해제·사용자 지정 키·멀티터치·모달·앱 이탈·온라인 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식과 버전 번호·release.json·CHANGELOG·PatchNotes는 유지했다. Git 명령은 실행하지 않았으며 가장 오래된 회차를 아카이브로 옮겨 최근 3회차만 남겼다.
- 다음 후보: 복구 비교에서 특정 감소 경고의 상세로 바로 이동하는 흐름, 도전 보관 전투 검색 결과의 페이지 번호 직접 이동, 전투 중 구조물의 남은 수명·만료 시점 안내.

## 2026-10-14 — 구조물 키보드 배치와 설치 간격 미리보기

- 이번 주제: 구조물을 키보드만으로 선택·위치 조정·설치할 수 있게 하고, 기존 구조물과의 설치 불가 간격을 전장에 미리 표시한다.
- 시작 상태: Git 명령 없이 인덱스를 읽어 작업 파일의 원본/LF 해시와 대조하고 재구성한 인덱스 트리를 HEAD 트리와 비교했다. 변경·충돌·미추적 파일·스테이징 변경이 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 주제·다음 후보를 읽었다. 최근 요약·보관함 개선과 겹치지 않는 전투 배치를 선택하고 소스 수정 전에 이번 주제를 기록했다.
- 확인한 불편: 구조물 구매 단축키는 카드를 선택하기만 했고 위치 조정·설치에는 포인터가 필요했다. 기존 구조물과의 간격 부족도 해당 위치를 짚어야 알 수 있었다.
- 구조물 구매 단축키로 선택하면 키보드 미리보기를 시작한다. 현재 포인터 주변에서 건설 구역 끝과 살아 있는 아군 구조물의 최소 간격 경계를 후보로 살펴 가까운 유효 위치를 고른다.
- 유효 위치가 없으면 미리보기의 기존 설치 불가 사유를 표시하며 강제로 설치하거나 자원을 예약하지 않는다. 발전기는 후방 구역만 후보로 사용한다.
- ←/→는 화면의 좌우 방향으로 15 월드 단위, Shift+←/→는 3 단위씩 이동한다. Home/End는 후방/전방 끝으로 이동하며 레드 진영의 반전 시점에도 같은 조작을 사용한다.
- 사용자 지정 구매 키와 겹치는 방향키·Home/End는 기존 구매에 우선 사용한다. 선택 중 Shift와 함께 누르면 배치 조작으로 사용할 수 있으며 단축키 설정·세이브 형식은 바꾸지 않는다.
- Enter·숫자패드 Enter로 기존 설치 경로를 호출한다. 마우스로 선택한 카드에서 첫 Enter는 미리보기를 시작하고 별도의 다음 입력으로 설치해 보지 못한 위치에 즉시 건설하지 않는다.
- Enter 자동 반복과 키를 놓는 이벤트를 소비해 설치 후 선택이 풀리거나 서버 응답이 도착해도 아래의 구매 버튼이 함께 작동하지 않게 한다. 앱 이탈·화면 정리 때 눌림 기록을 초기화한다.
- 키보드 위치를 월드 좌표로 보관하고 미리보기와 설치가 같은 값을 사용한다. 좌표 왕복의 반올림으로 구역·최소 간격 경계 판정이 달라지는 경로를 피한다.
- 정지한 마우스 좌표는 키보드 위치를 덮어쓰지 않는다. 전장에서 실제 마우스를 움직이거나 터치를 시작하면 해당 입력으로 전환하며, 구조물 교체·해제는 이전 미리보기와 터치를 정리한다.
- 채팅·텍스트 입력·스탯·전투 요약·확인창과 전투 정지·재접속·관전·종료·설치 응답 대기에서는 배치 확정을 실행하지 않는다. 진행 중인 터치도 키보드로 확정하지 않는다.
- 녹색 건설 구역 안에 살아 있는 아군 구조물의 최소 간격을 붉은 빗금 띠로 표시한다. 색상과 무늬를 함께 쓰며 적군·파괴된 구조물은 제외하고 발전기 후방 범위와 진영 반전을 반영한다.
- 키보드 커서에 금색 표시와 유효 위치의 Enter 설치 안내를 더했다. 조작 안내는 전장 위쪽으로 옮겨 간격 띠와 설치 오류 문구를 가리지 않도록 배치하고 카드 툴팁·README도 갱신했다.
- 기존 클릭·터치 놓기·전장 밖 취소·Esc, 설치 성공 후 해제, 로컬 리플레이 기록, 온라인 서버 승인·자원·전체/종류별 한도 판정 경로를 유지한다.
- 소스로 입력 라우팅·반복/해제·반전 좌표·경계·미리보기 수명·팝업 차단을 검토하고 [Godot 키 입력](https://docs.godotengine.org/en/stable/classes/class_inputeventkey.html)과 [속성 setter](https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/gdscript_basics.html#properties-setters-and-getters) 동작을 확인했다.
- 테스트 추가·수정·실행과 게임 실행·로드 검사·렌더링은 하지 않았다. 실제 로드·키보드/터치 전환·사용자 지정 키·온라인 응답·앱 이탈·좁은 화면 배치는 외부 스크립트에서 검증해야 한다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식과 버전 번호·release.json·CHANGELOG·PatchNotes는 유지했다. Git 명령은 실행하지 않았으며 가장 오래된 회차를 아카이브로 옮겨 최근 3회차만 남겼다.
- 다음 후보: 병력 생산 카드를 누르고 유지하는 동안 생산 대기에 맞춰 반복 구매하는 조작, 복구 비교에서 특정 감소 경고의 상세로 바로 이동하는 흐름, 도전 보관 전투 검색 결과의 페이지 번호 직접 이동.

## 2026-10-14 — 전투 요약의 읽던 위치 복원과 모달 조작

- 이번 주제: 전투 결과 요약의 스크롤·기여도 선택·초점을 복원하고 키보드 조작을 모달 안에 한정하며 확정된 전세 기록의 반복 깊은 복사를 제거한다.
- 시작 상태: Git 명령 없이 인덱스와 작업 파일의 원본/LF 해시를 대조하고, loose·pack 객체에서 HEAD 트리를 읽어 인덱스와 비교했다. 미커밋·스테이징 변경·충돌·미추적 소스가 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 주제·다음 후보를 읽었다. 소스 수정 전에 이번 주제를 로그에 먼저 기록했다.
- 확인한 불편: 결과 요약을 다시 열면 스크롤·피해/처치 선택이 초기화되고, Esc·페이지 이동 및 창 내부 초점 순환이 없어 긴 집계를 다시 찾아야 했다.
- Main에 같은 전투의 요약 탐색 상태를 보관한다. 새 전투의 결과 초기화 때 새 딕셔너리로 교체하며 세이브에는 쓰지 않는다.
- 공통 기여도 UI에 populate_with_state를 추가해 선택한 피해/처치를 복원한다. 기존 populate 호출은 독립 상태로 동작해 리플레이의 기존 호출 방식을 유지한다.
- 화면 내용과 본문에 고정 노드 이름을 부여해 재생성 후에도 스크롤·비교 버튼의 초점 경로를 다시 찾는다.
- BattleReportBrowser가 스크롤과 본문 초점을 기록한다. 닫기 버튼으로 옮긴 초점은 기존 읽기 위치를 덮어쓰지 않는다.
- 창을 열면 목록에 즉시 초점을 주고, 레이아웃과 초점 따라 스크롤이 끝난 뒤 저장 위치를 복원한다. 사라진 초점 경로는 목록으로 대체한다.
- 사용자의 키·클릭·휠·터치·드래그는 대기 중인 복원을 취소한다. 창 숨김·삭제 대기·조상 삭제·화면 이탈 후에는 지연 복원을 적용하지 않는다.
- Tab·Shift+Tab은 목록·실제 피해·처치·닫기를 창 안에서 순환한다. 외부의 재도전·단계 이동 버튼으로 키보드 초점이 넘어가지 않는다.
- 목록 초점의 위/아래 방향키와 창 안의 Page Up/Down·Home/End로 긴 집계를 탐색한다. 터치·휠·기존 비교 버튼 조작도 유지한다.
- Esc와 닫기는 읽던 위치를 보관하고 요약 진입 초점으로 돌아간다. 기존 초점이 없어졌다면 결과 화면의 전투 요약 버튼을 사용한다.
- Main의 요약 키 처리를 전투 단축키보다 먼저 배치한다. 창 조작과 전장 조작이 겹치지 않으며 전역 F11 처리는 유지한다.
- 닫을 때 삭제 대기 전에 창을 숨겨 남은 포인터 입력과 곡선 준비를 중단한다. 이미 닫힌 창의 예약 복원도 무효화한다.
- 결과 확정 후 전세 샘플링은 멈추고 새 경기에서는 배열을 교체하는 경로를 확인했다. 확정된 전세 기록은 읽기 전용 그래프에 참조로 전달해 매번 모든 관측점을 깊게 복사하지 않는다.
- 결과 확정 전 호출에는 기존 깊은 복사 격리를 유지한다. 그래프의 극값·공백·좌표와 프레임별 곡선 준비, 작은 전투 집계의 스냅샷 복사는 유지한다.
- README에 복원·단축키·초점 복귀를 반영했다. 소스로 결과 확정·경기 초기화·모달 입력·노드 경로·지연 복원 수명을 검토했으며 성능 수치는 측정하지 않았다.
- 테스트 추가·수정·실행 및 게임 실행·렌더링은 하지 않았다. 실제 로드·재진입·메트릭 전환·키보드/터치·연속 닫기·새 경기·재접속·긴 기록 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식과 버전 번호·release.json·CHANGELOG·PatchNotes를 유지했다. Git 명령은 실행하지 않았다. 가장 오래된 회차를 아카이브로 옮겨 최근 3회차만 남겼다.
