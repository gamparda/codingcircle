# 프로젝트 개선 기록

## 2026-10-13 — 중요한 리플레이의 정리 제외와 보존 해제

- 이번 주제: 보관함에서 기존 전투·클립을 다시 저장하지 않고 정리 대상에서 보존하고, 보존 상태·해제 영향과 파일 변경을 확인한다.
- 시작 상태: Git 명령 없이 추적 파일 해시와 인덱스·HEAD 루트 트리를 비교해 미커밋 변경·충돌·미추적 소스와 문서가 없음을 확인했다. 최근 기록·아카이브의 다음 후보에서 보존을 선택하고 소스 수정 전 주제를 먼저 적었다.
- 확인한 불편: 오래된 중요한 전투·클립·메모를 정리 대상에서 남기려면 사본을 다시 저장해야 했고, 원하는 전투를 계속 보존할 조작이 없었다.
- 보관함 카드에 정리 제외·보존 해제를 추가했다. 확인창에 전투 결과·전체 시간·클립 구간·메모 수와 적용 범위를 표시한다.
- 정리 제외한 정상 파일은 일반 리플레이 최근 50개와 별도로 모두 보존한다. 자동 저장 정리와 수동 정리가 같은 대상 선정 함수를 사용한다.
- 보존 해제는 지금 삭제하거나 정리하지 않는다. 다음 저장·정리 때 기존 보관 순서에 따라 삭제될 수 있음을 확인창과 완료 안내에 명시했다.
- 같은 파일의 선택 메타데이터만 저장한다. 파일 이름·전투·클립·메모·보관 순서를 유지하며 새 사본·새 저장 순서·서버 요청은 만들지 않는다.
- 메모 저장은 디스크의 보존 상태를 유지한다. 새 사본·새 클립 저장과 공유 텍스트의 내보내기·가져오기는 이 파일의 보존 설정을 넘기지 않는다.
- 보존 표식과 정리 제외만·일반만 필터를 추가했다. 기존 검색·종류·결과·클립 조건과 함께 적용하고 초기화·새로고침·재생 복귀에서도 상태를 유지한다.
- 일반 파일 수와 보존 파일 수를 구분해 보존 때문에 50개를 넘는 상황을 정리 실패로 안내하지 않는다. 실패 재시도는 일반 파일이 한도를 넘을 때 표시한다.
- 정리 확인창의 이 전투 정리 제외로 보존한 뒤 카드·보존 개수·삭제 목록을 갱신한다. 남은 대상은 새 확인창에서 확인하며 더 없으면 보관함으로 돌아간다.
- 경로·파일 종류·SHA-256을 확인창 구성과 저장 직전·임시 파일 교체 전에 비교한다. 내용·메모 변경·소실·링크·폴더와 임시 경로 링크·폴더는 차단하고 쓰기·교체 실패 때 원본을 유지한다.
- 자동 정리도 삭제 직전 보존 상태·읽기 가능 여부와 파일 지문을 재확인한다. 수동 정리의 목록·지문·부분 실패 보호와 최근 저장 파일 보존을 유지한다.
- 직접 삭제 확인창에는 보존한 전투임을 추가로 표시한다. 직접 삭제·데이터 전체 초기화에는 정리 제외가 적용되지 않으며 별도 백업이 필요함을 안내한다.
- 기본 초점은 취소다. Tab·방향키·Esc·키보드 스크롤·터치 높이 58·줄바꿈을 적용했다. 취소는 기존 초점, 변경 후에는 검색·스크롤과 카드 보존 버튼 초점을 복원하며 필터에서 제외되면 검색칸으로 옮긴다.
- 보존 변경은 도전 점수 분석의 재사용 지문에서 제외한다. 재생·분석 시작의 전체 파일 변경 검사와 전투 재현·점수 계산은 유지한다.
- README와 보관 도움말을 갱신하고 오래된 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 소스로 저장·정리·콜백·파일 지문·초점 경로를 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 실제 로드·재시작·메모·공유·정리·키보드·터치 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 로컬 리플레이 JSON에 선택 필드 _local_protected=true를 추가했다. 기존 파일은 일반 기록으로 읽으며 이전 게임은 이 설정을 적용하지 않는다. RPC 시그니처·진행도 세이브·서버 파일 형식과 버전 번호·release.json·CHANGELOG·PatchNotes는 유지했다. Git 명령은 실행하지 않았다.
- 다음 후보: 보관함에서 최근 재생한 전투 카드로 돌아오는 초점 복원, 복구 사본 목록의 선택·스크롤·초점을 새로고침 후 복원하는 흐름, 오래된 보존 전투를 한눈에 관리하는 보관 용량·개수 안내.

## 2026-10-13 — 복구 사본의 덱 이름·구성 검색과 슬롯 범위 선택

- 이번 주제: 덱 이름·병력·구조물로 복구 사본을 찾고, 같은 슬롯에서 일치한 구성과 최근 선택 덱을 복구 전에 확인한다.
- 시작 상태: Git 명령 없이 인덱스와 추적 파일의 원본/LF 해시, 인덱스 루트 트리와 HEAD 루트 트리를 비교했다. 미커밋 변경은 없었고 미추적 소스·문서도 없었다. 무시된 Python 캐시는 작업 대상에서 제외했다.
- 최근 3회차·아카이브의 다음 후보를 읽고 남아 있던 복구 사본의 덱 검색을 선택했다. 소스 수정 전에 이번 주제를 로그에 먼저 적었다.
- 확인한 불편: 사본 검색은 닉네임·날짜·파일명·진행도 요약만 읽어 기억하는 덱 이름이나 구성으로 과거 사본을 찾을 수 없었다.
- 검색 대상에 저장된 세 덱의 이름, 병력·구조물 한글 이름과 영문 ID를 추가했다. 현재 덱이나 현재 선택 슬롯으로 대체하지 않는다.
- 공백·탭·개행·대소문자를 정리해 모든 검색어를 포함하는 사본을 찾는다. 날짜·닉네임 등 기존 검색 조건과 함께 쓸 수 있다.
- 덱 조건은 같은 슬롯 안에서 모두 일치해야 한다. 서로 다른 슬롯에 나뉜 병력·구조물을 하나의 덱처럼 합쳐 검색하지 않는다.
- 모든 덱 슬롯·사본의 최근 선택 덱·덱 슬롯 1~3 범위를 추가했다. 최근 선택 덱은 각 사본의 last_deck 값으로 판단한다.
- 목록 행에 일치한 첫 슬롯·덱 이름과 추가 일치 슬롯 수를 표시해 비슷한 진행도의 사본을 구별한다. 긴 구성은 도움말과 미리보기에 표시한다.
- 선택한 사본의 일치 슬롯마다 이름·최근 선택 여부와 병력·구조물 전체 구성을 표시한다. 표시 순서는 저장된 전투 버튼 순서를 유지한다.
- 한글 이름 옆 영문 ID를 표시해 이름이 겹치는 병력을 구별한다. 미리보기와 검색은 같은 슬롯 판정 함수를 사용한다.
- 검색한 슬롯이 기존 비교 선택과 다르면 첫 일치 슬롯부터 현재 → 사본 비교를 보여 준다. 기존 슬롯 버튼으로 다른 덱도 비교할 수 있다.
- 검색 범위는 사본을 찾는 조건이며 복구는 진행도와 세 덱 전체를 되돌린다는 안내를 화면·범위 도움말에 명시했다.
- 새로고침·사본 보관·가져오기·삭제·복구 이후에도 슬롯 범위와 정렬을 화면 상태로 유지한다. 초기화는 검색·범위·정렬을 함께 되돌린다.
- 선택 사본이 조건에서 제외되면 다른 사본을 자동 선택하지 않는다. 복구·내보내기·삭제 비활성화와 마지막 사본 보존·파일 지문 확인을 유지한다.
- 검색칸을 전체 폭으로 배치하고 범위·정렬·초기화는 좁은 화면에서 줄바꿈한다. 터치 환경의 최소 높이 58과 기존 입력·선택 조작을 유지한다.
- 검색 중 파일 재조회·저장·삭제·리소스 로드·서버 요청은 추가하지 않았다. 사본 목록을 열 때 읽은 정규화된 데이터만 검색한다.
- README를 갱신하고 오래된 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 소스로 검색 판정·콜백·선택 제외·범위 상태·비교 연결을 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 실제 로드·검색·키보드·터치·복구 회귀 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식과 버전 번호·release.json·CHANGELOG·PatchNotes를 유지했다. Git 명령은 실행하지 않았다.
- 다음 후보: 보관 전투를 다시 저장하지 않고 정리 대상에서 보존하는 흐름, 보관함에서 최근 재생한 전투 카드로 돌아오는 초점 복원, 복구 사본 목록의 선택·스크롤·초점을 새로고침 후 복원하는 흐름.

## 2026-10-13 — 도전 보관 전투의 전체 덱 한 번에 검색

- 이번 주제: 카드의 내 덱·상대 덱 전체를 한 번에 검색 조건으로 적용하고, 다른 조건·스크롤·초점과 재생 후 복귀를 유지한다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 해시와 HEAD 객체의 루트 트리를 비교했다. 미커밋 변경과 미추적 파일은 없었다.
- 최근 3회차·아카이브의 다음 후보에서 전체 덱 검색을 선택했다. 소스 수정 전 선기록을 시도했지만 셸 인코딩으로 반영되지 않은 것을 발견해 패치로 바로 보정했다.
- 확인한 불편: 같은 출전 구성을 찾으려면 진영마다 병력·구조물을 하나씩 눌러야 했다. 양쪽 덱을 찾을 때는 두 진영의 조건을 따로 조립해야 했다.
- 카드에 내 덱 전체 검색·상대 덱 전체 검색을 추가했다. 해당 검색칸을 저장된 병력·구조물 전체 영문 ID로 교체한다.
- 양쪽 덱 전체 검색은 두 진영의 검색칸을 함께 교체해 같은 대결 구성을 한 번에 찾는다.
- 적용된 버튼은 체크·눌림 상태와 검색 해제를 표시한다. 다시 누르면 해당 진영의 검색칸만 비우며 양쪽 버튼은 두 칸을 비운다.
- 전체 검색·결과·클립 조건과 선택하지 않은 진영의 검색어를 유지한다. 대상 검색칸의 기존 조건을 대체한다는 점을 도움말·툴팁·상태 안내에 명시했다.
- 구성은 저장된 전투에서 읽고 현재 덱·오늘의 도전으로 대체하지 않는다. 클립도 전체 전투의 출전 구성으로 검색한다.
- 영문 ID로 이름이 겹치는 병력을 구별한다. 병력·구조물 전체를 포함해야 하며 출전 순서나 실제 생산·설치 수는 구분하지 않는다.
- 검색어의 대소문자·공백·순서가 달라도 같은 전체 ID 조건이면 선택 표시를 유지한다. 추가 검색어나 일부 항목만 지정한 조건은 전체 덱 선택으로 표시하지 않는다.
- 직접 입력·개별 항목 선택·해제·초기화 때 모든 카드의 개별 항목과 전체 덱 선택 표시를 함께 갱신한다.
- 양쪽 검색칸의 길이를 먼저 확인한 뒤 모두 갱신하고 필터를 한 번 적용한다. 길이 초과 시 일부 조건만 적용하거나 기존 검색어를 잘라내지 않는다.
- 개별 항목과 전체 덱의 검색 적용 경로를 공유한다. 클릭한 카드 초점·보이는 위치를 유지하고 터치 키보드를 자동으로 열지 않는다.
- 지연 스크롤 복원은 기존 화면 수명·회차 값으로 차단한다. 새로고침·재생 후 복귀에도 진영별 검색·스크롤·카드 버튼 초점을 유지한다.
