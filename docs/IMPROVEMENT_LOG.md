# 프로젝트 개선 기록

## 2026-10-13 — 온라인 리플레이 코드 요청과 화면 수명 보호

- 이번 주제: 코드 열기·최근 전투 보기·코드 공유의 중복 요청을 막고, 닫힌 화면의 늦은 응답을 안전하게 정리한다.
- 시작 상태: Git 명령 없이 인덱스와 추적 파일 내용 해시를 비교하고 인덱스의 트리 해시를 HEAD와 대조했다. 미완료 변경·새 소스·문서는 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고, 남아 있던 온라인 리플레이 요청의 중복 클릭·화면 수명 관리를 선택했다.
- 확인한 문제: 코드 발급·최근 전투 보기에서 클릭마다 응답 구독과 요청이 늘어났고, 닫힌 화면의 콜백이 재생이나 클립보드 변경을 수행할 수 있었다.
- 코드 열기는 입력한 코드와 응답 코드를 대조한다. 다른 코드의 늦은 응답은 무시한다.
- 코드 입력을 기존 서버의 허용 문자·길이 규칙으로 확인하고 잘못된 입력은 접속 전에 안내한다. 요청 중 입력과 열기 버튼을 잠근다.
- 연결 실패·찾을 수 없는 코드·응답 시간 초과 후에는 입력과 버튼을 다시 활성화한다. 닫기 버튼은 요청 중에도 사용할 수 있다.
- 네트워크 노드 아래에 응답 채널별 요청을 관리한다. 화면이 바뀌어도 요청 구분에 필요한 상태는 유지하고 화면 콜백은 분리한다.
- 소유 컨트롤과 모든 상위 노드의 삭제 예약까지 확인해 같은 프레임에 닫힌 화면으로 응답이 돌아오는 경우를 차단한다.
- 최근 전투 보기도 요청 코드가 일치할 때만 재생한다. 같은 버튼의 중복 클릭과 다른 전투의 동시 요청을 막고 이유를 안내한다.
- 최근 온라인 목록에 새로고침을 추가했다. 요청 중 비활성화하고 실패 후 다시 활성화하며 기존 목록을 유지한다.
- 목록 교체 시 이전 행을 즉시 트리에서 분리해 그 행에 연결된 보기 요청의 화면 콜백도 해제한다.
- 코드 발급은 채널 전체에서 한 번에 하나만 보낸다. 응답에 요청 식별자가 없어 다른 전투에 늦은 코드가 붙지 않도록 한다.
- 발급이 끝난 카드의 코드를 다시 누르면 추가 업로드 없이 복사한다. 공유 내용의 해시가 달라지면 새로 발급한다.
- 발급 지연·화면 닫기 후에도 전송한 요청은 응답을 소진하거나 연결이 바뀔 때까지 유지한다. 같은 내용은 추가 전송 없이 다시 응답을 기다릴 수 있다.
- 다른 전투의 발급은 이전 응답을 기다리도록 안내하고 복사 공유를 제공한다. 연결을 임의로 끊어 진행 중인 온라인 활동을 중단하지 않는다.
- 응답 대기는 전송 후 12초로 제한한다. 시간 초과·서버 연결 변경·응답 완료 시 버튼 상태와 구독을 정리하고, 닫힌 화면의 클립보드 변경을 막는다.
- 새 입력·열기·닫기·새로고침·보기 조작은 최소 높이 58을 적용했다. 긴 상태 안내와 전투 설명은 줄바꿈한다.
- README를 갱신하고 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 요청·응답·화면 정리·연결 전환·시간 초과 흐름을 소스로 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 수행하지 않았다. 실제 로드·표시·네트워크 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식·버전 번호·release.json·CHANGELOG·PatchNotes는 변경하지 않았다. Git 명령은 실행하지 않았다.
- 다음 후보: 도전 기록에서 보관한 전투 리플레이로 이동하는 흐름, 사본 복구 전후 캠페인·덱 변경의 상세 비교, 최근 온라인 전투 목록의 날짜·보관 시간 안내.

## 2026-10-13 — 리플레이 선택 구간 클립 공유

- 시작 상태: Git 명령 없이 인덱스·추적 파일 내용 해시와 압축된 HEAD·인덱스 루트 트리를 읽어 비교했다. 미완료 변경·새 소스·문서는 없었다.
