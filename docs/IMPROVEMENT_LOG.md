# 프로젝트 개선 기록

## 2026-10-11 — 구조물 카드의 설치 개수와 제한 사전 안내

- 이번 주제: 구조물 카드에 종류별 설치 개수와 제한 사유를 표시하고, 설치 불가능한 카드 선택을 막으며 빈자리가 생기면 다시 활성화한다.
- 시작 상태: Git 명령 없이 추적 파일과 인덱스의 내용 해시, 인덱스 루트 트리와 HEAD를 읽어 비교했다. 미완료 변경은 없었다.
- 최근 3회차와 다음 후보를 확인했다. 설치 터치·서버 확인 흐름은 유지하고 남은 개수 제한 사전 안내를 선택했다.
- 확인한 문제: 자원만 충분하면 개수 제한에 도달한 카드도 선택할 수 있어, 위치를 찍은 뒤에야 설치 불가를 알 수 있었다.

### 구현한 개선

- 구조물 카드 이름 옆에 현재 아군 설치 개수와 종류별 한도를 표시한다. 비용 배지와 늪의 효과 설명은 유지한다.
- 전체 3개 제한과 종류별 제한을 구분해 카드에 표시하고, 제한에 도달한 카드의 클릭·단축키 선택을 막는다.
- 전체 개수 표시도 같은 계산을 사용하며 한도에 도달하면 강조한다. 적 구조물과 체력 0인 구조물은 제외한다.
- 카드 툴팁에 전체·종류별 개수, 제한 사유, 필요한 추가 자원 또는 설치 방법, 발전기의 후방 규칙을 안내한다.
- 기존 구조물 파괴·늪 만료 후 스냅샷이 갱신되면 개수와 자원에 맞춰 카드를 다시 활성화한다.
- 선택 중 한도에 도달하면 안내와 함께 선택을 해제한다. 서버 확인 중에는 기존 요청의 선택과 대기 표시를 유지한다.
- 모델의 설치 판정·온라인 미리보기·HUD가 같은 개수 및 제한 함수를 사용한다. 종류별 한도는 기존 구조물 데이터에서 읽는다.
- 로컬 설치 성공 직후 스냅샷을 갱신해 개수·자원·카드 상태를 다음 전투 틱까지 기다리지 않고 반영한다.
- README에 개수 표시·한도별 비활성화·다시 설치 가능한 조건과 툴팁 사용법을 설명했다. 이전 1회차를 아카이브로 옮겼다.
- 검토: 관련 소스를 읽어 진영별 집계·죽은 구조물 제외·기존 설치 오류 우선순위·서버 응답 대기·키보드 조작 연결을 검토했다.
- 테스트를 추가·수정·실행하지 않았다. 게임 실행·렌더링도 수행하지 않았으며 실행 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC·세이브·서버 파일 형식·전투 수치·버전 번호·release.json·CHANGELOG·PatchNotes는 유지했다. Git 명령은 실행하지 않았다.
- 다음 후보: 도전 기록의 실제 달력 날짜·완료 시간 로드 검증, 진행도 사본의 내보내기·관리 흐름, 재접속·일시정지 중 구매 카드 상태 안내.

## 2026-10-11 — 프로필 사본 보관과 안전한 진행도 복구

- 이번 주제: 설정에서 현재 진행도 사본을 보관하고, 복구 사본을 확인한 뒤 현재 진행도와 원본을 보존하며 복원한다.
- 시작 상태: 인덱스의 루트 트리와 HEAD, 추적 파일 내용과 인덱스를 Git 명령 없이 읽어 비교했다. 미완료 변경이나 새 파일은 없었다.
- 최근 기록과 다음 후보를 읽고, 아직 구현되지 않은 프로필 복구 흐름을 선택했다. 기존 저장 보호·리플레이·도전 기록 조회는 유지했다.

### 구현한 개선

- 설정 → 데이터에 **진행도 보관·복구**를 추가했다. 현재 메모리의 진행도를 기존 복구 폴더에 사본으로 보관한다.
- 같은 내용의 사본은 재사용한다. 사본·손상 원본은 자동 삭제하지 않으며 전체 초기화 대상임을 안내한다.
- 읽을 수 있는 사본의 파일 보관 시간·닉네임·별·전적·도전 기록 수를 표시하고 복구 전 확인 화면을 제공한다.
- 손상·새 형식·프로필 구조 누락 파일은 목록에서 제외하고 개수와 보관 위치를 안내한다. 목록은 새로고침할 수 있다.
- 복구 전에 현재 메모리 진행도와 디스크 원본의 정확한 바이트를 모두 보관한다. 보관·읽기·원자적 저장 실패 시 현재 진행도를 유지한다.
- 확인한 사본의 내용 지문을 다시 비교한다. 확인 도중 바뀐 파일은 다시 선택하도록 안내한다.
- 전적·진행도·덱·닉네임을 복구하되 현재 설정·익명 ID·전송 대기열을 유지한다. 과거 사본의 대기 결과는 되살리지 않는다.
- 같은 익명 ID의 결과 순번은 현재 메모리·디스크·복구 사본 중 가장 큰 값을 유지해 새 결과가 이미 처리된 것으로 판정되는 일을 막는다.
- 목록과 확인 설명은 스크롤되며 복구·취소 버튼은 고정한다. 실패 안내가 생기면 해당 위치로 스크롤한다.
- README에 사본 보관·복구·수동 수리 사본의 사용법과, 정상 사본이 없으면 손상 전 진행도를 자동 복원할 수 없다는 한계를 설명했다.

### 검토와 다음 후보

- 테스트를 추가·수정·실행하지 않았다. 소스의 저장 실패 분기·기존 원본 보호·화면 전환·전송 대기열 연결을 읽어 검토했으며 실행 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. 기존 저장 스키마·형식 번호·RPC·서버 파일 형식을 유지하며 버전·release.json·CHANGELOG·PatchNotes는 수정하지 않았다. Git 명령은 실행하지 않았다.
- 다음 후보: 도전 기록의 실제 달력 날짜·완료 시간 로드 검증, 많은 도전 기록의 날짜 탐색 편의, 진행도 사본의 내보내기·관리 흐름.
