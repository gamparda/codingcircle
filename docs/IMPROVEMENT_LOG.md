# 프로젝트 개선 기록

## 2026-10-13 — 도전 기록 복원의 날짜·완료 시간 검증

- 이번 주제: 손상된 날짜·완료 시간이 정상 도전 기록을 밀어내거나 0초 최고 기록으로 복원되지 않도록 검증하고, 유효한 이전 버전 기록을 보존한다.
- 시작 상태: Git 명령 없이 인덱스와 추적 파일의 내용 해시, HEAD와 인덱스의 루트 트리를 비교했다. 미완료 소스·문서 변경은 없었고 무시 대상 Python 캐시만 있었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고, 남아 있던 도전 기록의 날짜·완료 시간 로드 검증을 선택했다.
- 확인한 문제: 날짜를 정렬·제한한 뒤 검사해 손상된 날짜가 정상 기록을 밀어낼 수 있었다. 없는 달·날짜와 월요일이 아닌 주간 키도 허용했다.
- 일일 기록은 실제 달력 날짜, 주간 기록은 실제 월요일인지 기존 서버 날짜 검증으로 확인한다. 문자열이 아닌 키도 정렬 전에 제외한다.
- 유효한 날짜와 기록을 먼저 모은 뒤 최근 일일 60일·주간 16주만 남긴다. 손상된 항목은 보관 한도를 소비하지 않는다.
- 성공 여부·점수·완료 시간의 자료형을 검사한다. 성공은 기존 점수 범위 100~3000점, 실패는 기존 규칙대로 0점만 허용한다.
- 누락·음수·무한대·숫자가 아닌 완료 시간을 0초로 바꾸거나 상한값으로 보정하지 않고 해당 버전 기록을 제외한다.
- 실제 0초는 허용하고, 시간 제한이 없는 로컬 전투의 유한한 긴 완료 시간은 자르지 않는다. 서버 제출 시간 한도는 그대로다.
- 주 기록이 손상되어도 유효한 이전 버전 기록을 독립적으로 검증해 살린다. 결정적인 버전 순서로 대표 기록을 골라 기존 저장 구조를 유지한다.
- 이전 기록의 버전은 해당 history 키를 사용하며, 과거 점수를 현재 버전의 최고 기록으로 바꾸지 않는다. 유효한 대표 기록은 같은 버전의 중복보다 우선한다.
- 로드 시 제외한 항목 수를 기존 저장 경고 화면에 안내한다. 전적·덱·설정 등 정상 진행도와 유효한 성공 이력은 유지한다.
- 제외가 있으면 디스크 원본 바이트를 기존 복구 폴더에 보관한다. 보관 실패 시 원본 보호 플래그와 저장 재시도 흐름으로 자동 덮어쓰기를 막는다.
- 도전 시작 안내에 최고 점수를 낸 전투의 시간을 추가했다. 실패 기록은 실패한 전투의 시간으로 별도 안내한다.
- 개인 기록 본문과 시간 툴팁에 최고 점수와 완료 시간의 관계, 동점이면 빠른 성공 기록을 남기는 규칙을 설명한다.
- README를 갱신하고 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다.
- 검토: 생성되는 정상 기록, 버전별 조회·연속 성공·재도전, 원본 보관 실패·저장 재시도·경고 표시 연결을 소스로 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 수행하지 않았다. 기존 손상 시간을 0초로 정규화하는 테스트 기대는 새 제외 정책과 다르므로 외부 검증에서 검토해야 한다.
- 호환성 변경: 없음. 기존 세이브 필드·형식 번호·RPC 시그니처·서버 파일 형식을 유지한다. 손상된 도전 항목의 로드 정책만 강화했다. 버전·release.json·CHANGELOG·PatchNotes는 수정하지 않았고 Git 명령은 실행하지 않았다.
- 다음 후보: 진행도 사본의 내보내기·관리 흐름, 리플레이 병력 기여도의 선택 구간 비교, 도전 기록에서 실패 이력·성공 이력을 빠르게 필터링하는 흐름.
