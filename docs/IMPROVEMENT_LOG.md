# 프로젝트 개선 기록

## 2026-10-11 — 전투 종료 연출의 화면 수명과 재접속 결과 보호

- 이번 주제: 기지 붕괴 연출의 지연 콜백이 재접속·새 전투에 개입하지 않도록 하고, 완료된 결과의 재표시와 중복 기록을 안전하게 처리한다.
- 시작 상태: Git 명령 없이 인덱스와 추적 파일의 내용 해시, 인덱스 루트 트리와 HEAD를 읽어 비교했다. 미완료 변경이나 새 파일은 없었다.
- 최근 3회차와 다음 후보를 읽고, 구매 대기 개선과 구분되는 기지 붕괴 연출·결과 기록 흐름을 선택했다.
- 확인한 문제: 붕괴 타이머가 현재 화면을 참조해 재접속·새 경기의 배속과 결과를 바꿀 수 있었다. 연출 종료 전에는 완료된 경기도 연결 중단으로 집계될 수 있었다.

### 구현한 개선

- 승패 확정 스냅샷을 받으면 연출 시작 전에 전적·도전 점수·별·업적을 반영하고 진행도와 완료 리플레이 저장을 시도한다.
- 기존 저장 실패 안내·메모리 보관·재시도와 익명 결과 전송 대기열을 유지한다. 저장 재시도나 결과 재표시는 집계를 반복하지 않는다.
- 보상 표시용 별·신규 업적·목표·성장 수준·전투 요약을 경기별 메모리에 보관해 재접속 후에도 같은 결과 내용을 보여 준다.
- 붕괴 콜백에 연출 순번과 시작한 전투 화면을 연결한다. 이전 화면의 콜백은 새 경기의 시간 배율·연출·결과를 변경하지 않는다.
- 화면 교체·재접속·직접 결과 표시·노드 종료 시 연출을 취소하고 슬로모션을 즉시 해제한다.
- 재접속 중 결과 표시는 새 전투 상태를 기다린다. 이미 확정한 결과를 다시 받으면 붕괴 연출을 반복하지 않고 결과를 표시한다.
- 완료된 경기의 연결 종료를 중단 전적으로 추가하지 않는다. 확정 후 도착한 진행 중 스냅샷도 결과를 되돌리거나 집계를 다시 열지 않는다.
- 새 AI·도전·드래프트·실험·온라인 경기와 새 관전 시작에서만 결과 상태를 초기화하며, 같은 경기 재접속에서는 보존한다.
- 승패가 확정되면 열려 있던 항복 확인을 닫고 추가 항복을 막아 결과가 뒤바뀌지 않도록 한다.
- README를 갱신하고 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다.
- 검토: 변경 소스와 기존 테스트 내용을 읽어 연출 콜백 수명, 재접속·관전·재경기 분기, 보상·리플레이 저장 순서와 실패 재시도 연결을 검토했다.
- 테스트를 추가·수정·실행하지 않았고 게임 실행·렌더링도 수행하지 않았다. 실행 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식·전투 수치·버전 번호·release.json·CHANGELOG·PatchNotes는 변경하지 않았다. Git 명령은 실행하지 않았다.
- 다음 후보: 도전 기록의 실제 달력 날짜·완료 시간 로드 검증, 진행도 사본의 내보내기·관리 흐름, 온라인 재접속 시 전투 요약 그래프 연속성.

## 2026-10-11 — 온라인 전투 상태 수신 전 구매 대기와 이전 경기 상태 정리

- 이번 주제: 온라인 입장·재접속에서 최신 스냅샷 수신 전 구매를 차단하고, 이전 경기의 자원·승패를 새 전투 화면에서 사용하지 않도록 한다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 내용 해시와 인덱스 루트 트리·HEAD를 읽어 비교했다. 미완료 변경이나 새 파일은 없었다.
- 최근 3회차와 다음 후보를 확인하고, 아직 남아 있던 재접속 후 최신 전투 상태 수신 전 대기를 선택했다.
- 확인한 문제: 전투 화면 생성 시 이전 스냅샷·자원이 남았고 구매 카드가 첫 상태 수신 전에 활성화될 수 있었다. 이전 승패도 새 경기의 구매 차단 판정에 섞였다.

### 구현한 개선

- 온라인 전투 화면에 첫 스냅샷 수신 대기를 추가했다. 카드·클릭·단축키·전장 설치·터치 설치는 기존 공통 판정으로 함께 잠긴다.
- 카드에 **상태 수신 중**, 화면에 **최신 전투 상태를 받는 중**, 자원에 **동기화 중**을 표시하고 툴팁으로 구매 가능 시점을 안내한다.
- 대기 중 자원 막대를 숨기고 구조물 개수를 미확정 표시로 바꾼다. 오래된 자원 부족·생산 대기·설치 한도를 확정된 값처럼 안내하지 않는다.
- 새 전투 화면 생성 시 이전 스냅샷·자원·클라이언트 생산 대기를 정리하고 카드 상태를 즉시 갱신한다.
- 재접속 시작 시 다시 상태 수신 대기로 전환한다. 연결 복구 성공이나 복구 알림만으로 구매를 열지 않는다.
- 화면에 새 스냅샷과 자원을 반영한 뒤 대기를 해제하고 그 스냅샷의 자원·생산 대기·설치 개수로 구매 카드를 갱신한다.
- 상대 복구 대기·관전·승패 확정에 따른 기존 차단은 유지한다. 로컬 AI는 첫 로컬 스냅샷 반영 흐름을 유지하며 화면 이동 시 대기 플래그를 정리한다.
- README에 상태 수신 전 안내와 구매 해제 조건을 설명했다. 이전 1회차를 아카이브로 옮기고 최근 3회차만 남겼다.
- 검토: 소스와 기존 테스트 내용을 읽어 재접속 알림·복구 알림·스냅샷 순서, 새 경기·로컬 재시작·관전·설치 응답·화면 전환 연결을 검토했다.
- 테스트를 추가·수정·실행하지 않았고 게임 실행·렌더링도 수행하지 않았다. 실행 검증은 외부 스크립트에 맡긴다.

- 다음 후보: 도전 기록의 실제 달력 날짜·완료 시간 로드 검증, 진행도 사본의 내보내기·관리 흐름, 재접속 시 기지 붕괴 연출과 결과 기록 중복 처리 점검.

## 2026-10-11 — 전투 중단 사유 안내와 구매 입력 일관성

- 이번 주제: 일시정지·연결 복구·전투 종료 중 구매 카드에 중단 사유와 재개 방법을 안내하고 클릭·단축키·설치 입력의 차단 조건을 통일한다.
- 시작 상태: Git 명령 없이 인덱스와 추적 파일의 내용 해시, 인덱스 루트 트리와 HEAD를 읽어 비교했다. 미완료 변경은 없었고 무시 대상인 Python 캐시만 있었다.
- 최근 3회차와 다음 후보를 확인하고 아직 남아 있던 재접속·일시정지 중 구매 카드 안내를 선택했다.
- 확인한 문제: 중단된 전투에서도 카드가 자원 부족·생산 대기만 표시하거나 상태 표시 없이 비활성화됐다. 결과 연출 중에는 카드·단축키의 종료 차단도 빠져 있었다.

### 구현한 개선

- 병력·구조물 카드에 일시정지·연결 복구 중·복구 대기·관전·전투 종료 사유를 자원·생산 대기·설치 한도보다 우선 표시한다.
- 툴팁에 계속 버튼으로 재개하거나 연결·전투 상태 복구를 기다리는 방법을 안내한다. 병력 스탯과 추가 자원·생산 대기, 구조물 개수·후방 설치 규칙은 유지한다.
- 카드와 클릭·단축키·전장 설치·터치 설치가 같은 중단 판정을 사용한다. 재접속 플래그도 직접 확인해 상태 알림 전 입력을 차단한다.
- 승패가 확정된 스냅샷을 받는 즉시 구매를 차단한다. 기지 붕괴 연출과 결과 화면, 직접 표시되는 연결 종료 결과에서도 카드 상태를 갱신한다.
- 중단 시 미전송 구조물 선택과 진행 중인 터치 설치를 해제하며 사유를 안내한다. 차단된 구조물 콜백이 실행되어도 선택 상태가 바뀌지 않는다.
- 이미 전송한 설치 요청은 선택·서버 확인 대기를 유지한다. 전투 중단 사유와 설치 확인 대기 정보를 툴팁에서 함께 볼 수 있다.
- 상대 복구 대기 중 자신의 연결까지 끊기거나 복구되어도 카드 사유를 다시 갱신한다. 재개 후 최신 자원·생산 대기·설치 한도를 다시 반영한다.
- README에 중단 사유·재개 방법·결과 연출 중 입력 차단을 설명했다. 이전 1회차를 아카이브로 옮기고 최근 3회차만 남겼다.
