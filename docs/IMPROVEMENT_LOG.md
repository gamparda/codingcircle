# 프로젝트 개선 기록

## 2026-10-14 — 도전 기록·보관 전투 읽기와 카드 생성 분산

- 이번 주제: 도전 기록과 보관 전투 선택의 파일 읽기·카드 생성을 프레임마다 나누고 진행 표시·화면 이탈 중단으로 대량 보관에서도 조작을 유지한다.
- 시작 상태: Git 명령 없이 인덱스·작업 파일의 원본/LF 해시와 느슨한 객체·팩 객체의 HEAD 트리를 대조했다. 미커밋·스테이징 변경·충돌이 없어 중단 작업은 없었고 발견한 Python 캐시는 기존 무시 대상이었다.
- 최근 3회차와 아카이브 주제·다음 후보를 읽고 남아 있던 읽기·카드 생성 분산을 선택했다. 구현 전 주제 선기록 시도는 PowerShell 인코딩 때문에 반영되지 않아 작업 중 UTF-8 패치로 바로잡았다.
- 확인한 불편: 도전 탭 진입·개수 새로고침·전투 선택 시 모든 보관 파일 읽기와 카드 생성을 한 번에 처리해 대량 보관에서 입력 처리가 지연됐다.
- 공통 읽기 객체를 추가해 폴더 탐색은 회차당 최대 64개 이름, 파일 읽기는 최대 4개·약 4ms 예산으로 나누고 다음 프레임에 이어 처리한다.
- 파일 하나의 읽기·JSON 검증은 기존 로더를 사용한다. 큰 파일 하나가 예산을 넘을 수 있으며 4ms를 전체 작업의 보장 시간으로 취급하지 않는다.
- 도전 기록 탭은 파일을 읽는 동안 날짜·버전·결과 검색, 페이지·탭 이동과 메인 화면 복귀를 계속 사용할 수 있다. 전투 개수는 읽는 중으로 표시한다.
- 개수 조회에는 전체 명령 로그 직렬화·지문 계산·정렬을 생략하고 날짜·버전 판정에 필요한 작은 메타데이터만 보관한다.
- 개수 새로고침 중에는 이전 조회 개수를 표시하며, 완료 시 기존 숫자 버튼만 갱신해 필터·페이지·스크롤·초점을 유지한다. 비활성화된 선택 버튼의 초점은 목록으로 옮긴다.
- 폴더 접근·목록 읽기 실패는 보관 없음과 구분한다. 기존 조회 개수를 유지하고 보관 새로고침으로 다시 시도할 수 있으며, 처음 저장되지 않은 폴더는 빈 보관함으로 처리한다.
- 전투 선택 창은 먼저 진행 상황·읽기 다시 시작·도전 기록으로 버튼을 표시한 뒤 읽는다. 선택 날짜·일일/주간·버전에 해당하는 파일만 지문과 덱 정보를 준비한다.
- 읽기 완료 후 카드도 최대 두 개 또는 약 4ms마다 양보한다. 준비 중에는 검색·분석·재생을 잠그고 새로고침·닫기·Esc·Tab 조작을 유지한다.
- 날짜와 다른 확인 버전은 제외하고 미상 버전은 별도 그룹에 남긴다. 각 그룹의 최신 보관순과 기존 덱·클립·결과 안내를 유지한다.
- 화면 이탈·오버레이 교체·읽기 재시작은 디렉터리를 닫고 남은 작업을 중단한다. 카드는 새 배치를 시작하기 전과 대기 후에 부모의 삭제 대기까지 확인한다.
- 재생·점수 분석 직전의 파일 재읽기·지문 대조와 변경·삭제된 전투의 분석 해제, 메모만 바뀐 전투의 완료 분석 재사용을 유지한다.
- 완료 후 검색 조건·스크롤·선택 카드 초점을 복원한다. 카드 준비 중 직접 조작하면 지연된 자동 복원을 취소하며, 닫을 때는 개수 조회가 끝난 원래 도전 행도 다시 찾아 복귀한다.
- 기존 동기 조회 함수의 호출 형식과 반환 데이터를 유지하고 실제 화면 경로만 분산 로더로 전환했다. 기록·리플레이·프로필에 쓰거나 서버에 요청하지 않는다.
- README 사용법을 반영하고 가장 오래된 회차를 아카이브로 옮겨 최근 3회차만 남겼다. 소스로 호출·수명·필터·초점·재생 복귀 경로를 검토했다.
- 테스트 추가·수정·실행과 게임 실행·렌더링은 하지 않았다. 실제 로드·입력·대량 파일·권한 오류·닫기·연속 새로고침·재생 복귀 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식과 버전 번호·release.json·CHANGELOG·PatchNotes를 유지했다. Git 명령은 실행하지 않았다.
- 다음 후보: 도전 보관 전투의 페이지별 카드 제한, 복구 비교에서 특정 감소 경고의 상세로 바로 이동하는 흐름, 리플레이 시점별 병력 역할 구성 비교.

## 2026-10-14 — 병력 현황의 역할별 구성 비교와 종류 좁혀 보기

- 이번 주제: 양쪽 생존 병력을 근접 전열·원거리 공격·공속 지원·소환 지휘로 비교하고 역할을 눌러 해당 병력 종류만 확인한다.
- 시작 상태: Git 명령 없이 인덱스·작업 파일의 원본/LF 해시와 느슨한 객체·팩 객체의 HEAD 트리를 대조했다. 미커밋·스테이징 변경·충돌·미추적 파일이 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브 주제를 읽고 다음 후보 중 역할별 구성 안내를 선택했다. 주제 선기록의 인코딩을 UTF-8로 바로잡은 뒤 구현했다.
- 확인한 불편: 종류별 생존 수는 확인할 수 있지만, 양쪽의 근접·원거리·지원 구성을 비교하려면 여러 종류의 숫자를 직접 합해야 했다.
- 병력 현황에 역할별 생존 인원과 각 진영 전체 생존 병력 중 비율을 나란히 표시한다. 기본 화면에서는 네 역할을 모두 비교한다.
- 근접 전열은 탱커·전사·광전사·해골, 원거리 공격은 궁수·흑마법사, 공속 지원은 마법사, 소환 지휘는 네크로맨서로 분류한다.
- 각 종류는 한 역할에만 집계한다. 해골은 근접 전열에 포함하고 네크로맨서와 중복 계산하지 않으며, 소환 포함 표시와 역할 설명을 함께 제공한다.
- 비율은 해당 진영의 전체 생존 인원이 분모이며 정수로 반올림한다. 생존 병력이 없는 진영은 0명·비율 —로 표시해 0으로 나누지 않는다.
- 사망 후 정리 대기는 역할별 생존 구성에 넣지 않고 기존 공유 한도·정리 대기 안내에 남긴다. 병력 수를 전투력·승률로 추정하지 않는다.
- 목록 위의 역할 버튼을 누르면 해당 역할의 요약·종류만 표시한다. 같은 버튼을 다시 누르거나 모든 병력 보기로 전체 목록에 돌아간다.
- 역할을 선택하면 포함된 종류와 능력 설명을 표시한다. 생존 수가 0명인 종류·미출전 병력·소환 병력도 해당 목록에서 확인할 수 있다.
- 선택한 역할은 체크 표시와 금색으로 구분하고 역할 변경 시 목록 처음부터 읽는다. 버튼은 터치 높이 58과 놓기 시 동작을 유지한다.
- Tab·Shift+Tab은 현재 보이는 조작만 순환해 필터로 숨긴 병력 버튼에 초점을 주지 않는다. 기존 방향키·PageUp/PageDown·Home/End·Esc 경로를 유지한다.
- 종류 이름·진영별 숫자는 기존 스탯 바로가기를 사용한다. 돌아오면 역할 선택·진영·스크롤·초점을 함께 복원하며 역할 변경은 지연된 이전 복원을 취소한다.
- 역할 선택은 화면 간 복귀용 임시 정보만 사용한다. 새로 현황을 열 때는 전체 보기이며 기존 유닛 스탯의 검색·분류 기록을 덮어쓰지 않는다.
- 긴 공통 안내를 목록 안으로 옮겨 역할 버튼과 병력 목록의 공간을 확보했다. 자원·회복·생산 조건과 진영별 전체 생존 수는 기존 표시를 유지한다.
- 온라인 입장·재접속·복구 대기에는 역할 인원·비율을 —로 표시한다. 관전과 아군이 오른쪽인 전투도 기존 실제 진영 순서를 사용한다.

- README에 사용법을 반영하고 가장 오래된 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 집계·필터·입력·스탯 왕복·상태 수신 경로를 소스로 검토했다.
- 테스트 추가·수정·실행과 게임 실행·렌더링은 하지 않았다. 실제 로드·배치·터치·키보드·스탯 복귀·재접속 검증은 외부 스크립트에 맡긴다.

## 2026-10-14 — 도전 보관 전투의 개별 검색 조건 해제

- 이번 주제: 검색 결과가 없어도 카드 밖에서 전체·내 덱·상대 덱 검색어를 하나씩 해제하고 다른 조건과 탐색 흐름을 유지한다.
- 시작 상태: Git 명령 없이 인덱스와 작업 파일의 원본/LF 해시, 느슨한 객체·팩 객체의 HEAD 트리를 대조했다. 미커밋·스테이징 변경·충돌·미추적 파일이 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 주제·다음 후보를 읽고, 조건을 추가하면 해제 카드까지 숨겨지는 불편을 선택했다. 구현 전 주제 선기록은 PowerShell 인코딩 오류로 반영되지 않아 원본 복구 후 UTF-8로 바로잡았다.
- 확인한 불편: 카드에서 덱 조건을 고른 뒤 결과가 없어지면 같은 카드의 해제 버튼도 사라져 검색칸을 직접 수정하거나 모든 조건을 초기화해야 했다.
- 도전 보관 전투 선택 창의 검색칸 아래에 전체·내 덱(블루)·상대 덱(레드) 검색어별 해제 버튼을 추가했다.
- 버튼은 결과 카드 밖에 남아 검색 결과 0개·보관 전투 없음에서도 사용한다. 검색어가 모두 없으면 행을 숨긴다.
- 덱의 영문 ID는 기존 병력·구조물 한글 이름으로 표시하고 전체 검색·직접 입력한 부분 검색어는 입력한 단어를 표시한다.
- 같은 칸의 중복·대소문자 변형은 하나의 버튼으로 표시하고 해제할 때 함께 지운다. 탭·줄바꿈·공백 분리는 기존 검색 판정과 맞춘다.
- 선택한 단어만 정확히 지우고 부분 검색어·다른 검색칸·결과·클립 조건과 날짜·버전 범위는 유지한다.
- 기존 필터 갱신을 한 번만 호출해 표시 개수·빈 결과 안내·카드 개별 항목·전체 덱 선택 표시를 함께 갱신한다.
- 완료된 점수 분석과 기존 분석 취소 조건을 유지한다. 해제 자체로 파일을 다시 읽거나 전투를 재현하지 않는다.
- 버튼 행은 한 줄의 가로 스크롤로 높이를 제한하고 터치 크기·드래그 여유·버튼 놓기 시 동작을 적용했다.
- Tab·Shift+Tab·방향키 탐색에는 현재 버튼만 포함한다. Enter·Space로 해제하고 새 버튼의 Esc도 기존 도전 기록 복귀에 연결한다.
- 해제한 버튼의 초점은 가까운 남은 단어로, 마지막 단어는 결과 스크롤로 이동한다. 검색칸으로 자동 이동해 터치 키보드를 열지 않는다.
- 남아 있는 버튼은 재사용하고 없어지는 버튼만 제거한다. 버튼 이름을 검색칸·단어 기준으로 고정해 새로고침 시 초점 복원과 연결했다.
- 개별 해제는 읽던 목록 위치를 유지하며 지연된 이전 복원을 취소한다. 연속 해제·후속 검색·창 닫기에서는 오래된 위치 복원을 적용하지 않는다.
