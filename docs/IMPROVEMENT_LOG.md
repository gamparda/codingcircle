## 2026-10-13 — 진행도 복구 전후 캠페인·덱 상세 비교

- 이번 주제: 사본 선택·가져오기·복구 확인에서 캠페인 단계별 기록과 세 덱의 변경을 비교해 복구 결과를 미리 확인한다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 해시와 HEAD·인덱스 루트 트리를 비교했다. 미완료 변경·새 소스·문서는 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고, 남아 있던 사본 복구 전후 캠페인·덱 상세 비교를 선택했다.
- 확인한 문제: 사본과 현재 진행도의 총계만 보여 어떤 단계의 기록이 줄고 어떤 덱으로 바뀌는지 복구 전에 파악하기 어려웠다.
- 사본 선택 화면·클립보드 가져오기 확인·최종 복구 확인에 동일한 현재 → 사본 비교를 추가했다.
- 비교는 복구에 쓰이는 정규화된 값을 사용하며 원본 사본과 현재 진행도를 수정하지 않는다.
- 캠페인에서 변경된 단계만 이름과 함께 표시하고 클리어·별·최단 승리 시간·최고 기지 체력·시도/승리 횟수를 비교한다.
- 변경된 캠페인 기록 수·덱 구성 수·개방 단계·총 별을 요약한다. 변경이 없는 캠페인과 덱은 변경 없음을 안내한다.
- 개방 단계가 줄어 다시 잠기는 캠페인과 줄어드는 클리어·별을 별도 경고로 표시한다.
- 일부 단계의 별 증가가 다른 단계의 감소를 가리지 않도록 감소분은 단계별로 합산한다.
- 클리어 수가 달라지면 기존 전투 모델의 성장 공식을 사용해 병력 강화·자원 수입·보유 한도·시작 자원의 변화를 표시한다.
- 세 덱을 슬롯별로 비교하고 변경된 이름·병력·구조물을 게임 내 이름으로 보여 준다.
- 같은 병력·구조물의 순서 변경도 표시한다. 전투 버튼·키보드 슬롯 순서가 바뀌는 의미를 안내한다.
- 최근 선택 덱 슬롯의 변경을 표시하고, 최단 승리 0초는 미기록과 구분할 수 없음을 드러낸다.
- 복구가 높은 기록을 합치는 작업이 아니라 전적·업적·도전 기록을 포함한 진행도 전체 교체임을 안내한다.
- 긴 비교는 기존 세로 스크롤 안에서 줄바꿈한다. 확인·취소 버튼과 키보드 스크롤·Tab·Esc 조작은 기존 흐름을 사용한다.
- 사본 선택이 유효하지 않으면 비교를 숨기고 복구를 막는다. 재선택 시 이전 비교 노드를 제거해 새 사본 내용만 표시한다.
- 기존 원본 보관·파일 지문 재확인·저장 실패 보호·설정/익명 ID/전송 대기 기록 유지 흐름은 그대로 사용한다.
- README를 갱신하고 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 비교 데이터·화면 연결·성장 수치·복구 정책을 소스로 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 실제 로드·표시·조작 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식과 버전 번호·release.json·CHANGELOG·PatchNotes는 변경하지 않았다. Git 명령은 실행하지 않았다.
- 다음 후보: 최근 온라인 전투 목록의 날짜·보관 시간 안내, 도전 전투의 점수 근거를 리플레이 선택 창에서 확인하는 흐름, 사본 복구 전후 도전 기록의 날짜·버전별 상세 비교.

## 2026-10-13 — 도전 기록에서 보관 전투 찾아보기

- 이번 주제: 일일·주간 기록에서 같은 날짜의 보관 전투를 열고, 버전 확인과 기록 화면 복귀를 지원한다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 해시와 HEAD·인덱스 루트 트리를 비교했다. 미완료 변경·새 소스·문서는 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고, 남아 있던 도전 기록에서 보관 전투로 이동하는 흐름을 선택했다.
- 확인한 문제: 도전 최고 기록과 리플레이 보관함이 분리돼 날짜를 다시 찾아야 했고, 기존 리플레이에는 콘텐츠 버전이 없었다.
- 일일·주간 기록마다 보관 전투 개수와 열기 버튼을 추가했다. 읽을 수 있는 전투가 없으면 보관 없음과 저장 실패·정리·삭제 가능성을 안내한다.
- 같은 UTC 날짜·도전 종류로 조회하고 기록과 다른 버전으로 확인된 전투는 제외한다. 기존 period 없는 도전 리플레이는 일일로 읽는다.
- 버전 확인된 전투를 먼저, 버전 미상 전투를 별도 그룹으로 표시한다. 각 그룹에서 기존 로컬 순번·경로 기준 최신 보관순을 유지한다.
- 선택 창에 성공/실패·점수·완료 시간을 표시한다. 후보의 승패·전투 시간·파일명·보관 날짜를 비교하고 전체 경로는 툴팁으로 제공한다.
- 클립도 포함하고 전체 전투 결과·시작–끝·클립 길이를 구분한다. 재생은 기존 클립 시작·끝 정지·이어 보기 흐름을 사용한다.
- 기록과 결과·완료 시간이 일치하면 표시하지만 최고 점수의 전투라고 단정하지 않는다. 날짜·시간 일치는 전투 식별자가 아니며 버전 미상은 추정하지 않는다.
- 새 일일·주간 리플레이에 시작 당시 ruleset을 선택 메타데이터로 남기고 기존 버전 문자열 검증 규칙을 적용한다. 버전 없는 기존 파일은 계속 읽는다.
- 기록 화면에서는 도전 탭 첫 진입 때 한 번 읽고 표시용 메타데이터·지문만 유지한다. 검색·필터·페이지 이동마다 파일을 다시 읽지 않는다.
- 보관 새로고침은 조건·페이지·스크롤을 유지한다. 선택 창 진입·새로고침 때 파일을 다시 조회하고 손상되거나 삭제된 후보는 제외한다.
- 재생 직전에 파일을 다시 읽고 전체 내용 지문을 비교한다. 삭제·읽기 실패·내용 변경이면 기록 화면에 남겨 새로고침 후 재선택을 안내한다.
- 선택 창은 터치·휠·방향키·Page Up/Down·Home/End 스크롤, Tab 초점 순환, Esc 닫기를 지원한다. 재생·새로고침·돌아가기 높이는 58이다.
- 재생 후 기록 탭·날짜 검색·버전/결과 조건·페이지·스크롤·초점을 복원한다. 화면 수명과 복원 순번을 확인해 닫힌 화면의 지연 복원을 막는다.
- 기록 탐색 상태는 Main의 세션 메모리에만 둔다. 일반 리플레이의 보관함 복귀·메모 저장·목표 달성·되감기 실험 흐름은 유지한다.
- README를 갱신하고 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 조회·버전 판별·클립 표시·파일 재확인·화면 복귀를 소스로 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 수행하지 않았다. 실제 로드·표시·조작 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 로컬·공유 리플레이의 meta.ruleset 선택 필드 추가. 형식 번호·공유 접두사는 유지하며 기존 파일을 읽고 기존 리더는 추가 필드를 무시한다. RPC 시그니처·프로필 세이브·서버 파일 구조는 변경하지 않았다.
- 버전 번호·release.json·CHANGELOG·PatchNotes는 변경하지 않았고 Git 명령은 실행하지 않았다.
- 다음 후보: 사본 복구 전후 캠페인·덱 변경의 상세 비교, 최근 온라인 전투 목록의 날짜·보관 시간 안내, 도전 전투의 점수 근거를 리플레이 선택 창에서 확인하는 흐름.

## 2026-10-13 — 온라인 리플레이 코드 요청과 화면 수명 보호

- 이번 주제: 코드 열기·최근 전투 보기·코드 공유의 중복 요청을 막고, 닫힌 화면의 늦은 응답을 안전하게 정리한다.
- 시작 상태: Git 명령 없이 인덱스와 추적 파일 내용 해시를 비교하고 인덱스의 트리 해시를 HEAD와 대조했다. 미완료 변경·새 소스·문서는 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고, 남아 있던 온라인 리플레이 요청의 중복 클릭·화면 수명 관리를 선택했다.
- 확인한 문제: 코드 발급·최근 전투 보기에서 클릭마다 응답 구독과 요청이 늘어났고, 닫힌 화면의 콜백이 재생이나 클립보드 변경을 수행할 수 있었다.
- 코드 열기는 입력한 코드와 응답 코드를 대조한다. 다른 코드의 늦은 응답은 무시한다.
- 코드 입력을 기존 서버의 허용 문자·길이 규칙으로 확인하고 잘못된 입력은 접속 전에 안내한다. 요청 중 입력과 열기 버튼을 잠근다.
- 연결 실패·찾을 수 없는 코드·응답 시간 초과 후에는 입력과 버튼을 다시 활성화한다. 닫기 버튼은 요청 중에도 사용할 수 있다.
- 네트워크 노드 아래에 응답 채널별 요청을 관리한다. 화면이 바뀌어도 요청 구분에 필요한 상태는 유지하고 화면 콜백은 분리한다.
- 소유 컨트롤과 모든 상위 노드의 삭제 예약까지 확인해 같은 프레임에 닫힌 화면으로 응답이 돌아오는 경우를 차단한다.
- 최근 전투 보기도 요청 코드가 일치할 때만 재생한다. 같은 버튼의 중복 클릭과 다른 전투의 동시 요청을 막고 이유를 안내한다.
- 최근 온라인 목록에 새로고침을 추가했다. 요청 중 비활성화하고 실패 후 다시 활성화하며 기존 목록을 유지한다.
- 목록 교체 시 이전 행을 즉시 트리에서 분리해 그 행에 연결된 보기 요청의 화면 콜백도 해제한다.
- 코드 발급은 채널 전체에서 한 번에 하나만 보낸다. 응답에 요청 식별자가 없어 다른 전투에 늦은 코드가 붙지 않도록 한다.
- 발급이 끝난 카드의 코드를 다시 누르면 추가 업로드 없이 복사한다. 공유 내용의 해시가 달라지면 새로 발급한다.
- 발급 지연·화면 닫기 후에도 전송한 요청은 응답을 소진하거나 연결이 바뀔 때까지 유지한다. 같은 내용은 추가 전송 없이 다시 응답을 기다릴 수 있다.
- 다른 전투의 발급은 이전 응답을 기다리도록 안내하고 복사 공유를 제공한다. 연결을 임의로 끊어 진행 중인 온라인 활동을 중단하지 않는다.
- 응답 대기는 전송 후 12초로 제한한다. 시간 초과·서버 연결 변경·응답 완료 시 버튼 상태와 구독을 정리하고, 닫힌 화면의 클립보드 변경을 막는다.
- 새 입력·열기·닫기·새로고침·보기 조작은 최소 높이 58을 적용했다. 긴 상태 안내와 전투 설명은 줄바꿈한다.
- README를 갱신하고 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 요청·응답·화면 정리·연결 전환·시간 초과 흐름을 소스로 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 수행하지 않았다. 실제 로드·표시·네트워크 검증은 외부 스크립트에 맡긴다.
