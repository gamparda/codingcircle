# 프로젝트 개선 기록

## 2026-10-14 — 리플레이 보관 용량 안내와 큰 파일 탐색

- 이번 주제: 보관함의 전체·일반·정리 제외·읽기 실패 파일 용량과 개수를 안내하고, 큰 파일부터 정렬해 보존한 전투를 관리한다.
- 시작 상태: Git 명령 없이 인덱스와 추적 파일의 원본/LF 해시를 비교했다. 변경·미추적 소스·문서가 없었고, 압축 HEAD 객체를 읽어 인덱스 루트 트리와 일치함을 확인해 중단 작업이 없음을 확인했다.
- 최근 3회차와 아카이브의 다음 후보를 읽고 남아 있던 보관 용량·개수 안내를 선택했다. 소스 수정 전에 이번 주제를 한 줄 먼저 기록했다.
- 확인한 불편: 정리 제외한 전투는 계속 누적되지만 차지하는 용량과 큰 파일을 구분할 안내·정렬이 없었다.
- 보관함 상단에 전체 파일 개수와 용량, 일반·정리 제외·읽기 실패의 개수와 용량을 항상 표시한다. 검색 조건과 관계없는 전체 현황이다.
- 검색·필터 결과 개수 옆에는 표시된 파일의 합계 용량을 안내한다. 보존 필터와 함께 큰 파일이 차지하는 비중을 확인할 수 있다.
- 정상 전투·클립 카드와 읽기 실패 카드에 파일 크기를 표시한다. 정상 카드의 도움말에는 정확한 바이트 수와 실제 파일 경로도 안내한다.
- B·KiB·MiB·GiB·TiB로 크기를 표시한다. 클립도 전체 전투·메모를 포함하며 파일 크기는 디스크 사용량·남은 저장 공간과 다름을 안내한다.
- 파일 소실·접근 실패·링크 등으로 크기를 확인하지 못하면 0으로 계산하지 않고 용량 미상으로 표시한다. 일부 미상 합계는 확인한 최소 용량과 미상 개수를 안내한다.
- 최근 보관순·오래된 보관순·용량 큰 순을 추가했다. 크기가 같으면 최근 보관순과 파일명으로 순서를 고정하며, 미상 크기는 큰 순 정렬의 마지막에 둔다.
- 정리 제외만 필터와 큰 순 정렬로 용량이 큰 보존 전투를 살펴볼 수 있다. 보존 해제·삭제는 기존 카드의 확인창을 거친다.
- 새로고침·재생 복귀·메모 수정·삭제·보존 변경 후 정렬을 유지한다. 정렬은 세션 상태에만 두고 초기화·가져오기 성공 시 최근 보관순으로 돌아간다.
- 기존 카드를 재배치해 정렬하며 파일·버튼 식별과 카드 위치·키보드 초점 복원을 유지한다. 정렬 변경 때는 목록 맨 위로 이동한다.
- 크기는 목록을 읽을 때 파일 길이만 조회한다. 검색·필터 조작은 읽어 둔 값을 합산하고 정렬 변경 때만 카드를 재배치해 파일 재조회·전투 분석을 추가하지 않는다.
- 저장·자동 정리·수동 정리의 대상과 보관 순서는 유지한다. 정리 제외·읽기 실패 보존, 파일 지문 확인과 직접 삭제 확인도 유지한다.
- README를 갱신하고 오래된 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 소스로 집계·미상 크기·동률 정렬·빈 목록·초점 복원·의존성을 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 실제 로드·크기 표시·정렬·키보드·터치·삭제·보존 회귀 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식과 버전 번호·release.json·CHANGELOG·PatchNotes를 유지했다. Git 명령은 실행하지 않았다.
- 다음 후보: 긴 복구 비교의 항목별 접기·펼치기, 보관함에서 내 덱·상대 덱을 구분해 검색하는 흐름, 큰 보관함에서 화면 밖 카드 생성을 지연해 진입 부담을 줄이는 흐름.

## 2026-10-13 — 리플레이 보관함의 카드 초점과 탐색 위치 복원

- 이번 주제: 보관 전투 재생·새로고침·카드 조작 후 같은 카드의 키보드 초점과 탐색 위치를 복원하고, 파일 소실 시 안전한 목록 탐색을 유지한다.
- 시작 상태: Git 명령 없이 인덱스를 읽어 추적 파일의 원본/LF 해시를 비교했다. 작업 트리 변경·충돌 항목·미추적 소스·문서가 없어 중단 작업은 없었다. HEAD 객체가 압축 보관되어 인덱스와 HEAD 비교는 수행하지 못했다.
- 최근 3회차와 아카이브의 다음 후보를 읽고 아직 남아 있던 로컬 보관함의 재생 후 카드 복귀를 선택했다. 소스 수정 전에 주제를 먼저 기록했다.
- 확인한 불편: 검색·필터·스크롤만 남고 재생 후 키보드 초점이 사라졌다. 새 파일이 목록 앞에 추가되면 같은 스크롤 수치에서도 다른 전투가 보였다.
- 재생을 누를 때 해당 파일과 재생 버튼을 기억한다. 나가기는 보관함의 같은 전투 재생 버튼으로 돌아오며 뷰어 나가기 도움말에도 복귀 위치를 표시한다.
- 파일 경로와 카드 안의 버튼 이름으로 초점을 찾는다. 중복 카드 이름·자동 생성된 컨테이너 이름·새 파일에 따른 생성 순서에 의존하지 않는다.
- 검색칸·종류·결과·클립·보존 조건·새로고침·보관 안내·하단 버튼의 초점도 화면 재생성 후 복원한다. 상태는 기존 세션 딕셔너리 안에만 둔다.
- 스크롤할 때 첫 표시 카드의 파일과 화면 내 상대 위치를 기억한다. 새 전투가 위에 추가되어도 해당 카드 위치를 유지한다.
- 기준 카드가 없어지면 기존 스크롤 수치를 현재 범위 안으로 제한한다. 복원한 카드 조작은 화면 안에 보이도록 보정한다.
- 메모 수정으로 검색에서 제외되거나 파일이 사라지면 다른 전투의 재생·삭제 버튼을 자동으로 선택하지 않는다. 검색칸으로 초점을 옮기고 상태 안내를 표시한다.
- 재생 직전 파일을 읽지 못하면 보관함을 다시 읽고 재생 실패를 명시한다. 읽기 실패 카드의 기존 직접 삭제 확인은 유지한다.
- 직접 삭제 후 가까운 남은 카드, 보존 변경 후 같은 카드의 보존 버튼, 정리 후 재시도·검색칸으로 돌아가는 기존 규칙을 공통 복원 처리와 연결했다.
- 컨테이너 배치와 초점에 따른 지연 스크롤 이후 위치를 적용한다. 초기 배치 중 스크롤 값으로 이전 탐색 기록을 덮어쓰지 않는다.
- 복원 대기 중 키보드·마우스·터치 입력이 들어오면 예약을 취소한다. 사용자가 새로 조작한 초점과 위치를 우선한다.
- 확인창 초점은 보관함 기록을 덮어쓰지 않는다. 복원 중 확인창이 열려도 그 초점은 유지하고 뒤의 보관함 위치만 복원한다.
- 삭제 예약된 화면과 배경을 확인하고 복원 회차를 비교한다. 이전 화면의 콜백이 새 화면의 상태·초점·스크롤을 바꾸지 않게 한다.
- 기존 검색 변경 시 맨 위 이동, 가져오기 성공 시 조건 초기화, 파일 지문 확인, 보존·삭제·정리 범위와 공유 동작은 유지한다. 탐색에 파일 저장·서버 요청을 추가하지 않았다.
- README의 보관함 사용법을 갱신하고 오래된 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 소스로 초점 식별·배치 순서·콜백 수명·필터 제외·파일 소실 경로를 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 실제 로드·키보드·터치·재생 복귀·메모·새로고침 회귀 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식과 버전 번호·release.json·CHANGELOG·PatchNotes를 유지했다. Git 명령은 실행하지 않았다.
- 다음 후보: 오래된 보존 전투를 한눈에 관리하는 보관 용량·개수 안내, 긴 복구 비교의 항목별 접기·펼치기, 보관함에서 내 덱·상대 덱을 구분해 검색하는 흐름.

## 2026-10-13 — 복구 사본 탐색 위치와 초점 복원

- 이번 주제: 사본 새로고침·보관·가져오기·삭제·복구 후 선택과 비교 위치·키보드 초점을 복원하고, 결과 안내를 읽으면서 살펴보던 위치를 유지한다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일의 원본/LF 해시와 HEAD 루트 트리를 비교했다. 미커밋 변경·미추적 소스·문서가 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고 남아 있던 복구 사본 탐색 상태 복원을 선택했다. 소스 수정 전에 이번 주제를 먼저 기록했다.
- 확인한 불편: 선택 파일·검색 조건은 남지만 화면 재생성 때 스크롤·초점이 사라졌고, 완료 안내가 긴 비교 내용 아래로 화면을 이동시켰다.
- 새로고침·사본 보관·가져오기·삭제·복구 이후 같은 화면의 스크롤 위치와 버튼·입력칸 초점을 복원한다. 다른 메뉴로 나가면 탐색 상태는 끝난다.
- 완료·실패·클립보드 내보내기 안내를 스크롤 밖에 배치했다. 비교 내용을 읽던 위치에서 결과를 확인하며 안내를 찾으러 아래로 이동하지 않는다.
- 스크롤 영역의 키보드 초점과 방향키·Page Up/Down·Home/End 탐색을 추가했다. 입력칸과 목록의 기존 편집·선택 키는 유지한다.
- 컨테이너 배치와 초점에 따른 지연 스크롤이 끝난 뒤 위치를 복원한다. 목록 길이가 바뀌면 현재 스크롤 범위 안으로 제한한다.
- 복원 대기 중 키보드·마우스·터치 조작이 들어오면 예약된 복원을 취소해 사용자의 새 탐색을 우선한다.
- 화면과 배경의 삭제 예약·회차를 확인해 다른 메뉴로 이동한 뒤 이전 화면의 지연 콜백이 초점이나 위치를 바꾸지 않게 한다.
- 확인창의 초점은 목록의 초점 기록을 덮어쓰지 않는다. 취소는 기존 진입 버튼으로 돌아오고 성공 후 화면 재생성은 목록의 기록을 사용한다.
- 기존 초점 대상이 없거나 숨김·비활성화 상태면 사본 선택 목록으로 돌아온다. 목록이 비면 검색칸으로 이동하고 보이는 위치를 확보한다.
