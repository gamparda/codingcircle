# 프로젝트 개선 기록

## 2026-10-13 — 진행도 복구 전 전적·업적의 상세 감소 안내

- 이번 주제: 사본 선택·가져오기·복구 확인에서 전적의 항목별 변화와 사라지는 업적 이름을 보여 주어 복구로 잃는 기록을 미리 확인한다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 해시와 HEAD·인덱스 루트 트리를 비교했다. 미커밋 변경과 미추적 소스·문서는 없었다.
- 최근 3회차·아카이브와 다음 후보를 읽고 아직 남아 있던 전적·업적의 구체적인 감소 안내를 선택했다. 구현 전에 주제를 로그에 먼저 기록했다.
- 확인한 문제: 사본의 경기 수와 업적 개수만 보여 주어 승리·연승이 줄거나 업적 총수가 같아도 달성한 업적이 사라지는 것을 알기 어려웠다.
- 전적 비교에 AI 경기·승패, 최고 캠페인, 온라인 완료·승패·무승부·중단, 현재·최고 연승, 일일·주간 누적 성공의 13개 항목을 추가했다.
- 변경된 항목마다 현재 → 사본 값과 단위·증가/감소량을 표시하며 감소·증가·동일 항목 수를 함께 안내한다. 총 별은 기존 캠페인 비교를 사용한다.
- 줄어드는 전적의 항목명과 감소량을 상단 경고로 표시한다. 다른 항목의 증가로 감소분을 상쇄하지 않는다.
- 패배·중단 횟수 감소도 저장된 기록 감소로 표시하되, 실력이 낮아졌다는 뜻이 아님을 상세 비교에 설명한다.
- 업적은 개수나 타임스탬프의 참/거짓 대신 ID의 존재로 달성 여부를 비교한다. 시각이 0인 기존 업적도 달성으로 유지한다.
- 현재 달성한 업적이 사본에 없으면 이름·현재 달성 시각·미달성 상태·달성 조건을 보여 주고 상세 목록에서 먼저 표시한다.
- 사라지는 업적 이름과 개수를 상단에 경고한다. 사본에 새로운 업적이 있어 총수가 같거나 증가해도 기존 업적의 상실을 숨기지 않는다.
- 사본에서 추가되는 업적과 양쪽 모두 달성한 업적의 시각 변경을 별도로 표시한다. 시각만 바뀌는 업적은 상실 경고로 세지 않는다.
- 달성 시각은 기존 UTC 표기를 사용하며 0은 달성 시각 미상으로 안내한다. 양쪽 모두 같은 달성 기록의 개수와 변경 없음도 표시한다.
- 실제 복구와 같은 정규화된 프로필을 비교하며 업적 정의의 이름·조건을 재사용한다. 비교는 원본·사본·현재 진행도를 수정하지 않는다.
- 사본 선택·클립보드 가져오기 확인·최종 복구 확인의 공통 비교에 연결했다. 감소 항목은 경고색과 글자로 함께 구분하며 좁은 화면에서 줄바꿈한다.
- 기존 스크롤·Tab·Esc, 캠페인·덱·도전 비교, 사본 지문 확인과 복구 전 보관·저장 실패 처리는 유지한다. 새 조작 버튼은 추가하지 않는다.
- README를 갱신하고 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 정규화·카운터 의미·업적 판정·세 화면 연결·기존 저장 경로를 소스로 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 실제 로드·표시·조작 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식을 유지한다. 버전 번호·release.json·CHANGELOG·PatchNotes는 수정하지 않았고 Git 명령은 실행하지 않았다.
- 다음 후보: 도전 보관 전투 카드의 덱 구성 사전 표시, 온라인 전투 다운로드를 창을 닫지 않고 취소하는 조작, 복구 비교에서 시작 목표·튜토리얼 완료 상태의 변화 안내.

## 2026-10-13 — 최근 온라인 전투의 보기 요청 유지와 상태 안내

- 이번 주제: 최근 온라인 전투 목록을 새로고침하거나 필터링해도 선택한 보기 요청을 유지하고, 진행·실패 상태와 재시도 방법을 화면에 안내한다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 해시와 HEAD·인덱스 루트 트리를 읽었다. 미커밋 추적 파일 변경과 미완료 소스·문서는 없었다.
- 최근 3회차와 아카이브의 다음 후보를 읽고 남아 있던 온라인 전투 보기 요청 안내를 선택했다. 구현 전에 주제를 로그에 먼저 기록했다.
- 확인한 문제: 보기 요청의 소유자가 카드 버튼이어서 새로고침으로 행을 교체하면 응답 관찰이 끊기고, 실패 안내도 목록 갱신 메시지에 덮였다.
- 최근 온라인 전투 목록에서는 보기 요청의 소유자를 선택 창으로 옮겼다. 목록 조회와 전투 다운로드는 기존의 별도 응답 채널을 사용한다.
- 보기 요청 상태는 창에만 두며 현재 코드·진행 메시지·진행/실패 여부를 기억한다. 재생 데이터나 카드 노드를 세션·세이브에 보관하지 않는다.
- 상단에 요청 코드와 접속·응답 대기·실패 이유를 표시한다. 목록 갱신 상태와 분리해 서로의 안내를 덮지 않는다.
- 선택 카드에도 진행·실패 이유를 줄바꿈해 표시한다. 터치 환경에서도 툴팁 없이 실패 이유를 읽을 수 있다.
- 목록 새로고침 뒤 새 카드에 요청 상태와 버튼 잠금을 다시 적용한다. 진행 중인 요청을 다시 전송하지 않는다.
- 검색·종류·결과 조건으로 선택 카드가 숨겨지거나 최신 목록에서 제외되어도 다운로드를 유지하며 상단에 이유를 안내한다.
- 불러오는 동안 모든 보기 버튼을 잠그고 선택한 전투에 불러오는 중을 표시한다. 코드 복사·검색·필터·새로고침·닫기는 유지한다.
- 연결 실패·응답 시간 초과·읽을 수 없는 전투는 잠금을 해제하고 선택 카드에 재시도를 표시한다. 다른 전투도 바로 선택할 수 있다.
- 실패한 카드가 현재 보이지 않으면 검색 조건 초기화·목록 새로고침으로 확인하도록 안내한다. 새 카드에서도 같은 코드의 실패 상태를 유지한다.
- 기존 ReplayRequest의 연결 세대·요청 중복·시간 제한·소유자 수명 보호를 사용한다. 닫힌 창의 늦은 응답은 재생하지 않는다.
- 새로고침 응답으로 카드 교체 후에도 다운로드 결과는 기존 목록 복귀가 가능한 재생기로 연결한다. 로컬 보관·메모 저장 경로는 유지한다.
- Tab 순환에서 비활성 보기·새로고침 버튼을 건너뛰고 상태 변경 때 연결을 갱신한다. 초점 복원도 비활성 버튼을 피하며 Esc·방향키 스크롤을 유지한다.
- 독립적으로 카드를 생성하는 기존 호출은 기본 인자를 유지해 기존 보기 경로를 계속 사용한다. RPC 호출이나 서버 응답 형식은 변경하지 않는다.
- README를 갱신하고 이전 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 콜백 소유권·목록 교체·필터·실패 복구·키보드 이동을 소스로 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 실제 로드·표시·조작 검증은 외부 스크립트에 맡긴다.

- 다음 후보: 복구 비교에서 전적·업적의 구체적인 감소 안내, 도전 보관 전투 카드의 덱 구성 사전 표시, 온라인 전투 다운로드를 창을 닫지 않고 취소하는 조작.

## 2026-10-13 — 도전 보관 전투 재생 후 분석 카드 복귀

- 이번 주제: 도전 보관 전투를 재생한 뒤 완료된 점수 분석·스크롤·선택 카드 초점을 유지한 선택 창으로 돌아온다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일 해시와 HEAD·인덱스 루트 트리를 읽어 미커밋 변경 및 미완료 소스·문서가 없음을 확인했다.
- 최근 3회차와 아카이브의 다음 후보를 읽고 남아 있던 도전 보관 전투의 재생 후 복귀를 선택했다.
- 주제 선기록을 먼저 시도했으나 셸의 문자 인코딩 때문에 삽입이 누락되었다. 소스 검토 중 확인해 로그를 바로 보정했다.
- 확인한 문제: 보관 전투를 재생하고 나가면 전적 화면으로 돌아가 선택 창을 다시 열고 긴 전투의 점수 분석도 다시 해야 했다.
- 도전 보관 전투의 재생 → 나가기를 원래 날짜·버전의 보관 전투 선택 창으로 연결했다. 다른 전투를 바로 분석하거나 재생할 수 있다.
- 완료된 점수 분석 요약과 스크롤을 유지하고 재생한 파일의 재생 버튼으로 키보드 초점을 돌린다.

- 선택 창을 도전 기록으로 또는 Esc로 닫으면 원래 전투 개수 버튼으로 돌아온다. 날짜·버전·결과 조건과 페이지·스크롤은 기존 상태를 사용한다.
- 원래 버튼이 삭제·비활성화되면 전적 목록으로 초점을 돌린다. 재생했던 전투가 사라지면 선택 창 목록에 초점을 두고 이유를 안내한다.
- 복귀 때 로컬 파일을 다시 읽어 날짜·버전과 내용을 확인한다. 바뀌거나 삭제된 전투의 분석 요약은 폐기하고 개수를 안내한다.

- 분석 재사용 지문은 선택 창 조회에서만 계산한다. 전적 화면의 보관 전투 개수 조회에는 추가 계산을 하지 않는다.
