# 프로젝트 개선 기록

## 2026-10-14 — 전장 병력 현황과 생산 한도 안내

- 이번 주제: 양쪽 병력·소환수의 전장 현황과 공유 생산 한도를 표시하고, 한도에 도달하면 카드·클릭·단축키에 같은 사유를 안내한다.
- 시작 상태: Git 명령 없이 인덱스와 추적 파일의 원본/LF 해시를 비교하고 느슨한 객체·팩 객체의 HEAD 트리도 대조했다. 미커밋 변경·충돌·미추적 소스·문서가 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 주제·다음 후보를 읽었다. 실제 전투에서 드러나지 않던 병력 현황·생산 한도를 선택하고 소스 수정 전에 이번 주제를 먼저 기록했다.
- 확인한 문제: 모델은 양쪽 병력·소환수 합계 256명에서 생산을 거절하지만 카드는 자원·생산 대기만 확인했다. 한도에 도달하면 활성 카드를 눌러도 생산되지 않았고 원인도 표시되지 않았다.
- 양쪽 기지 패널의 기존 제목 옆에 살아 있는 병력 수를 표시했다. 소환수가 있으면 전체 병력 중 소환수 수를 함께 표시해 전력 규모를 바로 확인할 수 있다.
- 각 진영의 툴팁에 병력 종류별 생존 수와 소환 병력을 표시했다. 관전의 툴팁은 블루·레드 기준을 사용하며 내 진영이 오른쪽 서버 진영이어도 실제 진영에 맞춰 집계한다.
- 전장 아래에 양쪽 병력·소환수의 합계와 공유 한도를 표시했다. 한도 도달 시 생산 한도를 강조하고, 툴팁에 구조물의 별도 한도와 생산 재개 조건을 안내한다.
- 생존 병력 수는 체력이 남은 병력만 집계한다. 생산 한도 판정은 모델과 동일하게 배열 전체 크기를 사용해 사망 후 정리 대기 중인 병력도 포함한다.
- 정리 대기 중인 병력이 있으면 전체 한도 툴팁에 그 수를 별도로 안내한다. 구조물·포탑·발전기는 병력 수에 포함하지 않는다.
- 한도에 도달한 생산 카드에는 전장 한도 N/N을 표시하고 비활성화한다. 한도 미만의 새 상태를 받으면 기존 자원·생산 대기에 맞춰 자동으로 다시 활성화한다.
- 병력 카드 툴팁에 해당 종류의 생존 수와 전장 전체 수를 추가했다. 네크로맨서는 살아 있는 아군 해골 수와 소환수도 한도에 포함된다는 안내를 함께 표시한다.
- 한도 사유를 자원 예상 대기보다 우선해 기다리기만 하면 구매할 수 있다는 오해를 줄였다. 일시정지·관전·연결 복구·상태 수신·전투 종료의 기존 우선순위는 유지한다.
- 생산 콜백과 단축키도 같은 전장 한도를 확인한다. 온라인에서는 한도가 찬 상태의 불필요한 생산 요청을 보내지 않으며, 단축키에는 짧은 제한 안내를 표시한다.
- 구조물 설치 확인 중에는 생산 제한 메시지로 서버 확인 안내를 덮어쓰지 않는다. 병력 한도는 구조물 선택·설치를 잠그지 않는다.
- 오프라인 생산 성공 직후 현재 모델의 스냅샷으로 자원·병력·모든 구매 카드를 즉시 갱신한다. 다음 프레임까지 이전 자원과 병력 수가 남지 않으며 기존 구매 간격·리플레이 기록 순서를 유지한다.
- 입장·연결 복구·복구 대기 중에는 병력 수를 —로 표시한다. 새 화면에는 이전 진영 라벨 참조를 남기지 않고 최신 상태 수신 후 실제 현황으로 복원한다.
- 기존 기지 패널·생산 카드·전장 크기를 유지하고 전체 병력 안내는 설치 상태 메시지 위에 배치했다. 문구·툴팁·색상이 바뀔 때만 해당 속성을 갱신한다.
- 전투 스탯의 전투 규칙에 검색 가능한 병력 한도 설명을 추가하고 README를 갱신했다. 가장 오래된 1회차를 아카이브로 옮겨 최근 3회차만 남겼다.
- 소스로 생산·소환·사망 정리·진영 집계·입력·화면 해제·정지·재접속 경로와 변경 내용을 검토했다. 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 실제 로드·배치·한도 도달/해제·입력 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·스냅샷·세이브·서버 파일 형식과 전투 규칙·밸런스·버전 번호·release.json·CHANGELOG·PatchNotes를 유지했다. Git 명령은 실행하지 않았다.
- 다음 후보: 도전 보관 전투 선택 창의 개별 검색 조건 해제, 스탯 창의 분류별 읽던 위치 복원, 병력 종류별 생존 수를 터치로 확인하는 상세 안내.

## 2026-10-14 — 전투 자원 회복과 구매 예상 대기 안내

- 이번 주제: 전투 HUD에 자원 회복 속도·한도 도달 상태와 카드별 구매 예상 대기를 표시해 생산·건설 시점을 쉽게 판단한다.
- 시작 상태: Git 명령 없이 추적 파일의 원본/LF 해시와 인덱스를 비교하고, 느슨한 객체·팩 객체의 HEAD 트리도 인덱스와 대조했다. 미커밋 변경·충돌·미추적 소스·문서가 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 주제·다음 후보를 읽었다. 보관함·복구·스탯 탐색과 중복되지 않는 실제 전투의 구매 시점 안내를 선택하고 소스 수정 전에 주제를 먼저 기록했다.
- 확인한 불편: 구매 카드는 부족한 자원만 표시하고 회복 속도는 보이지 않아 생산·건설까지 얼마나 기다려야 하는지 계산해야 했다. 자원이 가득 차 회복이 멈춘 상태도 숫자만으로 판단해야 했다.
- 자원 패널 아래에 회복 +N/초를 표시했다. 툴팁에는 전투 시간 기준 회복량·살아 있는 아군 발전기 개수·보유 한도를 함께 안내한다.
- 오프라인은 현재 모델의 성장 반영 회복량·한도를 사용한다. 온라인은 기존 기본 수치와 받은 스냅샷을 사용하며 추가 서버 요청을 보내지 않는다.
- 기존 설치 개수 집계에서 체력이 남은 아군 발전기만 포함해 추가 수입을 계산한다. 적 발전기와 파괴 후 정리 대기 중인 발전기는 포함하지 않는다.
- 자원이 보유 한도에 도달하면 한도 도달·회복 멈춤을 강조하고 자원을 사용하면 회복이 이어진다고 안내한다. 무한 자원에서는 자동 보충 안내를 우선한다.
- 자원 부족 카드에 자원 약 N초를 표시한다. 툴팁에는 기존 부족한 자원 수와 구매 대기 예상, 추가 구매·발전기 파괴로 달라질 수 있다는 안내를 함께 둔다.
- 예상 시간은 올림한 부족 자원 수가 아닌 실제 소수 부족량을 회복 속도로 나눠 계산한다. 자원 대기와 생산 대기의 큰 값을 사용하고 0.1초 단위로 올려 0.0초 대기를 피한다.
- 연습 배속에서는 회복량과 모델 생산 대기를 실제 시간 기준으로 환산한다. 클라이언트의 중복 구매 방지 대기는 실제 시간 기준을 유지한다.
- 캠페인·일일/주간 도전·고스트·되감기 실험은 기존 고정 속도 경로를 따른다. 이전 연습의 배속 설정이 남아 있어도 예상치를 그 배속으로 바꾸지 않는다.
- 무한 자원에서 부족 상태가 잠시 남으면 자원 보충 중으로 표시한다. 비용이 보유 한도를 넘으면 자원 한도 초과로 안내하며 불가능한 회복 대기를 표시하지 않는다.
- 정지·재접속·관전·전투 종료·설치 확인·구조물 한도의 기존 카드 표시 우선순위를 유지한다. 정지·복구 중에는 구매 예상 시간을 추가하지 않는다.
- 자원 회복 안내도 일시정지·상태 수신·연결 복구·종료 상태를 반영한다. 첫 스냅샷 전에는 추정 회복량을 표시하지 않으며 재개·최신 상태 수신 후 기존 갱신 경로로 복원한다.
- 기존 자원 패널의 한 줄을 사용해 전장과 구매 카드 크기를 유지했다. 툴팁 입력을 허용하고 문구·색상이 바뀔 때만 해당 속성을 갱신한다.
- 예상치는 표시 전용이다. 자원·쿨다운·구매 가능 판정·클릭·단축키·설치 선택·전송·리플레이 기록·전투 밸런스를 바꾸지 않는다.
- README에 사용법을 추가하고 가장 오래된 1회차를 아카이브로 옮겨 최근 3회차만 남겼다. 소스로 자원 회복·발전기 생존·배속·정지/재개·재접속·종료와 기존 카드 판정 경로를 검토했다.
- 테스트는 추가·수정·실행하지 않았고 게임 실행·렌더링도 하지 않았다. 실제 로드·문구 배치·예상 대기·툴팁·배속·재접속 검증은 외부 스크립트에 맡긴다.

## 2026-10-14 — 리플레이 보관함의 개별 검색 조건 해제

- 이번 주제: 카드가 검색 결과에서 사라져도 상단에서 전체·블루·레드 검색어를 개별 해제하고 다른 조건과 탐색 위치를 유지한다.
- 시작 상태: Git 명령 없이 인덱스·추적 파일의 원본/LF 해시를 비교하고 팩 객체를 읽어 HEAD/인덱스도 대조했다. 미커밋 변경·충돌·미추적 소스·문서가 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 주제·다음 후보를 읽고 아직 남아 있던 보관함의 개별 조건 해제를 선택했다. 소스 수정 전에 이번 주제를 한 줄 먼저 기록했다.
- 확인한 불편: 카드의 구성 버튼으로 조건을 추가하면 카드가 결과에서 사라질 수 있어 같은 버튼으로 해제하기 어려웠다. 결과가 없으면 검색칸을 직접 편집하거나 모든 조건을 초기화해야 했다.
- 검색 결과 밖에 전체·블루·레드 검색어별 해제 버튼을 추가했다. 결과 0개와 읽기 실패 파일만 있는 상태에서도 덱 조건을 단계적으로 풀 수 있다.
- 카드에서 고른 영문 ID뿐 아니라 직접 입력한 한글·영문·부분 검색어도 버튼으로 표시한다. 전체 검색의 날짜·메모·구간 검색어도 같은 방법으로 해제한다.
- 버튼에는 검색칸의 전체·블루·레드 구분과 진영 색상을 표시한다. 온라인의 진영을 추정하지 않고 기존 저장된 블루·레드 기준을 유지한다.
- 덱의 알려진 영문 ID는 병력·구조물 이름으로 표시한다. 긴 이름은 줄여 표시하고 툴팁에 실제 단어와 해제 범위를 안내한다.
- 한 버튼은 해당 칸의 정확한 단어와 그 대소문자 변형·중복만 해제한다. 다른 부분 검색어·반대 진영·전체 검색·필터·정렬은 유지한다.
- 검색 판정과 버튼 생성에 같은 공백 분리 함수를 사용한다. 탭·줄바꿈도 기존 검색 규칙대로 처리하며 남은 조건의 의미를 바꾸지 않는다.
- 조건 버튼은 한 줄의 가로 스크롤 안에 둔다. 긴 검색어와 많은 조건이 결과 목록의 높이를 계속 줄이지 않으며 조건이 없으면 줄 전체를 숨긴다.
- 버튼에 터치 높이·놓을 때 실행·스크롤 입력 전달을 적용한다. Tab으로 이동하면 가로 스크롤이 초점을 따라간다.
- 조건을 해제하면 기존 페이지·카드 기준 위치를 복원한다. 검색 범위가 넓어져 카드의 페이지가 달라져도 기존 파일 기준 탐색 경로를 재사용한다.
- 해제한 버튼의 초점은 가까운 남은 조건으로 옮긴다. 마지막 조건이면 목록으로 옮겨 터치 키보드를 자동으로 열지 않는다.
