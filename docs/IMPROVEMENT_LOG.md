# 프로젝트 개선 기록

## 2026-10-14 — 전투 요약의 읽던 위치 복원과 모달 조작

- 이번 주제: 전투 결과 요약의 스크롤·기여도 선택·초점을 복원하고 키보드 조작을 모달 안에 한정하며 확정된 전세 기록의 반복 깊은 복사를 제거한다.
- 시작 상태: Git 명령 없이 인덱스와 작업 파일의 원본/LF 해시를 대조하고, loose·pack 객체에서 HEAD 트리를 읽어 인덱스와 비교했다. 미커밋·스테이징 변경·충돌·미추적 소스가 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 주제·다음 후보를 읽었다. 소스 수정 전에 이번 주제를 로그에 먼저 기록했다.
- 확인한 불편: 결과 요약을 다시 열면 스크롤·피해/처치 선택이 초기화되고, Esc·페이지 이동 및 창 내부 초점 순환이 없어 긴 집계를 다시 찾아야 했다.
- Main에 같은 전투의 요약 탐색 상태를 보관한다. 새 전투의 결과 초기화 때 새 딕셔너리로 교체하며 세이브에는 쓰지 않는다.
- 공통 기여도 UI에 populate_with_state를 추가해 선택한 피해/처치를 복원한다. 기존 populate 호출은 독립 상태로 동작해 리플레이의 기존 호출 방식을 유지한다.
- 화면 내용과 본문에 고정 노드 이름을 부여해 재생성 후에도 스크롤·비교 버튼의 초점 경로를 다시 찾는다.
- BattleReportBrowser가 스크롤과 본문 초점을 기록한다. 닫기 버튼으로 옮긴 초점은 기존 읽기 위치를 덮어쓰지 않는다.
- 창을 열면 목록에 즉시 초점을 주고, 레이아웃과 초점 따라 스크롤이 끝난 뒤 저장 위치를 복원한다. 사라진 초점 경로는 목록으로 대체한다.
- 사용자의 키·클릭·휠·터치·드래그는 대기 중인 복원을 취소한다. 창 숨김·삭제 대기·조상 삭제·화면 이탈 후에는 지연 복원을 적용하지 않는다.
- Tab·Shift+Tab은 목록·실제 피해·처치·닫기를 창 안에서 순환한다. 외부의 재도전·단계 이동 버튼으로 키보드 초점이 넘어가지 않는다.
- 목록 초점의 위/아래 방향키와 창 안의 Page Up/Down·Home/End로 긴 집계를 탐색한다. 터치·휠·기존 비교 버튼 조작도 유지한다.
- Esc와 닫기는 읽던 위치를 보관하고 요약 진입 초점으로 돌아간다. 기존 초점이 없어졌다면 결과 화면의 전투 요약 버튼을 사용한다.
- Main의 요약 키 처리를 전투 단축키보다 먼저 배치한다. 창 조작과 전장 조작이 겹치지 않으며 전역 F11 처리는 유지한다.
- 닫을 때 삭제 대기 전에 창을 숨겨 남은 포인터 입력과 곡선 준비를 중단한다. 이미 닫힌 창의 예약 복원도 무효화한다.
- 결과 확정 후 전세 샘플링은 멈추고 새 경기에서는 배열을 교체하는 경로를 확인했다. 확정된 전세 기록은 읽기 전용 그래프에 참조로 전달해 매번 모든 관측점을 깊게 복사하지 않는다.
- 결과 확정 전 호출에는 기존 깊은 복사 격리를 유지한다. 그래프의 극값·공백·좌표와 프레임별 곡선 준비, 작은 전투 집계의 스냅샷 복사는 유지한다.
- README에 복원·단축키·초점 복귀를 반영했다. 소스로 결과 확정·경기 초기화·모달 입력·노드 경로·지연 복원 수명을 검토했으며 성능 수치는 측정하지 않았다.
- 테스트 추가·수정·실행 및 게임 실행·렌더링은 하지 않았다. 실제 로드·재진입·메트릭 전환·키보드/터치·연속 닫기·새 경기·재접속·긴 기록 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식과 버전 번호·release.json·CHANGELOG·PatchNotes를 유지했다. Git 명령은 실행하지 않았다. 가장 오래된 회차를 아카이브로 옮겨 최근 3회차만 남겼다.
- 다음 후보: 복구 비교에서 특정 감소 경고의 상세로 바로 이동하는 흐름, 도전 보관 전투 검색 결과에서 특정 페이지 번호로 직접 이동하는 흐름, 같은 결과 요약을 다시 열 때 완성된 전세 곡선 형상을 재사용하는 흐름.

## 2026-10-14 — 전세 곡선 최초 준비의 프레임 분산과 화면 이탈 중단

- 이번 주제: 전세 그래프의 원본 순회와 채움 형상 준비를 프레임별로 나누고 크기·데이터 교체와 화면 이탈 시 이전 작업을 중단한다.
- 시작 상태: Git 명령 없이 인덱스·작업 파일의 원본/LF 해시와 인덱스에서 재구성한 트리·HEAD 트리를 대조했다. 미커밋·스테이징 변경·충돌·미추적 소스가 없었으며 무시 대상 Python 캐시만 있어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 주제·다음 후보를 읽고 남아 있던 최초 곡선 준비의 프레임 분산을 선택했다. 소스 수정 전에 이번 주제를 UTF-8 패치로 먼저 기록했다.
- 확인한 문제: 표시 열 제한과 정적 캐시는 이미 있었지만 최초 표시·분석 결과 교체·크기 변경 때 모든 원본 순회와 채움 삼각형 준비를 _draw에서 한 번에 실행했다.
- MomentumCurve의 준비를 관측점 선택·채움 삼각형·완성 결과 반영으로 나누고, 화면의 _process에서만 진행한다. 그리기는 원본 순회나 형상 생성을 실행하지 않는다.
- 원본 선택과 삼각형 준비는 각각 프레임당 최대 512개 작업 또는 약 4ms 예산으로 나눈다. 단계가 끝나도 다음 단계는 별도 프레임에 시작한다.
- 엔진의 메시 업로드는 CPU 준비 이후 별도 프레임에 한 번 실행한다. 단일 작업·업로드·완성 곡선 그리기는 예산을 넘을 수 있어 4ms를 보장 시간으로 취급하지 않는다.
- 그래프 내부에 전세 곡선 준비 중 진행률을 표시한다. 관측점 단계는 0~89%, 채움 단계는 90~99%이며 완성 후 문구를 없애고 곡선을 한 번에 표시한다.
- 부분적으로 준비된 곡선·채움은 공개하지 않는다. 준비 중에도 배경·기준선·재생 위치·주요 순간·메모·선택 구간 표시는 기존 부모에서 계속 그린다.
- 첫 값·최저값·최고값·마지막 값과 최대 2,048 표시 열 규칙을 유지한다. 배치를 나누어도 같은 열의 후보와 원본 순서를 이어 받아 짧은 역전을 보존한다.
- break_before 경계는 배치 경계·같은 표시 열에서도 유지한다. 단일 관측점 구간의 다음 구간 이동도 작업 개수에 포함해 공백이 많아도 한 번에 순회하지 않는다.
- 양쪽 전세가 바뀌는 선분의 기준선 교차와 진영별 채움 색상·윤곽선·한 관측점 표시를 유지한다. 빈 기록은 배경·기준선만 표시한다.
- 크기 변경·setup의 데이터 교체는 기존 준비와 캐시를 즉시 버리고 최신 조건만 준비한다. 0 크기에서는 계산을 멈추고 이후 크기 변경으로 재개한다.
- 숨김·트리 이탈·삭제 대기인 조상 노드를 확인해 남은 준비를 버린다. 다시 표시하면 필요한 준비를 새로 시작하며 완료된 같은 크기 캐시는 재사용한다.
- 완료 후 _process를 끈다. 재생 위치·메모·반복 구간만 바뀔 때 곡선 준비를 다시 시작하거나 빈 프레임 작업을 남기지 않는다.
- ReplayViewer의 시점 탐색 시작은 곡선 준비만 일시 중지한다. 탐색 완료·취소 후 이어 준비하며 기존 전세 분석의 탐색 우선순위와 함께 장면 이동을 우선한다.
- 원본 분석·주요 순간 판정·클릭/드래그 좌표·전투 규칙·메모·클립·재생 상태는 변경하지 않는다. 공통 그래프를 사용하는 전투 결과·실시간 요약에도 준비 분산이 적용된다.
- README 사용법을 갱신했다. 소스로 배치 경계·공백·극값·결과 반영·탐색·화면 수명을 검토하고 [Godot Node 처리 순서](https://docs.godotengine.org/en/stable/classes/class_node.html)와 [CanvasItem 표시 수명](https://docs.godotengine.org/en/stable/classes/class_canvasitem.html)을 확인했다.
- 테스트 추가·수정·실행과 게임 실행·렌더링은 하지 않았다. 실제 로드·긴 기록·동일 열의 극값·공백·창 크기 변경·준비 중 탐색·화면 이탈 검증은 외부 스크립트에 맡긴다. 성능 수치는 측정하지 않았다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식과 버전 번호·release.json·CHANGELOG·PatchNotes를 유지했다. Git 명령은 실행하지 않았다. 가장 오래된 회차를 아카이브로 옮겨 최근 3회차만 남겼다.
- 다음 후보: 복구 비교에서 특정 감소 경고의 상세로 바로 이동하는 흐름, 도전 보관 전투 검색 결과에서 특정 페이지 번호로 직접 이동하는 흐름, 긴 전투 요약을 열 때 확정된 전세 기록의 깊은 복사 비용 제한.

## 2026-10-14 — 도전 보관 전투의 페이지 탐색과 카드 생성 제한

- 이번 주제: 도전 보관 전투를 전체 검색 후 페이지로 나누고 현재 페이지의 카드만 생성하여 대량 보관에서도 탐색·분석·재생 복귀를 유지한다.
- 시작 상태: Git 명령 없이 인덱스·작업 파일의 원본/LF 해시와 재구성한 인덱스 트리·HEAD 트리를 대조했다. 미커밋·스테이징 변경·충돌·미추적 소스가 없어 중단 작업은 없었다.
- 최근 3회차와 아카이브의 주제·다음 후보를 읽고 남아 있던 도전 보관 전투의 페이지별 카드 제한을 선택했다. 소스 수정 전에 이번 주제를 먼저 기록했다.
- 확인한 불편: 읽기와 카드 생성은 이미 분산했지만 보관된 모든 전투의 카드를 끝까지 만들어야 검색을 사용할 수 있었고, 화면에 없는 카드도 계속 유지했다.
- 전체 검색용 메타데이터와 현재 페이지의 카드를 분리했다. 카드 생성·유지는 한 쪽 최대 8개로 제한하며 보관 파일이나 전투 내용은 변경하지 않는다.
- 처음·이전·다음·마지막 버튼과 현재 쪽·전체 쪽·표시 범위를 추가했다. 검색 결과가 한 쪽 이하면 페이지 조작을 숨긴다.
- 전체 검색·내 덱·상대 덱·결과·클립 조건은 보관 전투 전체에 적용한다. 검색 개수와 버전별 그룹 개수는 현재 페이지의 카드 수와 구분한다.
- 확인된 버전을 먼저, 미상 버전을 뒤에 배치하고 각 그룹의 최신 보관순을 유지한다. 두 그룹이 같은 페이지에 있으면 각각의 제목과 이 쪽 개수를 표시한다.
- 검색 문자열은 파일 읽기의 작은 배치에서 준비한다. 카드와 무관하게 메타데이터를 검색하며 페이지 이동·검색으로 파일을 다시 읽거나 전투를 재현하지 않는다.
- 현재 페이지의 새 카드는 프레임당 최대 두 개 또는 약 4ms 예산으로 준비한다. 단일 카드 비용은 예산을 넘을 수 있으며 준비 중 검색·페이지 이동·새로고침·닫기를 계속 사용할 수 있다.
- 연속 검색·페이지 이동은 남은 카드 준비를 최신 페이지로 교체한다. 화면 이탈·조상 노드의 삭제 대기를 검사해 이전 창의 준비를 중단한다.
- 페이지에 남은 카드는 재사용한다. 벗어난 카드는 분리·삭제하고 해당 진행 중인 분석만 중단하며, 분석의 대기 후 카드·상세 문구 수명을 함께 검사한다.
- 완료된 점수 분석은 작은 요약으로 유지해 페이지 왕복 시 재사용한다. 새로고침의 변경·삭제된 전투 분석 해제와 재생·분석 직전 지문 검사를 유지한다.
- 검색칸 직접 수정·결과·클립 조건 변경·초기화는 첫 페이지로 이동한다. 카드의 덱 조건 선택은 선택한 전투가 있는 페이지를 찾아 초점과 보이는 위치를 유지한다.
- 개별 검색어 해제는 현재 페이지·읽던 위치·가까운 남은 검색어 초점을 유지하고, 결과가 줄면 마지막 유효 페이지로 제한한다. 터치 키보드를 자동으로 열지 않는다.
- 재생 후 복귀·새로고침은 읽던 전투의 파일 경로로 페이지를 다시 찾는다. 파일이 사라지면 유효 페이지로 제한하고, 사라진 카드의 초점은 목록으로 돌린다.
- 페이지 경계의 비활성 버튼은 사용 가능한 이전·다음 버튼으로 초점을 넘긴다. Tab·방향키는 현재 카드와 사용 가능한 조작만 순환하며 Esc·목록 스크롤 조작을 유지한다.
- 사용자의 키·클릭·터치·스크롤은 지연 복원을 취소한다. 카드 준비가 끝날 때 기존 오류·조건 변경 안내를 함께 유지하고 README 사용법을 갱신했다.
- 모든 파일 읽기·지문 준비와 전체 메타데이터 검색 비용은 남는다. 소스로 생성 제한·그룹·수명·분석·필터·복귀 경로를 검토했으며 성능 수치는 측정하지 않았다. 테스트 추가·수정·실행 및 게임 실행·렌더링은 하지 않았고 실제 로드·대량 보관·입력 검증은 외부 스크립트에 맡긴다.
- 호환성 변경: 없음. RPC 시그니처·세이브·서버 파일 형식과 버전 번호·release.json·CHANGELOG·PatchNotes를 유지했다. Git 명령은 실행하지 않았다. 가장 오래된 회차를 아카이브로 옮겨 최근 3회차만 남겼다.
